<objective>
Ship `EdenStatusPalette` — a `ThemeExtension<EdenStatusPalette>` carrying per-profile semantic status colors (success / warning / danger / info / neutral), with profile-aware defaults that ATTACH automatically to `ThemeData.extensions` when consumers opt-in via the extended `EdenTheme.light/dark` signature.

Per `VERTICAL_UX_RESEARCH_2026-05-16.md` §2.4.4:

> Today's status colors (`EdenColors.success/warning/error/info`) are global constants. Per-vertical, status semantics can shift: medical urgency uses full red/amber/green ramp, gov classification uses purple/red/orange, retail stock uses pulsing red for OOS. Solution: `ThemeExtension` per semantic group. Backwards-compatible: today's widgets read static `EdenColors.success`; the new ThemeExtension supplies defaults that match today's values when no profile is active.

**Public API surface:**

```dart
@immutable
class EdenStatusPalette extends ThemeExtension<EdenStatusPalette> {
  const EdenStatusPalette({
    required this.successBg, required this.successFg, required this.successBorder,
    required this.warningBg, required this.warningFg, required this.warningBorder,
    required this.dangerBg,  required this.dangerFg,  required this.dangerBorder,
    required this.infoBg,    required this.infoFg,    required this.infoBorder,
    required this.neutralBg, required this.neutralFg, required this.neutralBorder,
  });

  final Color successBg, successFg, successBorder;
  final Color warningBg, warningFg, warningBorder;
  final Color dangerBg,  dangerFg,  dangerBorder;
  final Color infoBg,    infoFg,    infoBorder;
  final Color neutralBg, neutralFg, neutralBorder;

  /// Default commercial palette (today's EdenColors.{success,warning,error,info}).
  /// Used as the fallback when no profile is attached. Back-compat anchor.
  factory EdenStatusPalette.commercial() => const EdenStatusPalette(
    successBg: Color(0x1A10B981), // matches EdenColors.successBg
    successFg: Color(0xFF10B981), // matches EdenColors.success
    successBorder: Color(0x4D10B981), // 30% alpha
    warningBg: Color(0x1AF59E0B),
    warningFg: Color(0xFFF59E0B),
    warningBorder: Color(0x4DF59E0B),
    dangerBg: Color(0x1AEF4444),
    dangerFg: Color(0xFFEF4444),
    dangerBorder: Color(0x4DEF4444),
    infoBg: Color(0x1A3B82F6),
    infoFg: Color(0xFF3B82F6),
    infoBorder: Color(0x4D3B82F6),
    neutralBg: Color(0xFFF4F4F5), // neutral[100]
    neutralFg: Color(0xFF52525B), // neutral[600]
    neutralBorder: Color(0xFFE4E4E7), // neutral[200]
  );

  /// Factory: per-profile palette. commercialWarm reproduces today.
  factory EdenStatusPalette.forProfile(EdenThemeProfile profile) {
    switch (profile) {
      case EdenThemeProfile.commercialWarm:
      case EdenThemeProfile.retailVibrant:
      case EdenThemeProfile.legalProfessional:
        return EdenStatusPalette.commercial();
      case EdenThemeProfile.medicalInstitutional:
        return _medicalInstitutional;
      case EdenThemeProfile.govFederal:
        return _govFederal;
    }
  }

  @override
  EdenStatusPalette copyWith({ /* 15 nullable color params */ }) { ... }

  @override
  EdenStatusPalette lerp(ThemeExtension<EdenStatusPalette>? other, double t) {
    if (other is! EdenStatusPalette) return this;
    return EdenStatusPalette(
      successBg: Color.lerp(successBg, other.successBg, t)!,
      // ... 14 more Color.lerp calls
    );
  }
}
```

<context>
**Why a `ThemeExtension` instead of just exposing more `EdenColors` constants:** profile-aware theming requires a way to vary status colors PER-`ThemeData`-instance without mutable global state. ThemeData.extensions is Flutter's official escape hatch — `Theme.of(context).extension<EdenStatusPalette>()` resolves at the build-time scope of the nearest Theme widget, supporting nested themes for future use cases (e.g., embedded preview-with-different-profile demos in the catalog itself).

**Why 5 semantic groups × 3 facets = 15 fields, not a Map:** explicit fields are greppable (you can search for `successFg` across the codebase) and IDE-autocompletable. Maps lose this. ThemeExtension lerp also requires field-by-field interpolation; a map would force null checks everywhere.

**Why `EdenStatusPalette.commercial()` is a `factory` not a `static const`:** factory pattern preserves test substitutability and matches Flutter's ThemeExtension conventions. Note: it returns a const-shaped instance (all defaults are `Color(0xFFXXX)` const literals), so allocation is cheap.

**Why the 15 Color literals are duplicated between `commercial()` and the EdenColors constants:** because we cannot use `EdenColors.success` etc. in a const constructor body if `EdenColors.success` is not itself a const Color expression. Inspect: `lib/src/tokens/colors.dart` line 121 — `static const Color success = Color(0xFF10B981);` — IS const. So we COULD use `EdenColors.success` in const contexts. **However**, for `successBorder` (30% alpha) and `neutralBg/neutralFg/neutralBorder` (which derive from neutral[100]/[600]/[200] — NOT const expressions because `[X]` is a method call), we need hex literals. For consistency, hex literals are used throughout. Drift is caught by a back-compat test that asserts `commercial().successFg == EdenColors.success` etc.

**ThemeExtension contract (Flutter SDK):** `copyWith` + `lerp` are required. `lerp` is invoked during theme transitions (e.g., light↔dark animations); for status colors, `Color.lerp` per-field is correct. Edge: if `other` is null OR not an `EdenStatusPalette`, lerp returns `this` (no-op). This is the standard Flutter pattern — verify by reading the ThemeExtension API docs OR existing extension implementations in the Flutter SDK source.

**Wiring into `EdenTheme.light/dark`:** the existing method copies a built `ThemeData` and adds an extension. This is the LEAST INVASIVE change — does NOT refactor the existing `_buildTheme` helper. The base theme (built from existing ColorScheme + textTheme + ... logic) is preserved bit-for-bit. Only the `extensions` field is augmented.

**No `flex_color_scheme` or other theme-management packages.** Constraint 2.
</context>

- **`ThemeExtension` requires you to override `Object get type` IMPLICITLY via the `extension<T>` lookup mechanism — no manual override needed.** Verified: Flutter SDK's `ThemeExtension<T>` exposes type via the generic. `lerp` and `copyWith` are the only methods we must override.
- **`copyWith` with 15 nullable params is tedious but unavoidable.** Use the standard pattern: each param is `Color?`, body uses `?? this.fieldName`. Do NOT shortcut with a builder pattern or codegen.
- **`EdenTheme.light/dark` signature change MUST keep existing call sites working.** `EdenTheme.light()` (no args) → today's behavior. `EdenTheme.light(brand: EdenColors.blue)` (positional named today) → continues to work because `brand` is still a named param with default null.
