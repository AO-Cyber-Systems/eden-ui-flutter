<objective>
Ship `EdenAdaptiveTheme` — the top-level integration point that composes TRDs 009-01..009-04 into a single consumer-facing API + the visual catalog screen demonstrating all 5 profiles.

This is the FINAL piece of objective 009. After this TRD lands, downstream Eden Flutter apps consume the entire vertical-theme system via one of two patterns:

**Pattern A — Static factory for MaterialApp.theme (recommended for app-wide theming):**

```dart
MaterialApp(
  theme: EdenAdaptiveTheme.light(
    EdenThemeProfile.medicalInstitutional,
    brand: EdenBrandPresetRegistry.byId('medical-teal'),
  ),
  darkTheme: EdenAdaptiveTheme.dark(
    EdenThemeProfile.medicalInstitutional,
    brand: EdenBrandPresetRegistry.byId('medical-teal'),
  ),
  home: HomePage(),
);
```

This pattern returns `ThemeData` (NOT a widget). It composes `EdenTheme.light(profile: ..., brand: ...)` from TRD 009-02 (already attaches `EdenStatusPalette`) and OVERLAYS a profile-aware `TextTheme` using `EdenProfileFonts` from TRD 009-04.

**Pattern B — Widget wrapper for in-tree embedding (used by the catalog screen + downstream preview surfaces):**

```dart
EdenAdaptiveTheme(
  profile: EdenThemeProfile.govFederal,
  brand: EdenBrandPresetRegistry.byId('gov-federal-navy'),
  child: PreviewArea(),
)
```

This pattern is a `StatelessWidget` that wraps `child` in `EdenThemeProfileScope` + `Theme(data: EdenAdaptiveTheme.light(profile, brand: brand))`. Used inside the catalog screen to render multiple profiles SIMULTANEOUSLY on one page (e.g., for side-by-side comparison) — each profile card uses the widget pattern to scope its own Theme.

**Catalog screen — `lib/dev_app/screens/theme_profiles_screen.dart`:**

The screen renders a Wrap of 5 profile cards. Each card contains:
1. **Header** — profile display name + 1-line description (e.g., "Federal navy + USWDS conformance").
2. **Sample triptych** — three components rendered inside the wrapped profile theme:
   - `EdenButton.primary(label: 'Submit')` — shows the profile's primary color.
   - `EdenCard(child: Text('Sample body text'))` — shows surface tint + body font.
   - `EdenBadge.success(label: 'Active')` — shows the status palette successFg/successBg.
3. **Brand-preset chips row** — 3-4 `EdenChip` instances showing brand presets recommended for that profile (via `EdenBrandPresetRegistry.forVertical('<profile-vertical>')`). Tapping a chip rebuilds the card with that brand applied — local state per card.

Layout: `Wrap(spacing: 16, runSpacing: 16, children: [...])`. Each card width = 320pt. At 390pt logical width (iPhone-narrow), the Wrap flows to single column. At ≥760pt, two columns. At ≥1140pt, three columns.

<context>
**Why both a static factory AND a widget exist:** they serve different scopes.
- The static factory `EdenAdaptiveTheme.light(...)` returns a `ThemeData` — the EXTERNAL surface for `MaterialApp.theme` where the WHOLE app gets themed. This is Pattern A.
- The widget `EdenAdaptiveTheme(profile: ..., child: ...)` wraps a SUBTREE in a different theme — Pattern B, used inside the catalog screen to render multiple profiles on one page. Without the widget, the catalog screen would have to instantiate 5 separate MaterialApps which is gnarly.

**Why `EdenAdaptiveTheme.light` composes `EdenTheme.light` instead of replacing it:** the existing `EdenTheme.light(profile: ..., brand: ...)` already attaches the `EdenStatusPalette` extension (TRD 009-02). It's the canonical "build a ThemeData" entry point. `EdenAdaptiveTheme.light` is a CONVENIENCE wrapper that:
1. Resolves an optional `EdenBrandPreset` to its `MaterialColor` and passes through.
2. ADDITIONALLY constructs a profile-aware `TextTheme` overlay using `EdenProfileFonts` and re-attaches it to the ThemeData.

Step 2 is the value-add: today's `EdenTheme.light` builds a hardcoded TextTheme with `GoogleFonts.outfit` + `GoogleFonts.plusJakartaSans` calls. To respect a profile's `bodyFontFamily / displayFontFamily`, we rebuild the TextTheme with the profile-aware family. We do NOT modify the existing TextTheme construction in `EdenTheme._buildTheme` — Constraint 1 (back-compat). Instead, we OVERLAY via `ThemeData.copyWith(textTheme: ...)`.

**Why we don't move the TextTheme construction into `EdenTheme.light` itself:** it would require profile-awareness inside `_buildTheme`, which today returns a ThemeData with hardcoded fonts. Moving it changes the back-compat anchor (Constraint 1 — `EdenTheme.light()` no-args MUST return today's output). Instead, the overlay approach keeps `EdenTheme.light` unchanged for the default profile (when bodyFontFamily/displayFontFamily are null, the overlay is a no-op — we return the same TextTheme), and only differs for the 2 profiles that opt-in to fonts.

**TextTheme overlay logic:**

```dart
ThemeData _withProfileTextTheme(ThemeData base, EdenThemeProfile profile) {
  // If profile uses defaults for both body + display, no overlay needed.
  if (profile.data.bodyFontFamily == null && profile.data.displayFontFamily == null) {
    return base; // back-compat — no allocation, no theme rebuild
  }

  // Rebuild specific TextStyle entries with profile-aware fonts.
  final body = base.textTheme;
  final overridden = body.copyWith(
    // Display roles use the display font.
    displayLarge: body.displayLarge?.merge(EdenProfileFonts.displayTextStyle(profile)),
    displayMedium: body.displayMedium?.merge(EdenProfileFonts.displayTextStyle(profile)),
    displaySmall: body.displaySmall?.merge(EdenProfileFonts.displayTextStyle(profile)),
    headlineLarge: body.headlineLarge?.merge(EdenProfileFonts.displayTextStyle(profile)),
    headlineMedium: body.headlineMedium?.merge(EdenProfileFonts.displayTextStyle(profile)),
    headlineSmall: body.headlineSmall?.merge(EdenProfileFonts.displayTextStyle(profile)),
    // Body roles use the body font.
    titleLarge: body.titleLarge?.merge(EdenProfileFonts.bodyTextStyle(profile)),
    titleMedium: body.titleMedium?.merge(EdenProfileFonts.bodyTextStyle(profile)),
    titleSmall: body.titleSmall?.merge(EdenProfileFonts.bodyTextStyle(profile)),
    bodyLarge: body.bodyLarge?.merge(EdenProfileFonts.bodyTextStyle(profile)),
    bodyMedium: body.bodyMedium?.merge(EdenProfileFonts.bodyTextStyle(profile)),
    bodySmall: body.bodySmall?.merge(EdenProfileFonts.bodyTextStyle(profile)),
    labelLarge: body.labelLarge?.merge(EdenProfileFonts.bodyTextStyle(profile)),
    labelMedium: body.labelMedium?.merge(EdenProfileFonts.bodyTextStyle(profile)),
    labelSmall: body.labelSmall?.merge(EdenProfileFonts.bodyTextStyle(profile)),
  );
  return base.copyWith(textTheme: overridden);
}
```

The `.merge` pattern preserves existing fontSize/fontWeight/height from the base TextTheme while overriding the fontFamily. Critical — we don't want to lose the size/weight/height tuning.

/// Top-level integration of the vertical theme system (objective 009).
///
/// Two consumption patterns:
///
/// **Pattern A — Static factory for MaterialApp.theme** (app-wide theming):
/// ```dart
/// MaterialApp(
///   theme: EdenAdaptiveTheme.light(
///     EdenThemeProfile.medicalInstitutional,
///     brand: EdenBrandPresetRegistry.byId('medical-teal'),
///   ),
///   darkTheme: EdenAdaptiveTheme.dark(EdenThemeProfile.medicalInstitutional),
/// );
/// ```
///
/// **Pattern B — Widget wrapper** (in-tree subtree override; catalog
/// screens, embedded preview surfaces):
/// ```dart
/// EdenAdaptiveTheme(
///   profile: EdenThemeProfile.govFederal,
///   brand: EdenBrandPresetRegistry.byId('gov-federal-navy'),
///   child: PreviewArea(),
/// )
/// ```
///
/// Both patterns compose:
///   - [EdenTheme.light]/[EdenTheme.dark] from TRD 009-02 (attaches
///     [EdenStatusPalette] per profile)
///   - [EdenProfileFonts] from TRD 009-04 (profile-aware TextTheme overlay)
///   - [EdenBrandPreset.color] override for [ColorScheme.primary]
class EdenAdaptiveTheme extends StatelessWidget {
  const EdenAdaptiveTheme({
    super.key,
    required this.profile,
    this.brand,
    required this.child,
  });

  final EdenThemeProfile profile;
  final EdenBrandPreset? brand;
  final Widget child;

  /// Static factory returning a [ThemeData] for [MaterialApp.theme].
  ///
  /// Composes [EdenTheme.light] (which attaches [EdenStatusPalette]) and
  /// overlays a profile-aware [TextTheme] using [EdenProfileFonts].
  ///
  /// **Back-compat anchor** (OBJECTIVE.md Constraint 1): for
  /// [EdenThemeProfile.commercialWarm] with no brand override, returns
  /// a [ThemeData] equivalent to today's `EdenTheme.light()` output.
  static ThemeData light(
    EdenThemeProfile profile, {
    EdenBrandPreset? brand,
  }) {
    final base = EdenTheme.light(profile: profile, brand: brand?.color);
    return _withProfileTextTheme(base, profile);
  }

  /// Static factory for dark mode. Analogous to [light].
  /// v1 reuses the same per-profile palette in dark mode (no per-profile
  /// dark-mode aesthetic tuning — Out-of-Scope per OBJECTIVE.md).
  static ThemeData dark(
    EdenThemeProfile profile, {
    EdenBrandPreset? brand,
  }) {
    final base = EdenTheme.dark(profile: profile, brand: brand?.color);
    return _withProfileTextTheme(base, profile);
  }

  /// Overlay the base TextTheme with profile-aware font families.
  /// Short-circuits when profile uses defaults for both body + display
  /// (back-compat preservation: zero allocation, zero change for default).
  static ThemeData _withProfileTextTheme(
    ThemeData base,
    EdenThemeProfile profile,
  ) {
    final data = profile.data;
    if (data.bodyFontFamily == null && data.displayFontFamily == null) {
      return base;
    }

    final body = base.textTheme;
    final displayOverlay = EdenProfileFonts.displayTextStyle(profile);
    final bodyOverlay = EdenProfileFonts.bodyTextStyle(profile);
    final overridden = body.copyWith(
      // Display + headline roles use the display font.
      displayLarge: body.displayLarge?.merge(displayOverlay),
      displayMedium: body.displayMedium?.merge(displayOverlay),
      displaySmall: body.displaySmall?.merge(displayOverlay),
      headlineLarge: body.headlineLarge?.merge(displayOverlay),
      headlineMedium: body.headlineMedium?.merge(displayOverlay),
      headlineSmall: body.headlineSmall?.merge(displayOverlay),
      // Title/body/label roles use the body font.
      titleLarge: body.titleLarge?.merge(bodyOverlay),
      titleMedium: body.titleMedium?.merge(bodyOverlay),
      titleSmall: body.titleSmall?.merge(bodyOverlay),
      bodyLarge: body.bodyLarge?.merge(bodyOverlay),
      bodyMedium: body.bodyMedium?.merge(bodyOverlay),
      bodySmall: body.bodySmall?.merge(bodyOverlay),
      labelLarge: body.labelLarge?.merge(bodyOverlay),
      labelMedium: body.labelMedium?.merge(bodyOverlay),
      labelSmall: body.labelSmall?.merge(bodyOverlay),
    );
    return base.copyWith(textTheme: overridden);
  }

  @override
  Widget build(BuildContext context) {
    final themeData = light(profile, brand: brand);
    return EdenThemeProfileScope(
      profile: profile,
      child: Theme(
        data: themeData,
        child: child,
      ),
    );
  }
}
