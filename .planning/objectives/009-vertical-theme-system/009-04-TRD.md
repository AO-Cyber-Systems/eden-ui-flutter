<objective>
Ship `EdenProfileFonts` — a static helper that resolves the right `TextStyle` for the active `EdenThemeProfile` using the existing `google_fonts ^6.1.0` package. This is the bridge between the profile-data fields (`bodyFontFamily / displayFontFamily / monoFontFamily` String?) defined in TRD 009-01 and a renderable `TextStyle` consumers can drop into a `Text` widget.

Per `VERTICAL_UX_RESEARCH_2026-05-16.md` §2.4.5:

> Eden ships Outfit/Plus Jakarta/JetBrains Mono via GoogleFonts. Vertical opt-ins:
> - Medical → IBM Plex Sans (body), IBM Plex Mono (codes), Outfit (display retained).
> - Gov → Public Sans (body + display bold).
> - Legal → Crimson Pro or Lora (display headers only).
>
> All Google Fonts. No new pubspec dep. Loaded on-demand by GoogleFonts package.

**Public API surface:**

```dart
class EdenProfileFonts {
  EdenProfileFonts._();

  // ---- Font family string lookups (delegate to profile data) ----

  static String? bodyFontFamily(EdenThemeProfile profile) =>
      profile.data.bodyFontFamily;

  static String? displayFontFamily(EdenThemeProfile profile) =>
      profile.data.displayFontFamily;

  static String? monoFontFamily(EdenThemeProfile profile) =>
      profile.data.monoFontFamily;

  // ---- TextStyle builders ----

  /// Returns a body TextStyle for the active profile. Falls back to
  /// Plus Jakarta Sans when the profile has no body opt-in (commercialWarm /
  /// retailVibrant / legalProfessional).
  static TextStyle bodyTextStyle(
    EdenThemeProfile profile, {
    double? fontSize,
    FontWeight? fontWeight,
    double? height,
    Color? color,
  }) {
    final family = bodyFontFamily(profile);
    if (family == null) {
      return GoogleFonts.plusJakartaSans(
        fontSize: fontSize, fontWeight: fontWeight, height: height, color: color,
      );
    }
    return GoogleFonts.getFont(family,
      fontSize: fontSize, fontWeight: fontWeight, height: height, color: color);
  }

  /// Display fallback = Outfit. Profile opt-ins:
  ///   govFederal → Public Sans, legalProfessional → Crimson Pro.
  static TextStyle displayTextStyle(EdenThemeProfile profile, {...}) { ... }

  /// Mono fallback = JetBrains Mono. All v1 profiles return the fallback.
  static TextStyle monoTextStyle(EdenThemeProfile profile, {...}) { ... }
}
```

|---|---|---|---|---|---|---|
| commercialWarm | null | null | null | Plus Jakarta Sans | Outfit | JetBrains Mono |
| medicalInstitutional | 'IBM Plex Sans' | null | null | IBM Plex Sans | Outfit | JetBrains Mono |
| govFederal | 'Public Sans' | 'Public Sans' | null | Public Sans | Public Sans | JetBrains Mono |

**`GoogleFonts.getFont(family, ...)` is the dynamic-lookup escape hatch** — it returns a `TextStyle` for any Google Fonts family by string name. For the fallback paths (commercialWarm body etc.), the existing static methods (`GoogleFonts.plusJakartaSans()`, `.outfit()`, `.jetBrainsMono()`) are used directly. The TextStyle helper picks the right path.

**Out of scope:** consuming `EdenProfileFonts` in `EdenTheme.light/dark` to rebuild the `TextTheme` per profile. That wiring lives in TRD 009-05 (`EdenAdaptiveTheme`). This TRD only ships the resolver; consumers can call it directly today.

<context>
**Why a separate font helper class vs baking into `EdenTheme`:** `EdenTheme.light/dark` already builds a `TextTheme` with hardcoded Outfit + Plus Jakarta Sans + JetBrains Mono calls (lines 100-116 of `lib/src/theme/eden_theme.dart`). Modifying that to be profile-aware would change the existing back-compat-anchored behavior. Instead, this TRD ships a SEPARATE helper that `EdenAdaptiveTheme` (TRD 009-05) consumes to build an OVERLAY `TextTheme` that overrides specific font families per profile. The existing `EdenTheme` stays UNCHANGED in TRD 009-04.

**Why the resolver delegates to `profile.data.bodyFontFamily` instead of duplicating the table:** single source of truth. TRD 009-01's `EdenThemeProfileData` is the canonical place where per-profile font choices live. The resolver is a THIN translation layer (String? → TextStyle). If TRD 009-01's data changes (e.g., v2 adds IBM Plex Mono for medical), this resolver picks it up automatically — only the `monoTextStyle` method needs the GoogleFonts.getFont call updated, and that's a separate concern.

**Why `GoogleFonts.getFont` (dynamic by string)** vs `GoogleFonts.ibmPlexSans()` (static): GoogleFonts ships static methods for ~50 popular fonts. IBM Plex Sans IS one of them (`GoogleFonts.ibmPlexSans()`). Public Sans IS one of them. Crimson Pro IS one of them. We COULD use the static methods for each. **But:** that locks us to those 3 fonts. Using `getFont(family)` lets a v2 profile add any family (e.g., `EdenThemeProfileData.medicalInstitutionalData.copyWith(bodyFontFamily: 'Source Sans 3')`) without touching the resolver. Dynamic dispatch wins on future-extensibility; the cost is one extra string lookup per font resolution which is negligible.

**`GoogleFonts.getFont` API contract:** returns a `TextStyle` whose `fontFamily` is the canonical Google Fonts family name (e.g., `'IBM Plex Sans'`). Loads the font on first use (async download in non-test environments; bundled in test environments via the `font_loader` set in `flutter_test`). For test environments, GoogleFonts falls back to whatever font matches — confirmed via the project's existing widget tests that use GoogleFonts without issues.

**Why `monoFontFamily` returns null for all v1 profiles:** per research §2.4.5, medical wants IBM Plex Mono for CPT/ICD-10 codes — but per OBJECTIVE.md Out-of-Scope (no per-vertical code-formatting requirements ship in this objective), we defer the medical mono opt-in. The API surface exists (the field is in EdenThemeProfileData) but every v1 profile has it null. v2 can flip medical to 'IBM Plex Mono' without changing this resolver.

**Why we test the fallback path explicitly:** the back-compat invariant (Constraint 1) says `commercialWarm` reproduces today. Today's body font is Plus Jakarta Sans. If we accidentally returned a `GoogleFonts.getFont(null)` (which would default to Roboto OR throw), back-compat breaks. The test asserts the fallback is the right font family — non-negotiable.

**Test environment caveat:** `flutter test` runs without internet access, so `GoogleFonts.getFont(...)` falls back to a stub font with a synthesized `fontFamily` matching the requested name (verified by existing widget tests that use `GoogleFonts.outfit()` etc. — they assert against the font family string, not actual rendering). Our tests follow the same pattern: assert on `style.fontFamily == 'IBM Plex Sans'` etc., not on pixel-level rendering.
</context>

<gotchas>
- **`GoogleFonts.getFont(family)` may throw if the family name is unknown to the package.** Defensive: the families we use (`IBM Plex Sans`, `Public Sans`, `Crimson Pro`) are ALL valid Google Fonts entries per the public catalog. If a test environment fails, suspect the GoogleFonts package version pinning.
- **`GoogleFonts.plusJakartaSans()` returns a TextStyle with `fontFamily: 'Plus Jakarta Sans'`.** Verified — matches the existing `EdenTypography.bodyFont` getter. The fallback path is identical to today's behavior.
- **`TextStyle.fontFamily` for `GoogleFonts.outfit()` is `'Outfit'` (literal string).** Verified via the existing `EdenTheme._buildTheme` calls — Outfit is used unchanged. Our display fallback uses the same call.
- **`GoogleFonts.getFont(family, fontWeight: FontWeight.w400)` — the named params on the dynamic method MATCH the named params on the static methods.** Same signature. Verified via google_fonts source.
- **For test environments where GoogleFonts uses HTTP fallback:** the test process runs in `flutter test` mode which sets `GoogleFonts.config.allowRuntimeFetching = false` by default. If the test infra changed, suspect this flag. The existing test suite (1041+ tests) uses GoogleFonts without issue, so the env is correctly configured.
- **DO NOT use `GoogleFonts.publicSans()` static method even if it exists — use `getFont('Public Sans')` for consistency.** Reason: the dynamic path is what extends to future fonts; using statics for some + dynamic for others is inconsistent and tempts future contributors to add static-only code paths. Pick one pattern. We pick dynamic.
- **`profile.data` is the extension getter from TRD 009-01.** Imported transitively via the eden_theme_profile.dart export. No additional imports needed beyond the existing TRD 009-01 dependency.
- **`Color?` param in TextStyle builders:** passing `null` to GoogleFonts.getFont(color: null) does NOT set the color to black — it leaves it unset (TextStyle inherits from parent). This is the desired behavior; consumers wanting black do `color: Colors.black`.
</gotchas>

<anti_patterns>
- Do NOT bundle font files into the package's `pubspec.yaml > flutter > fonts`. Constraint 2 — no new asset dependencies. GoogleFonts handles font loading at runtime.
- Do NOT cache the resolved TextStyles. GoogleFonts has its own internal caching; double-caching wastes memory and complicates invalidation.
- Do NOT add font-loading orchestration (e.g., `EdenProfileFonts.preloadAll()`). Consumer apps that want preload run the GoogleFonts API directly. v1 doesn't ship preloading.
- Do NOT use the `GoogleFonts.{specific font name}` static methods (e.g., `GoogleFonts.ibmPlexSans()`). Use `GoogleFonts.getFont('IBM Plex Sans')` for consistency. (See `<gotchas>`.)
- Do NOT depend on `EdenTypography` (the existing `lib/src/tokens/typography.dart`) — it's a different abstraction (named TextStyle getters per role). `EdenProfileFonts` is profile-aware family resolution; the two coexist. TRD 009-05 will combine them in EdenAdaptiveTheme.
- Do NOT use `package:flutter/cupertino.dart` or any non-material imports. Material + GoogleFonts only.
- Do NOT add an `EdenProfileFonts.textTheme(EdenThemeProfile)` method that returns a full `TextTheme`. Tempting but premature — TRD 009-05 owns the TextTheme construction; this TRD ships only the family-string + per-style resolution helpers. Keeping the surface small here means less to revise when 009-05 lands.
</anti_patterns>

import 'package:flutter/material.dart';
import 'package:google_fonts/google_fonts.dart';
import 'eden_theme_profile.dart';

/// Per-profile font resolver.
///
/// Bridges the [EdenThemeProfileData] font-family String fields (from
/// TRD 009-01) to renderable [TextStyle]s via the existing `google_fonts`
/// package. Consumers either:
///   - call [bodyTextStyle] / [displayTextStyle] / [monoTextStyle] directly
///     to get a profile-aware TextStyle, or
///   - call [bodyFontFamily] / [displayFontFamily] / [monoFontFamily] to
///     get the family-name String (null = use default).
///
/// **Back-compat fallback contract:** when a profile has no opt-in for a
/// given style (family-string is null), the corresponding TextStyle builder
/// returns the SAME font as today's `EdenTheme` defaults:
///   - body fallback = Plus Jakarta Sans
///   - display fallback = Outfit
///   - mono fallback = JetBrains Mono
///
/// **No Roboto.** A failing fallback would silently render Material's
/// default Roboto; the test suite asserts fontFamily is never 'Roboto'.
///
/// Reads from [EdenThemeProfileData] — single source of truth for the
/// per-profile font-family table. Changing TRD 009-01's data updates this
/// resolver automatically (except for mono which is universally null in v1).
class EdenProfileFonts {
  EdenProfileFonts._();

  // ---------------------------------------------------------------------------
  // Family-name lookups (delegate to profile data — single source of truth).
  // ---------------------------------------------------------------------------

  static String? bodyFontFamily(EdenThemeProfile profile) =>
      profile.data.bodyFontFamily;

  static String? displayFontFamily(EdenThemeProfile profile) =>
      profile.data.displayFontFamily;

  static String? monoFontFamily(EdenThemeProfile profile) =>
      profile.data.monoFontFamily;

  // ---------------------------------------------------------------------------
  // TextStyle builders.
  // ---------------------------------------------------------------------------

  /// Returns a body [TextStyle] for the active profile.
  /// Fallback (family null) = Plus Jakarta Sans (today's default).
  static TextStyle bodyTextStyle(
    EdenThemeProfile profile, {
    double? fontSize,
    FontWeight? fontWeight,
    double? height,
    Color? color,
  }) {
    final family = bodyFontFamily(profile);
    if (family == null) {
      return GoogleFonts.plusJakartaSans(
        fontSize: fontSize,
        fontWeight: fontWeight,
        height: height,
        color: color,
      );
    }
    return GoogleFonts.getFont(
      family,
      fontSize: fontSize,
      fontWeight: fontWeight,
      height: height,
      color: color,
    );
  }

  /// Returns a display [TextStyle] for the active profile.
  /// Fallback (family null) = Outfit (today's default).
  static TextStyle displayTextStyle(
    EdenThemeProfile profile, {
    double? fontSize,
    FontWeight? fontWeight,
    double? height,
    Color? color,
  }) {
    final family = displayFontFamily(profile);
    if (family == null) {
      return GoogleFonts.outfit(
        fontSize: fontSize,
        fontWeight: fontWeight,
        height: height,
        color: color,
      );
    }
    return GoogleFonts.getFont(
      family,
      fontSize: fontSize,
      fontWeight: fontWeight,
      height: height,
      color: color,
    );
  }

  /// Returns a mono [TextStyle] for the active profile.
  /// Fallback (family null — all v1 profiles) = JetBrains Mono.
  static TextStyle monoTextStyle(
    EdenThemeProfile profile, {
    double? fontSize,
    FontWeight? fontWeight,
    double? height,
    Color? color,
  }) {
    final family = monoFontFamily(profile);
    if (family == null) {
      return GoogleFonts.jetBrainsMono(
        fontSize: fontSize,
        fontWeight: fontWeight,
        height: height,
        color: color,
      );
    }
    return GoogleFonts.getFont(
      family,
      fontSize: fontSize,
      fontWeight: fontWeight,
      height: height,
      color: color,
    );
  }
}
