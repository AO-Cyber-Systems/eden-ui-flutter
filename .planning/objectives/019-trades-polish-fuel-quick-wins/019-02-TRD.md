<objective>
Ship `EdenEquipmentRecordCard` + `EdenWarrantyClaim` — paired widgets closing the highest-leverage trades library gap per `USE_CASES_TRADES_2026-05-17.md` Rec #9. RecordCard composes existing primitives (timeline, description list, certificate, membership badge, photo gallery) into the canonical equipment-detail surface. WarrantyClaim is a 3-step form wizard for filing manufacturer warranty claims.

Per Rec #9: "ServiceTitan's #1 competitive moat per FullStackHVAC 2026 comparison. Catching up on equipment depth is high-leverage." Unblocks 4 use cases: UC-19 (tech reviews customer history before arrival), UC-31 (tech creates equipment record post-install), UC-32 (TECH/CUST views equipment service history + warranty status), UC-39 (TECH/OM submits warranty claim to manufacturer).

Cross-vertical reuse: trades HVAC/plumbing equipment (compressor, water heater, electrical panel) + fuel customer-tank lifecycle (propane tank regulator/line/pressure-relief-valve warranty filing). Both verticals model "an installed thing at a customer location with a warranty + service history."

**EdenStatusPalette for warranty color rules:**

```dart
Color _warrantyStatusColor(BuildContext context, EdenEquipmentWarrantyStatus? warranty) {
  final palette = Theme.of(context).extension<EdenStatusPalette>();
  if (warranty == null) return palette?.neutralFg ?? EdenColors.neutral.shade400;
  final remaining = warranty.expiresOn.difference(DateTime.now());
  if (remaining.isNegative) return palette?.errorFg ?? EdenColors.error;
  if (remaining.inDays < 90) return palette?.warningFg ?? EdenColors.warning;
  return palette?.successFg ?? EdenColors.success;
}
```

<anti_patterns>
- **Do NOT bind to specific equipment domains.** `EdenEquipmentRecordData.type` is a free-form String. No `enum HvacEquipmentType`, no `enum FuelTankType`. Consumer maps `equipment` rows to library value classes.
- **Do NOT include a 'Submit Warranty Claim' button on the RecordCard itself.** The RecordCard exposes `onFileWarrantyClaim` callback only; the consumer wires it to either inline open an `EdenWarrantyClaim` widget OR push a route. Decouples the two widgets.
- **Do NOT auto-compute warranty status from the equipment install date.** Consumer provides `warrantyStatus` explicitly. Per use-case docs, warranties can be transferred at home sale, extended by service plan, void due to non-PM — the widget cannot infer.
- **Do NOT use device-time for `DateTime.now()` directly.** Wrap in a `_clock` getter that defaults to `DateTime.now()` but can be overridden in tests (e.g. via a static field or constructor param). Mirror how obj 005 widgets handle timestamps.
- **Do NOT eat the back-button in the warranty wizard.** EdenFormWizard's onCancel handles dismissal; the widget does not override system back.
- **Do NOT bundle photo capture INSIDE the library.** Per constraint 4, photo acquisition is a callback. The library only renders + manages the gallery state.
- **Do NOT auto-validate the claim draft.** Step-level `isValid` checks gate next-step navigation; final submission emits whatever was entered. Consumer's backend does deep validation.
</anti_patterns>

- Boundary: -1 day remaining → red.
