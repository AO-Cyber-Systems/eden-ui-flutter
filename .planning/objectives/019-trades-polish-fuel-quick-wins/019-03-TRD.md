<anti_patterns>
- **Do NOT bind to a specific scheduler view mode.** Default to swimlane (per the use-case docs: "swimlane per crew" is the canonical dispatch shape) but expose `initialMode` so consumers can override. Don't lock to swimlane.
- **Do NOT bundle the route-optimization logic.** Per constraint 4, route optimization is a callback or external API. `EdenDispatchPage` does NOT call Routific / OptimoRoute. The consumer wires it.
- **Do NOT import `EdenAiPanel` or `EdenMapPreview` directly.** Use the slot-builder pattern (consumer supplies `Widget Function(BuildContext, EdenDispatchData)`). This keeps the composite import-light + consumer-customizable.
- **Do NOT eat the scheduler controller's events.** Bubble scheduler controller changes via `onDataChange` callback. The dispatch page is fully controlled — local state only for layout breakpoint cache.
- **Do NOT auto-assign work items.** Even when only one crew can handle a skill, do NOT auto-fire `onDispatchAssignment`. The dispatcher's drag-to-assign gesture is the canonical assignment trigger.
- **Do NOT use `Wrap` for the scheduler swimlane.** Swimlanes must be horizontally-scrollable when more crews exist than fit on screen. Use `EdenSchedulerSwimlaneView`'s built-in horizontal scrolling.
- **Do NOT crash when `data.scheduler.crewResources` is empty.** Render an `EdenEmptyState` with 'No crews configured'.
</anti_patterns>

<gotchas>
- **EdenSchedulerController instantiation.** Per obj 004-01, the controller is required for the scheduler. The dispatch page accepts it as part of `EdenDispatchSchedulerSlot.controller` — caller-supplied. Don't instantiate a new controller inside the dispatch page; that breaks state retention across rebuilds.
- **Drag-and-drop in tabbed mode.** When the layout collapses to tabs at <1024pt, drag-from-queue-to-scheduler is broken (the drag target is on a different tab). Solution: in tabbed mode, show a long-press 'Assign...' menu on each work item that opens a `EdenSelect<crewId>` modal. Use platform-aware UX.
- **Slot-time computation from drop position.** When a work item is dropped on a swimlane column at vertical position Y, compute the slot time from `(Y - swimlaneTop) / pxPerMinute + dayStart`. The swimlane view exposes a `pxPerMinute` getter — verify at TRD-execute time. If not, use a default 1pt = 1min and document the assumption.
- **`onDispatchAssignment` payload.** The assignment is just (workItemId, crewResourceId, scheduledStart, scheduledDuration). The dispatch page does NOT persist; consumer's backend does. The dispatch page emits + leaves the work item in the queue + scheduler in unchanged state until the consumer mutates `data` and passes the updated `EdenDispatchData` back via the next build.
- **Crew capability check.** `onWillAccept` gates the drop based on `_crewCanHandle(crew, workItem)`. Default rule: crew accepts work item if `workItem.requiredSkills` is empty OR `crew.skills` is a superset of `workItem.requiredSkills`. Provide a sane default; expose `onCrewWillAcceptItem` callback for consumer override.
- **Layout breakpoints.** 1280 / 1024 / 800 are the breakpoints. iPhone-narrow (390pt) falls into the tabbed layout. Verify that `EdenSchedulerSwimlaneView` itself doesn't internally overflow at 390pt (it should, per obj 004-08 mobile view; if not, swap to `EdenSchedulerMobileView` at <600pt).

- Slot-builder pattern (`EdenDispatchSlotBuilder = Widget Function(BuildContext, EdenDispatchData)`) lets the consumer wire ANY map provider + ANY AI personality without the dispatch page importing them. Keeps composite import-light and consumer-customizable.

- Drag-from-queue-to-scheduler is the canonical dispatch gesture — every competitor (ServiceTitan / Jobber / Housecall / Workiz) ships drag-drop dispatch.
- `onDispatchAssignment` payload is just (workItemId, crewResourceId, scheduledStart, scheduledDuration) — consumer's backend persists, then sends back updated `data` for next render. Library never persists.
