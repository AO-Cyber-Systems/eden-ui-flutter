<objective>
Ship `EdenPriceBookBuilder` — the foundational pricing-catalog primitive for trades / salon / fuel verticals. 4-section composite (Categories + Items + Tiers + Taxes) that the consumer drops into a settings page and edits in place. Composes obj 012's `EdenLineItemEditor` for the items-table editing.

Per `USE_CASES_TRADES_2026-05-17.md` Rec #1: "Price book is the #1 trades feature universally shipped by every competitor, and Eden Biz has no first-class library widget today." Ranked #1 for unblock impact — closes UC-65 (settings: customize price book; must-launch) and dramatically improves UC-02 (every estimate touches this). Also serves UC-04 (proposals) and UC-40 (in-field invoicing).

Cross-vertical reuse beyond trades: salon `service_catalog` rows map to `EdenPriceBookItem` directly; fuel uses tier overrides for per-fuel-type pricing (rack price vs retail vs commercial-account rate); medical uses for procedure-code (CPT) catalog pricing.

Outside-in test approach (per user TDD Playbook habit 5): start with widget-rendering tests (builder renders 4 sections; section nav switches between them), then editing tests (add category, edit item base rate, edit tier markup, edit tax cell), then responsive tests at 390pt + 900pt thresholds, then save/cancel/dirty-state tests.

One test at a time per habit 3. RED → GREEN → next test.

<anti_patterns>
- **Do NOT bind to specific verticals.** `EdenPriceBookItem` is generic — no `HvacServiceCategory`, no `SalonServiceType`, no `FuelGrade`. Consumer maps domain rows to library value classes.
- **Do NOT include an "Add row" button INSIDE the items editor.** Per obj 012-01 pattern, vertical-specific add UX (HVAC service templates / salon service picker / fuel-type chip strip) belongs in the consumer's `itemPickerSlot`. The editor only edits / removes / reorders existing rows.
- **Do NOT use Form + FormField validators.** The builder is real-time editable. Validation is the consumer's responsibility (they wire it via `onDraftChange` and surface validation in their own UI).
- **Do NOT eat the back-button when dirty.** When the user navigates away with unsaved changes, the consumer's router decides whether to prompt — not the builder. The builder exposes `bool get isDirty` and `void revert()` for the consumer.
- **Do NOT round currency in the baseFlatRate / tierOverrides.** Display via `EdenCurrencyDisplay` (which rounds for display only); store as raw double for precision.
- **Do NOT throw on empty tax matrix.** `EdenPriceBookTaxMatrix(jurisdictions: [], itemTypes: [], rates: {})` is valid (zero-config tax). Render an `EdenEmptyState` with a "Configure jurisdictions" CTA.
- **Do NOT auto-create a default category.** If `initialData.categories` is empty, render an `EdenEmptyState` in the categories section with a "Create your first category" CTA that calls the add-category flow.
- **Do NOT mutate the inbound `initialData`.** Treat it as immutable; clone into local state at `initState()` + `didUpdateWidget()` (when initialData reference changes).
</anti_patterns>

**Cross-vertical sample scenarios for catalog:**

1. **HVAC flat-rate trades** — 3 categories (Repair / Replacement / Maintenance), 12 items with good-better-best tier examples (compressor repair / replacement / new install), 2 tiers (Standard / Gold member), 1 jurisdiction (CA, 8.25% rate).
2. **Salon service catalog** — 4 categories (Hair / Color / Nails / Wax), 18 items, 3 tiers (Walk-in / Member / VIP), 1 jurisdiction.
3. **Fuel-type pricing** — 2 categories (Residential / Commercial), 4 items (Propane / Heating Oil / Diesel / Gasoline), 3 tiers (Will-call / Auto-fill / Contract-locked), 3 jurisdictions × 3 item-types tax matrix.

**Why this design:**
- 4 sections cover the actual ops workflow (per use-case docs UC-65: "Owner customizes price book + adds custom services" + "Vendor cost change"). Categories first (organize structure), Items second (the daily-edit surface), Tiers third (less frequent), Taxes fourth (rare).
- Good-better-best as opt-in field (`gbb` nullable on item) keeps simple cases simple — most trades items are flat-rate single-price, only the high-margin sales items get GBB treatment.
- Tier overrides at item-level (not category-level) is intentional — ServiceTitan Pricebook Pro models this same way ("Client-Specific Pricing" feature). Categories are organizational; tiers are pricing dimensions.
- Tax matrix as separate section (rather than per-item taxRate) is intentional — taxes apply by jurisdiction × item-type, not by individual item. This matches real-world flat-rate-tax-matrix accounting (CA service tax differs from CA parts tax; NY service tax differs from NY parts tax).

## Test list (write FIRST, per TDD Playbook habit 2)

**Static rendering — 4 sections via tabs (>=900pt)**
- `EdenPriceBookBuilder(initialData: fx.hvac, onSave: noop)` renders an `EdenTabs` (or `TabBar`) with 4 tabs (Categories / Items / Tiers / Taxes).
- Renders 'Save' button at top-right.
- Defaults to `initialSection: categories` — categories tab is selected on first render.
- `initialSection: EdenPriceBookSection.items` → items tab selected on first render.

**Static rendering — narrow width (<900pt)**
- At width 800, renders an `EdenSelect` dropdown with 4 options instead of tabs.
- At width 390, renders the dropdown; categories section uses flat list (no tree affordance).

**Categories section**
- Renders 3 categories from `fx.hvac.categories` (Repair / Replacement / Maintenance).
- Empty state: `EdenPriceBookBuilder(initialData: fx.empty, ...)` renders "Create your first category" CTA.
- Tap category → selects it (visible selected state).
- Add-category button visible (NOT in readOnly mode); tapping it inserts a new category at the end; `onDraftChange` fires with new draft including the added category.
- Drag-reorder works: drag category-2 above category-1 → category list reorders → `onDraftChange` fires with reordered list; newIndex quirk normalized.
- Renaming a category: tap rename inline → edit text → blur → `onDraftChange` fires with updated name.
- Delete category: tap delete icon → confirms via `EdenConfirmDialog` → category removed → `onDraftChange` fires.

**Items section**
- Tap Items tab → `EdenLineItemEditor` renders with items from selected category.
- If no category selected, renders empty state "Select a category to view items".
- `itemPickerSlot` (consumer-supplied widget) renders above the editor.
- Edit baseFlatRate cell → editor calls `onItemsChanged` → builder maps back to `EdenPriceBookItem` → `onDraftChange` fires.
- Remove item → `onDraftChange` fires with item removed from the category's items list.
- Custom column (per must-have): shows badges for tier-override count / labor / SKU / GBB-link.
- GBB-link tap → opens `EdenModal` with 3 columns at >=900pt; 3 columns each have label-input + price-input; save → updates item.gbb → `onDraftChange`.
- GBB modal at <900pt → columns stack vertically.

**Tiers section**
- Tap Tiers tab → renders list of tier cards from `fx.hvac.tiers`.
- Each card shows name + defaultMarkupPct input + per-item override count.
- Edit defaultMarkupPct → `onDraftChange` fires.
- Add-tier button → inserts new tier → `onDraftChange`.
- 'Edit overrides' link on a tier card → switches to Items section + filters by tier.

**Taxes section**
- Tap Taxes tab → renders `EdenDataTable.dense` with jurisdictions as rows + itemTypes as columns.
- Cell shows current rate (e.g. '8.25%' for 0.0825).
- Edit cell → `onDraftChange` fires with updated tax matrix.
- Empty tax matrix → empty state with "Configure jurisdictions" CTA.
- At <900pt: tax matrix collapses to vertical-stacked jurisdiction cards.

**Save / cancel / dirty state**
- Initially `isDirty == false` → Save button disabled or muted.
- After any edit → `isDirty == true` → Save enabled + dirty banner shows.
- Tap Save → `onSave` fires with current draft → `isDirty == false` again.
- Tap Cancel (in dirty banner) → state reverts to initialData → `isDirty == false`.
- `didUpdateWidget` with new `initialData` (different identity) → state resets to new initialData; current section persists.

**Read-only mode**
- `EdenPriceBookBuilder(readOnly: true, ...)` → no add buttons, no remove icons, no editable cells.
- Save button NOT shown.
- `EdenLineItemEditor.readOnly == true` (inspected via widget tree).

**Cross-vertical scenarios**
- `EdenPriceBookBuilder(initialData: fx.salon, ...)` renders 4 categories (Hair / Color / Nails / Wax) — same widget code path.
- `EdenPriceBookBuilder(initialData: fx.fuel, ...)` renders 2 categories (Residential / Commercial) — same widget code path.

**Responsive — iPhone-narrow (390pt) without overflow**
- `wrap(EdenPriceBookBuilder(...), width: 390)` renders without `RenderFlex overflowed` warnings.
- All 4 sections individually render at 390pt without overflow.
- Tax matrix at 390pt is vertical-stacked.

- Wrap in `EdenAdaptiveTheme(profile: EdenThemeProfile.medicalInstitutional, ...)` → status badges shift to medical palette.
- No `EdenAdaptiveTheme` ancestor → falls back to `EdenColors.success` / `.warning` etc.
