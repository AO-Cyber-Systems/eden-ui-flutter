<anti_patterns>
- DO NOT compare two live calls to each other (`EdenTheme.light()` vs
  `EdenAdaptiveTheme.light(commercialWarm)`) as the ONLY proof. Objective 009 already
  does that and it cannot catch a change that moves both sides together. The recorded
  constant is the whole point of this TRD.
- DO NOT use `expect(themeA, themeB)` on whole `ThemeData` objects. `ThemeData.==` spans
  ~100 fields including sub-theme objects and callbacks; a failure yields an unreadable
  diff and it is brittle against Flutter SDK upgrades that add fields. Enumerate the
  observable fields instead.
- DO NOT collapse the baseline into a single hash/digest string. A digest mismatch tells
  you nothing about which field drifted. Use map-keyed expectations so the failure
  message names the key.
- DO NOT modify `test/theme/eden_adaptive_theme_test.dart` or any other objective 009
  test. They must stay green AND unmodified.
- DO NOT touch `lib/` in this TRD at all.
</anti_patterns>

<error_recovery>
**GoogleFonts requires an initialized binding.** A plain `test('...', () {})` that calls
`EdenTheme.light()` fails with:

```
Error: google_fonts was unable to load font Outfit-ExtraBold because the following
exception occurred: Binding has not yet been initialized.
```

This is why every objective 009 theme test uses `testWidgets(...)`. Use `testWidgets`
here too (or call `TestWidgetsFlutterBinding.ensureInitialized()` first). VERIFIED
2026-08-26.

**Font families carry a weight suffix.** `GoogleFonts` returns families like
`PlusJakartaSans_regular`, `Outfit_800`, `PublicSans_regular` — NOT `Plus Jakarta Sans`.
Record the exact string the runtime produces; do not "tidy" it. VERIFIED 2026-08-26.

**If a recorded value does not reproduce on re-run:** the field is non-deterministic and
does not belong in the baseline. Remove that key and note it in the SUMMARY rather than
weakening the assertion to a range check.
