the five `const` instances.

`window.APP_CONFIG` has nothing to build. This is capability 2 of 3.

plus a test suite. No existing behaviour changes.

<anti_patterns>
- DO NOT expose `radiusMultiplier`, `minimumTouchTargetPx`, `preferBorderOverShadow` or
  `surfaceTonalSeed` as parameters on `copyWith` or on the `runtime` factory. Those four
  tokens are read by NO production code (022-CONTEXT.md finding 6). Letting a partner set
  `radiusMultiplier: 0.5` from config, and having it change nothing on screen, is exactly
  the "looks finished but reaches nothing" failure the objective forbids. Carry them
  through by pass-through; do not offer them.
- DO NOT wire those four tokens into a ThemeExtension or into any widget. That is
  Objective 0b: 165 of 314 files in `lib/src/widgets/` use `EdenRadii.*` as static
  constants and 184 files in `lib/src` reference `EdenColors` directly. Out of scope.
- **`density` IS exposed on `copyWith` while those four are not — that asymmetry is
  deliberate and must be documented in the code, not left to be discovered.**
  `EdenThemeProfileDensity` is a FIFTH inert token: measured 2026-08-26, it has zero
  production references outside its own enum declaration, the constructor default and
  the field declaration. The line that matters is not "inert vs live", it is **which
  surface**. `copyWith` is a Dart-literal API a library consumer calls with a typed
  enum value in hand. `runtime()` and (in TRD 022-05) `lightFromConfig` are the CONFIG
  surfaces — the ones a partner's `window.APP_CONFIG` string reaches. `density` appears
  on neither, so no config value can set it and no partner can be shown a control that
  does nothing. Keep it that way: do NOT add `density` to `runtime()`.
- DO NOT change, reorder, rename or add to the `EdenThemeProfile` enum. It is LOCKED at
  five members (009 Constraint 11), and `EdenStatusPalette.forProfile` switches on it
  exhaustively.
- DO NOT convert the five static instances away from `const`, and do not touch their
  declared values. `flutter analyze` will not catch a semantic drift here — TRD 022-01's
  baseline will, loudly.
- DO NOT add a mutable builder class. An `@immutable` value type with `copyWith` is the
  established shape in this repo (`EdenTemplateLayoutSettings`,
  `EdenTemplateStyleSettings` from objective 021 both do this).
- DO NOT add `==`/`hashCode` overrides. They are not needed by any of the three
  capabilities, and changing equality semantics on a type embedded in theme resolution is
  gratuitous risk against the byte-identity spine. Assert field-by-field in tests instead.
</anti_patterns>

<error_recovery>
**The `copyWith` null-clearing ambiguity.** `copyWith({String? bodyFontFamily})` cannot
distinguish "caller omitted it" from "caller wants null". Resolve it by DOCUMENTING that
`copyWith` cannot clear a nullable field back to null, and pointing callers who need that
at the public `const` constructor. Do NOT introduce a sentinel wrapper type or an
`Object? = _undefined` trick — the extra machinery is not worth it for a case runtime
config never hits (config supplies values, it does not un-supply them).

**If `flutter analyze` reports the const instances are no longer const**, you have
introduced a non-const expression into the constructor's default arguments or field
initialisers. Revert and re-apply additively — `copyWith` and a `static` factory cannot
affect const-ness of existing instances unless the constructor itself was edited.
</error_recovery>

<gotchas>
- A runtime instance MUST carry a real `EdenThemeProfile` value in its `profile` field.
  `EdenStatusPalette.forProfile(profile)` switches exhaustively over the enum, and
  `EdenTheme.light(profile:)` uses the enum for exactly that one purpose
  (022-CONTEXT.md finding 1). The `runtime` factory therefore takes a `base` profile and
  inherits its enum value — a runtime profile is "commercialWarm with these overrides",
  never a sixth profile.
- `primaryColor` is typed `MaterialColor`, not `Color`. The runtime factory's
  `primaryColor` parameter must be `MaterialColor?` too — a downstream app gets one from
  `EdenBrandSwatch.tryParse` (TRD 022-02). Do not widen the field type to `Color`; that
  would break `EdenTheme.dark()`'s `primary[950]!` shade dereference.

```dart
  /// Returns a copy with the given fields replaced.
  ///
  /// **Cannot clear a nullable field back to null** — omitting a parameter means
  /// "keep the current value". Callers needing an explicit null should use the
  /// public `const` constructor directly. Runtime config supplies values; it does
  /// not un-supply them.
  ///
  /// `surfaceTonalSeed`, `radiusMultiplier`, `minimumTouchTargetPx` and
  /// `preferBorderOverShadow` are deliberately NOT settable here. They are read by
  /// no production code today (see objective 022 CONTEXT finding 6); making them
  /// configurable before they reach widgets would advertise a control that does
  /// nothing. They are carried through unchanged. Wiring them up is objective 0b.
  ///
  /// `density` IS settable here, and that asymmetry is intentional.
  /// [EdenThemeProfileDensity] is inert too — it has no production reader outside
  /// this file — but `copyWith` is a Dart-literal API, whereas [runtime] and
  /// `EdenAdaptiveTheme.lightFromConfig` are the surfaces a partner's
  /// `window.APP_CONFIG` string reaches. `density` is absent from BOTH of those, so
  /// no runtime config value can set it. Do not "finish the set" by adding it to
  /// [runtime]; that would put an inert control on the config surface, which is the
  /// one thing objective 022 forbids.
  EdenThemeProfileData copyWith({
    EdenThemeProfile? profile,
    MaterialColor? primaryColor,
    EdenThemeProfileDensity? density,
    String? bodyFontFamily,
    String? displayFontFamily,
    String? monoFontFamily,
  }) {
    return EdenThemeProfileData(
      profile: profile ?? this.profile,
      primaryColor: primaryColor ?? this.primaryColor,
      surfaceTonalSeed: surfaceTonalSeed,           // pass-through
      radiusMultiplier: radiusMultiplier,           // pass-through
      density: density ?? this.density,
      minimumTouchTargetPx: minimumTouchTargetPx,   // pass-through
      bodyFontFamily: bodyFontFamily ?? this.bodyFontFamily,
      displayFontFamily: displayFontFamily ?? this.displayFontFamily,
      monoFontFamily: monoFontFamily ?? this.monoFontFamily,
      preferBorderOverShadow: preferBorderOverShadow, // pass-through
    );
  }

  /// Builds profile data from plain RUNTIME values — the entry point for a
  /// downstream app assembling a theme from `window.APP_CONFIG` at boot.
  ///
  /// Starts from [base]'s canonical data and applies the supplied overrides, so
  /// the result always carries a real [EdenThemeProfile] and
  /// `EdenStatusPalette.forProfile` keeps resolving. A runtime profile is
  /// "[base] with overrides", never a sixth profile — the enum is LOCKED at five.
  ///
  /// [monoFontFamily] is carried as DATA and is not applied to any `ThemeData`.
  /// Material's [TextTheme] has no mono role, so nothing in Eden's theme pipeline
  /// consumes it; a consumer that wants mono type reads this field (or calls
  /// `EdenProfileFonts.monoTextStyleForFamily` directly) and styles its own widget.
  /// That is why the field lives here and NOT on
  /// `EdenAdaptiveTheme.lightFromConfig` — a data field a consumer reads is honest,
  /// a theme-building parameter that themes nothing is not. See TRD 022-05.
  ///
  /// ```dart
  /// final data = EdenThemeProfileData.runtime(
  ///   primaryColor: EdenBrandSwatch.tryParse(config['brandHex']) ??
  ///       EdenThemeProfile.commercialWarm.data.primaryColor,
  ///   bodyFontFamily: config['fontFamily'],
  /// );
  /// ```
  static EdenThemeProfileData runtime({
    EdenThemeProfile base = EdenThemeProfile.commercialWarm,
    MaterialColor? primaryColor,
    String? bodyFontFamily,
    String? displayFontFamily,
    String? monoFontFamily,
  }) {
    return base.data.copyWith(
      primaryColor: primaryColor,
      bodyFontFamily: bodyFontFamily,
      displayFontFamily: displayFontFamily,
      monoFontFamily: monoFontFamily,
    );
  }
```
