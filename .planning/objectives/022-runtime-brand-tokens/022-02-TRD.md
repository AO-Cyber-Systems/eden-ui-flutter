<research_context>
**The ramp algorithm is already chosen and empirically validated — implement this, do
not re-derive it.** Measured 2026-08-26 against the eight hand-tuned `EdenColors`
swatches, then verified across nine inputs including the pathological ones.

Chosen: **HSL lightness ramp anchored at the input's own lightness.** Preserve the
input's hue and saturation on every shade; vary only lightness. This is the only family
of algorithms that can satisfy "shade 500 equals the supplied colour" exactly.

The interpolation curve was derived from the MEAN HSL lightness of the seven non-neutral
`EdenColors` swatches, so a generated ramp looks like a sibling of the hand-tuned ones:

    shade:  50    100   200   300   400   500   600   700   800   900   950
    meanL:  97.0  92.8  86.2  76.3  62.9  53.1  44.7  37.5  30.7  25.2  14.6

Because existing 500-shades range from L=39.4 (emerald) to L=65.1 (purple), an absolute
target curve would break the 500==input requirement. So normalise the curve into
position weights and interpolate from the anchor outward:

    lightEnd = max(97.0, (anchorL + 100.0) / 2.0)   // clamp engages only when anchorL > 97
    darkEnd  = min(14.6, anchorL / 2.0)             // clamp engages only when anchorL < 29.2

    for shades < 500:  t = (meanL[s] - meanL[500]) / (meanL[50] - meanL[500])
                       L[s] = anchorL + t * (lightEnd - anchorL)
    for shade  == 500: L[500] = anchorL              // exact
    for shades > 500:  u = (meanL[500] - meanL[s]) / (meanL[500] - meanL[950])
                       L[s] = anchorL - u * (anchorL - darkEnd)

Precomputed weights — embed these as constants:

    t[50]=1.000000  t[100]=0.904328  t[200]=0.753986  t[300]=0.528474  t[400]=0.223235
    u[600]=0.218182 u[700]=0.405195  u[800]=0.581818  u[900]=0.724675  u[950]=1.000000

The two clamps exist because the unclamped form INVERTS for extreme inputs (verified:
`#FAFAFA` produced shade 50 darker than shade 500; `#101010` produced shade 950 lighter
than shade 500). The clamps are no-ops for every normal brand colour.

VERIFIED output — all nine cases monotonic with shade 500 exact:

  #0F62FE (IBM Carbon Blue 60, the partner hex named in the objective):
    50 #F0F5FF · 100 #DAE7FF · 200 #B8D1FF · 300 #86B0FE · 400 #4183FE · 500 #0F62FE
    600 #014FE2 · 700 #0142BD · 800 #01369B · 900 #012D7F · 950 #001A4A
    Contrast: white-on-500 = 5.00:1 (AA for normal text); shade 400 on Eden dark
    surface `neutral[900]` #18181B = 4.98:1. Legible on BOTH light and dark surfaces,
    which is the 022-CONTEXT.md § Discretion requirement.

  #D4A853 (AO gold) reproduces a close analogue of the hand-tuned gold ramp, confirming
  the curve matches house style.

  #FFFFFF, #000000, #FAFAFA, #101010, #FF0000, #808080, #00FF00: all monotonic, all
  500-exact.

Dart has no HSL helper you should hand-roll: use `HSLColor.fromColor(c)` and
`hslColor.withLightness(l).toColor()` from `dart:ui`/`package:flutter/material.dart`.
`HSLColor.lightness` is 0..1, so divide the L values above by 100.
</research_context>

<gotchas>
- `HSLColor.fromColor` on a fully-desaturated input yields `saturation == 0` and an
  arbitrary hue; `withLightness` still behaves correctly, producing a grey ramp. No
  special-casing needed, but include a grey input in the fixture to lock the behaviour.
- Round-tripping `Color -> HSLColor -> Color` is NOT exactly lossy-free for all inputs.
  Shade 500 must therefore be the ORIGINAL parsed `Color`, assigned directly — do NOT
  compute it through the HSL round trip, or `500 == input` will fail by a bit or two on
  some hexes.
- `Color.value` is deprecated in newer Flutter SDKs in favour of the float channel
  accessors, but this repo's existing code (`eden_theme.dart`, the 009 tests) uses
  `.value` throughout. Stay consistent with the repo; do not start a migration here.
- The `MaterialColor` constructor's first argument is the primary ARGB int; it must equal
  shade 500 or `ColorScheme.light(primary: swatch)` and `swatch[500]` disagree.
- `EdenTheme.brandColor` is a mutable static. Do not assign to it from library code.
</gotchas>

Public surface — keep it small and boring:

```dart
/// Generates a full 11-shade Eden [MaterialColor] from one arbitrary hex string.
///
/// This is the ESCAPE HATCH for a partner brand colour that is not one of the 15
/// [EdenBrandPresetRegistry] presets (022-CONTEXT.md LOCKED decision 3) — the
/// registry is unchanged and remains the preferred path.
///
/// Designed for runtime config: a Flutter web app reads `"#0F62FE"` out of
/// `window.APP_CONFIG` at boot and passes the String straight in.
class EdenBrandSwatch {
  EdenBrandSwatch._();

  /// Parses [hex] and returns an 11-shade swatch, or null when [hex] is not a
  /// colour this can understand. NEVER throws — a malformed partner value must
  /// not take an app's boot down.
  static MaterialColor? tryParse(String? hex);

  /// Builds an 11-shade swatch around an already-parsed [seed].
  /// Shade 500 is [seed] exactly.
  static MaterialColor fromColor(Color seed);
}
```

Approach:

1. `tryParse`:
   - null / blank -> null
   - trim, strip a single leading '#', uppercase
   - accept length 3 (expand each nibble: 'F00' -> 'FF0000'), 6 (prefix 'FF'), or 8
     (already AARRGGBB). Any other length -> null
   - `int.tryParse(value, radix: 16)`; null result -> null
   - `return fromColor(Color(argb))`

2. `fromColor`:
   - `final hsl = HSLColor.fromColor(seed); final anchorL = hsl.lightness * 100;`
   - `final lightEnd = max(97.0, (anchorL + 100.0) / 2.0);`
   - `final darkEnd  = min(14.6, anchorL / 2.0);`
   - for each shade, compute L from the embedded t/u weight constants, then
     `hsl.withLightness((L / 100).clamp(0.0, 1.0)).toColor()`
   - **assign shade 500 to `seed` DIRECTLY**, not via the HSL round trip
   - `return MaterialColor(seed.value, {50: ..., ..., 950: ...});` — eleven keys
