<objective>
Port trades-flutter `lib/shared/widgets/list_page_scaffold.dart` into eden-ui-flutter as `EdenListPageScaffold`. Composable list-page scaffold: header (title + optional Create button slot) → optional alerts slot → optional filter pills slot → optional search input slot → body slot. **Transport-agnostic** — strip the Riverpod / PermissionGate / search-provider plumbing from the trades donor; library version exposes raw slots and callbacks only. Every Eden Biz vertical's CRUD admin list pages compose against this scaffold.
</objective>

## Test list (write FIRST, before any test code)

Behavior cases this widget must satisfy:

**Happy path**
- Renders with only required props (title + body): shows title in header, shows body, no alerts/filter/search/create button slots rendered.
- Renders with full slot composition: title, alerts slot, filter pills slot, search slot, create button slot, body — all visible in correct vertical order.
- Tapping the "+ Create" button (when `onCreate` is set) invokes the callback.
- `searchHint` text appears as placeholder when search slot is enabled and no input has been typed.
- `onSearchChanged` callback fires with the typed value when user types in the search field.

**Edge cases**
- `createLabel` provided but `onCreate` is null → create button is NOT rendered (no dead button).
- `filterPills` is null → filter row collapses (zero vertical space, not just `Visibility.invisible`).
- `alerts` is null → alerts row collapses.
- Body is a tall scrollable → outer scaffold does NOT add its own scroll wrapper (body owns scroll).

**Failure / safety**
- Renders at iPhone-narrow (390pt logical width) with no `RenderFlex overflowed` warnings — header row uses Wrap or LayoutBuilder fallback to stack title above create button when constrained.
- Renders at tablet (768pt) and desktop (1280pt) without layout regressions.
- Renders inside a `MaterialApp(home: Scaffold(body: ...))` (the `wrap()` helper); does NOT require its own `Scaffold` ancestor.
