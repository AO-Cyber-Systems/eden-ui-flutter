# Objective 23 TRD 12: Release Bookkeeping (CHANGELOG / README / version) Summary

Cut the `2.2.0` release bookkeeping for objective 23 — renamed the CHANGELOG's `## Unreleased`
heading, documented the new public surface and the one changed default, wrote the additive-only
contract into README, and bumped `pubspec.yaml` from `2.0.0` to `2.2.0` (the field `release.yml`
derives the tag from). **Nothing pushed, nothing tagged, no PR** — and the CHANGELOG states plainly
that the tree is not release-ready.

## Version proof (both facts verified in-repo, not assumed)

```
$ grep '^version:' pubspec.yaml        # BEFORE
version: 2.0.0

$ git tag --list 'v*' | sort -V | tail -3
v1.0.0-rc.1
v2.0.0
v2.1.0

$ grep -n '^version:' pubspec.yaml     # AFTER
3:version: 2.2.0
```

`.github/workflows/release.yml` derives the tag with
`VERSION=$(grep '^version:' pubspec.yaml | sed 's/version: //')`, so the field is authoritative and
must be monotonic against the highest existing tag. `2.1.0` is already taken (at `e719691`, whose
pubspec also reads `2.0.0` — so `release.yml` cannot have cut that tag; it was made another way).
`2.2.0` is therefore the next valid value. Recorded in the CHANGELOG so the next reader does not
have to re-derive it.
