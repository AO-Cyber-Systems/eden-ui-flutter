<anti_patterns>
- **Do NOT write patterns for widgets that do not exist yet.** A pattern with no implementing widget
  and no story is a wish. Where wave-1 has no story for a pattern (list-detail, bulk-action-bar,
  studio-three-pane), say so explicitly in the file's `## Widgets` section rather than citing a story
  id that will fail the test.
- **Do NOT invent must_not terms per file.** The vocabulary is closed and shared with W1b. If a rule
  needs a term that is not in the list, add it to `must_not_vocabulary.json` in the same commit and
  flag it in the SUMMARY as a cross-repo change.
- **Do NOT write the rules as advice.** "Prefer not to navigate on close" is unenforceable. "must_not:
  navigate on close" is a term a spec can carry and a check can read.
- **Do NOT use a YAML front-matter block.** Dart has no built-in YAML parser and this package takes no
  new dependencies — story ids are cited as `story:<id>` tokens in the prose instead (see below).
</anti_patterns>

- If a pattern legitimately has no story yet, the file states `_no story yet — wave 1 scope is the
