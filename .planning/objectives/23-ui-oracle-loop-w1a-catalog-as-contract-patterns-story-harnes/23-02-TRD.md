<objective>
Plan row **1a-02 (`expectUiSane`)**. Ship the story harness's three assertions as one callable helper
at `package:eden_ui_flutter/testing.dart`, so the 600+ screen tests in eden-biz and aodex gain the
oracle without each writing it.

Purpose: §6.3 of the proposal is blunt about why this exists — without it, §6.2's harness only ever
protects this library's own stories and the consumers get nothing. This is the single most
widely-called artifact the objective ships.

Output: `lib/testing.dart` + `lib/testing/`, five hand-built broken fixtures, and six behaviour cases
each proven RED by **stashing the fixture's fix**, not by asserting that an assertion exists.
</objective>

<anti_patterns>
- **Do NOT prove RED by asserting the assertion exists.** "`expect(() => expectUiSane(tester), throwsA(...))`"
  written against an already-correct implementation proves nothing. The objective mandates: build the
  fixture broken, watch the case fail for the RIGHT reason, then fix. See the memory note
  `trd-prescriptions-need-verifying` — three of four prescribed assertions in one objective could not
  fail, or could not pass.
- **Do NOT export `testing.dart` from `lib/eden_ui.dart`.** That would drag `package:flutter_test` into
  two production apps on the next pin bump.
- **Do NOT re-implement the geometry walk.** It exists in `test_support/ui_oracle/semantics_geometry.dart`
  (23-01). Move it, do not copy it — two copies drift and only one gets the container:true fix.
- **Do NOT make `expectUiSane` fail on an empty semantics tree.** A surface with no identified controls
  is not broken; it has nothing to check. Failing there makes the helper unadoptable.
</anti_patterns>

<error_recovery>
- `tester.takeException()` CONSUMES the exception. Call it exactly once, keep the value, and re-report
  it in the failure message — a second call returns null and the overflow disappears.
- `meetsGuideline(textContrastGuideline)` needs `tester.ensureSemantics()` and real rendered colours;
  it silently passes on a transparent-on-transparent surface. The dark-on-dark fixture must use
  opaque colours.
- RenderFlex overflow is reported through `FlutterError` during layout, not as a thrown exception at
  the call site — it lands in `takeException()` only if it happened during the pump inside the test.
  Pump the fixture inside the test body, never in `setUp`.
</error_recovery>

## Test list

Six cases. Case 1 is the adoption gate; cases 2-6 are the five broken fixtures named in OBJECTIVE.md.
Each of 2-6 is proven RED by **stashing that fixture's fix** and watching it fail with the widget named.

1. **passes on a clean story** — `cleanSurface` (a 400x300 card with two well-spaced 48x48 identified
   buttons, legible contrast) → `expectUiSane` completes without throwing.
2. **RenderFlex overflow** — `overflowingRow`: a 215px overflow from a long unwrapped `Text` in an
   unbounded `Row` slot → fails, message contains the overflow pixel count and the widget.
3. **overlapping identified controls** — `overlappingControls`: two `Semantics(container: true)`
   controls placed by a `Stack` so their rects intersect → fails naming BOTH identifiers.
4. **two tap actions on one control** — `doubleTapAction`: `ExcludeSemantics` outside a
   `Semantics(onTap:)` wrapping an `InkWell` → fails naming the identifier and the count.
5. **sub-24px tap target** — `tinyTapTarget`: a 20x20 tappable → fails via `androidTapTargetGuideline`.
6. **dark-on-dark contrast** — `darkOnDark`: `#2A2A2A` text on `#1E1E1E`, both opaque → fails via
   `textContrastGuideline`.

Adoption invariant (verified by command, not a test case): `lib/eden_ui.dart` does not export
`testing.dart`, and nothing under `lib/src/` imports `lib/testing/`.

Implement the geometry/structure half of:

```
Future<void> expectUiSane(WidgetTester tester, {Set<String> allowOverlap = const {}}) async
```

Approach:
1. `final handle = tester.ensureSemantics();` / `addTearDown(handle.dispose)`.
2. Collect `identifiedNodes(tester)` (23-01's helper, now in lib/testing/).
3. **Exception check** — `final ex = tester.takeException();` ONCE. Non-null → fail with
   `'expectUiSane: an exception escaped during layout/paint: $ex'` and, when the string mentions
   RenderFlex, echo the overflow pixels.
4. **Viewport containment** — every identified node's `globalRect` is inside
   `tester.view.physicalSize / devicePixelRatio`. Fail naming the identifier and both rects.
5. **Disjointness** — for every unordered pair not in `allowOverlap`, `rectsOverlap` is false. Fail
   naming BOTH identifiers and the intersection rect.
6. **One tap action** — for each identified node, count declared tap routes (`SemanticsAction.tap`
   present on the node AND on an ancestor/descendant reachable without crossing another identified
   node). More than one → fail naming the identifier and the count.

Collect ALL violations and throw one `TestFailure` listing them, rather than failing on the first —
a consumer fixing one screen should see everything wrong with it in one run.
