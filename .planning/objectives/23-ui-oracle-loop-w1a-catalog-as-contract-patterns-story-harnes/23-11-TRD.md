<objective>
Plan row **1a-11 (lint)**. Three `custom_lint` rules enforcing the mechanical half of the design rules:
`no_raw_color`, `text_style_needs_family`, `no_magic_spacing`.

Purpose: §5's last line. Patterns (23-09) and a generated token reference (23-10) describe the
intended system; these three rules are the part a machine can hold. They are also the cheapest of the
three — a raw `Color(0xFF...)` in a widget is a token that will never respond to a brand change, which
is precisely what Objective 022's white-label work is fighting.

Output: a `lints/` package with three rules and their fixtures, wired through `analysis_options.yaml`,
gated by a CI `lint` job.
</objective>

<anti_patterns>
- **Do NOT switch the rules on across the whole tree.** 517 Dart files, 184 referencing `EdenColors`
  directly and 165 referencing `EdenRadii` as static constants (measured in Objective 022's scope
  note). A tree-wide `no_raw_color` lands thousands of findings, the job gets marked non-blocking
  within a week, and the gate joins the graveyard — `edenbiz-migration-gate-is-dead`,
  `path-filtered-ci-hides-red`. Scope is declared, starts at the shell widgets, and widens by edit.
- **Do NOT put `custom_lint` in `dependencies`.** It is dev-only. Two apps pin this library.
- **Do NOT ship a rule without a negative fixture.** A rule that fires on everything is indistinguishable
  from a broken rule until someone reads the output.
- **Do NOT exempt `lib/src/tokens/` by a `// ignore:` comment.** The exemption is a path check inside
  the rule — tokens are where raw colours BELONG.
</anti_patterns>

<error_recovery>
- `custom_lint` needs its version aligned with the `analyzer` the pinned Flutter SDK ships. Local is

- `dart run custom_lint` returns non-zero when any rule fires. That is the gate. Verify it returns

## Test list

Each rule gets a positive and a negative fixture — the row's requirement, stated per rule.

**`no_raw_color` — `lints/test/rules_test.dart`**
1. Fires on `Color(0xFF112233)` in a file under an enforced path, reporting name, line and the
   suggested token.
2. Does NOT fire on `EdenColors.neutral[500]` in the same file.
3. Does NOT fire on `Color(0xFF112233)` inside `lib/src/tokens/` — that is where raw colours belong.
4. Does NOT fire on a raw colour in a file OUTSIDE the enforced paths (scope is respected).

**`text_style_needs_family`**
5. Fires on `TextStyle(fontSize: 14)` with no `fontFamily` under an enforced path.
6. Does NOT fire on `TextStyle(fontSize: 14, fontFamily: 'Inter')`.
7. Does NOT fire inside `lib/src/tokens/`.

**`no_magic_spacing`**
8. Fires on `EdgeInsets.all(13)` / `SizedBox(height: 13)` under an enforced path.
9. Does NOT fire on `EdgeInsets.all(EdenSpacing.md)`.
10. Does NOT fire inside `lib/src/tokens/`.

**The gate itself**
11. `dart run custom_lint` on the committed tree exits 0 — the gate is green the day it lands.
12. `dart run custom_lint` exits NON-zero when a deliberate violation is added under an enforced
    path. **This is the differential control**: without it, case 11 passes identically for a plugin
    that never loaded. (RED proof: add a raw colour to a shell widget, capture the non-zero exit and
    the message, revert.)
