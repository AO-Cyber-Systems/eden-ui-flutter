<objective>
Plan row **1a-08 (probe settle knobs)**. `EdenProbeScope` — the widget a consumer's `main_e2e.dart`
wraps its app in so that, under `EDEN_PROBE`, animations do not run and fonts do not arrive late.

Purpose: a probe capture is only evidence if the same app in the same state produces the same pixels.
Two things break that on web: a transition still playing when the driver screenshots, and
`google_fonts` fetching a font over the network mid-render. `timeDilation` — the usual mobile answer —
does nothing on web, so the knob has to be the `disableAnimations` path instead.

Output: `EdenProbeScope`, exported from `package:eden_ui_flutter/probe.dart`.
</objective>

<anti_patterns>
- **Do NOT use `timeDilation`.** It is a `scheduler` knob with no effect on the web renderer's
  compositing — row 1a-08 says so outright. The mechanism is `disableAnimations`.
- **Do NOT set only `MediaQueryData.disableAnimations`.** It is a hint; several Material route
  transitions consult `SemanticsBinding.instance.disableAnimations` instead. Set both.
- **Do NOT make the scope do anything when the define is absent.** It will be wired into consumer app
  shells; a scope that alters rendering in production is a worse bug than the flakiness it fixes.
- **Do NOT remove `google_fonts` from the package.** The probe path asserts bundled fonts; the normal
  path keeps runtime fonts (Objective 022 depends on it).
</anti_patterns>

<error_recovery>
- `SemanticsBinding.instance.disableAnimations` is a settable flag on some SDK versions and read-only
  on others. Local is 3.41.9, CI pins 3.47.4. If it is not settable at the declared 3.27.0 floor, set
  the `MediaQuery` flag and additionally override `AnimationController`s' duration via a
  `TickerMode`/`Duration.zero` theme (`ThemeData(pageTransitionsTheme:)` with a zero-duration
  transition builder) — and say which mechanism shipped, in the dartdoc.
- The FAB exit-animation case is a known widget-test trap in this org (memory
  `scaffold-fab-exit-animation-widget-test`): the removal takes several frames and a single `pump()`
  leaves it mid-flight. This TRD INVERTS that — under the scope, one pump must be enough. That
  inversion is the test.
</error_recovery>

## Test list

1. **Inverted FAB case.** A `Scaffold` whose `floatingActionButton` is removed by a rebuild: WITHOUT
   the scope, one `pump()` leaves the FAB still present (this is the known trap, asserted as the
   control). WITH `EdenProbeScope` under the define, one `pump()` and the FAB is gone.
2. **Route transition.** A `Navigator.push` under the scope settles in one pump; without it, it does
   not. (Same control-and-case shape as 1.)
3. **Inert without the define.** With `kEdenProbe` false, `EdenProbeScope(child:)` renders the child
   and leaves `MediaQuery.of(context).disableAnimations` false — the FAB case behaves exactly as it
   does with no scope at all. (RED proof: make the scope unconditional, watch this fail.)
4. **Child passthrough.** The scope inserts no visible layout: a child laid out inside the scope has
   the same rect as the same child laid out without it.
5. **Bundled fonts under probe.** Under the define, resolving a text style through the package's font
   path uses a bundled family and does not initiate a `google_fonts` runtime fetch; a runtime fetch
   attempt fails loudly with the family name in the message.

Then `eden_probe_scope.dart`:

```dart
/// Wraps an app so that, under --dart-define=EDEN_PROBE=true, captures are deterministic.
/// Inert when the define is absent — safe to leave wired into a production app shell.
class EdenProbeScope extends StatelessWidget {
  const EdenProbeScope({super.key, required this.child});
  final Widget child;

  @override
  Widget build(BuildContext context) {
    if (!kEdenProbe) return child;                 // const-false: tree-shaken in production
    SemanticsBinding.instance.disableAnimations = true;   // see recovery if not settable at floor
    return MediaQuery(
      data: MediaQuery.of(context).copyWith(disableAnimations: true),
      child: child,
    );
  }
}
```
