<objective>
Plan row **1a-04 (story coverage ratchet)**. A committed count that may rise and may not fall.

Purpose: without a ratchet, the story set decays — a widget gets refactored, its story is deleted to
make a test green, and the catalogue quietly stops being a contract. With a 100% target instead, the
objective drowns: this package exports 364 symbols across 517 Dart files, and Wave-1 story scope is
deliberately the shell widgets (layout, nav, buttons, inputs, data grid) plus anything an objective
touches. The ratchet is what makes a partial catalogue honest.

Output: `tool/story_coverage.dart`, the committed `.story-coverage.json`, and the test that holds the
floor.
</objective>

<anti_patterns>
- **Do NOT assert equality on the count.** `expect(withStory, equals(11))` breaks on every story added
  and teaches everyone to edit the number reflexively. The assertion is `>=`.
- **Do NOT auto-update `.story-coverage.json` from the test.** A ratchet that writes its own floor is
  not a ratchet. Raising it is a human edit in a `chore:` commit.
- **Do NOT target 100%.** 364 exports with Wave-1 scope at the shell widgets means a 100% gate would
  be permanently red and would be disabled within a week — the `edenbiz-migration-gate-is-dead` failure
  mode. A floor that holds is worth more than a target that is switched off.
- **Do NOT count a story as coverage for a widget it does not render.** Map story → widget by the
  widget type actually built, not by string similarity between the story id and the export name.
</anti_patterns>

<error_recovery>
- Counting exported widgets by parsing `lib/eden_ui.dart` is line-based and fragile to a multi-line
  `export ... show ...`. Assert the parse: if any `export` line does not match the simple
  `export 'src/...';` shape, fail with the line number rather than silently skipping it.
- If a widget is exported but its story renders it only indirectly (nav items render through
  `EdenDesktopLayout`), record it in a hand-maintained `indirect` list inside `story_coverage.dart`
  with a comment per entry — not an automatic fuzzy match.
</error_recovery>

## Test list

**Counting logic — `test/tool/story_coverage_test.dart`** (pure functions, hand-built inputs)
1. Given a hand-written list of three `export 'src/widgets/eden_x.dart';` lines, `exportedWidgets`
   returns those three names.
2. An `export` line that does not match the expected shape raises a named error carrying the line
   number, rather than being skipped.
3. Given a hand-built registry of two stories rendering `EdenButton` and `EdenCard`, `widgetsWithStory`
   returns exactly those two.
4. A widget listed in the hand-maintained `indirect` list counts as covered, and the reason string is
   carried through to the report.

**The ratchet — `test/stories/coverage_test.dart`**
5. Current `with_story` count >= the committed `.story-coverage.json` `with_story` → passes.
6. **RED case:** with the committed floor raised by one above the real count, the test fails, and the
   message lists the exported widgets that have no story plus the sentence "the floor is raised in a
   `chore:` commit, never by this test". (Prove RED by editing the JSON, capturing the output,
   reverting.)
7. A rise is silent: with the real count ABOVE the committed floor, the test passes and does NOT
   rewrite `.story-coverage.json` — `git status --short` is clean after the run.
