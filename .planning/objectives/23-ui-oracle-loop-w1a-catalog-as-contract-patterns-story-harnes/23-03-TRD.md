<objective>
Plan row **1a-03 (story harness)**. Two generators and one harness: discover co-located
`<widget>.stories.dart` files and generate their registration (drift fails CI); then, for every
registered story, generate a `flutter test` asserting a light golden, a dark golden and
`expectUiSane`.

Purpose: §6.1-6.2. A story that is not tested is a demo. This TRD is what turns the `EdenStory`
registry from a dev-app catalogue into a contract — the thing 23-04's ratchet counts, 23-05's nav
stories feed, and 23-06's shell reshaping is proved harmless against.

Output: `tool/gen_stories.dart`, `tool/gen_story_tests.dart`, the harness helper, the drift and
freshness tests, and the Linux-only golden job in CI.
</objective>

<anti_patterns>
- **Do NOT regenerate `register_all.dart` wholesale.** It holds 49 hand-written registrations and a
  test asserting that exact count. Generate a SEPARATE `register_stories.g.dart` and call it from
  `registerAllStories()`. Overwriting the hand-written file is a silent deletion of the dev app.
- **Do NOT bless goldens on this workstation.** Local Flutter here is 3.41.9; CI pins 3.47.4. Different
  engines rasterise text differently. eden-ui-flutter#32 is exactly this failure: `chat_screen_test`'s
  390pt overflow assertion passes CI and fails locally by 8.5px. Goldens are generated in the CI
  container (Linux) and nowhere else.
- **Do NOT make the generator parse Dart with regex over whole files if a structural marker will do.**
  Discover by file path (`lib/**/<name>.stories.dart`) and require each file to export a top-level
  `List<EdenStory> <name>Stories` — a named contract the generator can assert, and a clear error when
  a file does not honour it.
- **Do NOT `.gitignore` the generated files.** Drift detection compares the committed bytes to a fresh
  generation. An ignored generated file cannot drift because it is never in the tree.
</anti_patterns>

<error_recovery>
- `matchesGoldenFile` on a missing golden fails with "Golden file ... does not exist". In the CI job,
  the first run is `flutter test --update-goldens` behind an explicit workflow input; the normal run
  never writes.
- If `flutter test test/stories/_generated/` is slow, it is because every story pumps twice (light +
  dark). That is the intended cost; do not "optimise" it by dropping the dark golden.
- Generator output must be byte-stable: sort discovered files by path, sort stories by
  `(component, name)` matching `StoryRegistry.all()`, emit a fixed header, and end the file with a
  newline. An unstable generator makes the drift test flaky, which is worse than no drift test.
</error_recovery>

## Test list

**`gen_stories` — `test/tool/gen_stories_test.dart`** (pure function over hand-built inputs)
1. Given two hand-written story-file descriptors, the emitted registration source lists them sorted by
   path, with one import and one `for (final s in <name>Stories) registry.register(s);` each.
2. Generating twice over the same input yields byte-identical output (stability).
3. Given zero story files, output is a valid Dart file with an empty `registerGeneratedStories()` —
   compiles, registers nothing.
4. A discovered `.stories.dart` that does not export the expected `List<EdenStory> <name>Stories`
   symbol produces a named error mentioning the file path.

**Drift — `test/stories/registry_drift_test.dart`**
5. Regenerating over the current tree produces bytes identical to the committed
   `register_stories.g.dart`; the failure message names the file and prints
   `flutter test tool/gen_stories.dart` as the remedy. (RED proof: hand-edit one character of the
   committed file, watch it fail, revert.)

**`gen_story_tests` — `test/tool/gen_story_tests_test.dart`**
6. For a hand-built two-story registry, the emitted test source contains one `testWidgets` per story
   naming its id, and each body calls the harness for light AND dark.
7. Emitted output is byte-stable across two runs.

**Freshness — `test/stories/generated_freshness_test.dart`**
8. A story present in `StoryRegistry.all()` with no corresponding generated test file fails, naming
   the story id. (RED proof: delete one generated file, watch it fail, regenerate.)

**Harness behaviour — asserted through the generated tests once 23-05 lands**
9. Golden expectations `skip` when `!Platform.isLinux`, and the skip reason string names
   eden-ui-flutter#32. `expectUiSane` does NOT skip — it runs on every platform.
10. A golden mismatch message contains the story id. (RED proof in CI: corrupt one committed golden
    byte on a scratch branch, read the CI log, revert.)
