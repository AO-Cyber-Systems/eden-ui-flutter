<objective>
Plan row **1a-10 (generated DESIGN.md)**. The token block of `DESIGN.md` is generated from
`lib/src/tokens/*.dart` and CI-diffed; the prose around it stays hand-written.

Purpose: §5's table moves the token documentation from "a markdown file someone updates" to "a
projection of the Dart". This repo has seven token files and 184 files referencing `EdenColors`
directly — a hand-maintained token table in a design doc is stale the week it is written, and a stale
token table is how a designer and an implementer end up building different things from the same page.

Output: `tool/gen_design_md.dart`, a `DESIGN.md` with generated token tables between markers, and the
freshness test.
</objective>

<anti_patterns>
- **Do NOT regenerate the whole file.** `DESIGN.md`'s prose is hand-written and is the part humans
  read. Generation is bounded by markers; the generator refuses to run if a marker is missing rather
  than rewriting from scratch.
- **Do NOT let the freshness test write the file.** A test that regenerates-and-passes is not a gate.
  It compares and fails.
- **Do NOT parse Dart with a general-purpose regex over whole files.** Extract by a declared, asserted
  shape (`static const Color <name> = Color(0x...)`) and FAIL LOUDLY on a declaration in the token
  files that does not match — a silently skipped token is exactly the staleness this TRD removes.
- **Do NOT add an analyzer package dependency** to parse Dart. String extraction with a strict
  asserted shape is sufficient for token files and adds nothing to `pubspec.yaml`.
</anti_patterns>

<error_recovery>
- `springs.dart` and `shadows.dart` hold structured values, not scalars. Row 1a-10 scopes generation to
  colour, type scale, spacing and radii — generate those four, and have the tool emit a short
  "not generated: shadows, springs (structured values)" line inside the block so the omission is
  visible in the rendered doc rather than silent.
- If a token file declares values inside a class with a non-`static const` shape, the extractor's
  strict-shape assertion will fail on it. That failure is correct: widen the accepted shape
  deliberately, in the tool, with a comment — never by loosening the regex to `.*`.
</error_recovery>

## Test list

**Extraction and rendering — `test/tool/gen_design_md_test.dart`** (pure functions, hand-built input)
1. Given three hand-written `static const Color` declaration lines, the extractor returns those three
   names and hex values in declaration order.
2. A declaration in a token file that does not match the accepted shape raises a named error carrying
   the file and line, rather than being skipped.
3. Rendering the same extracted tokens twice produces byte-identical markdown (stability).
4. The rendered block is bounded by the exact BEGIN/END markers and contains nothing outside them.

**Freshness — `test/design/design_md_fresh_test.dart`**
5. Regenerating from the current `lib/src/tokens/` produces bytes identical to the block committed in
   `DESIGN.md`. Failure message names `DESIGN.md` and prints
   `flutter test tool/gen_design_md.dart` as the remedy.
   **RED proof:** hand-edit one hex value inside the generated block, watch it fail, revert.
6. **A token added in Dart with no regeneration fails.** Add a `static const Color` to a token file,
   run the test, watch it fail naming the new token, remove it. This is the case the row names and it
   is a DIFFERENT failure from case 5 — one catches an edited doc, the other catches an edited Dart.
7. The prose outside the markers is preserved: regenerating after editing a prose paragraph leaves
   that paragraph byte-identical.
8. The test does not write: `git status --short DESIGN.md` is clean after a run.
