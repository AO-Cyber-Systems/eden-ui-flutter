`window.__edenProbe.{find,tree,settled,state}`, compiled in only under `EDEN_PROBE`, with a CI job

<anti_patterns>
- **Do NOT use the VM service.** §7.1 is explicit and the reason is empirical: release builds have no
  VM service, `flutter run`'s DWDS wedges (memory `flutter-web-browser-proof-use-release-build`), and
  dart-lang/ai#356 breaks the DTD path for web.
- **Do NOT gate on `kIsWeb` at runtime.** A runtime branch keeps `dart:js_interop` code in every
  bundle. The gate is a CONDITIONAL IMPORT plus `const bool.fromEnvironment`, which is what lets the
  tree shaker remove it — and what makes the guard script's grep meaningful.
- **Do NOT test the bridge by asserting the JS object exists.** Test the Dart entry the JS calls
  (`EdenProbeApi`) with widget tests over hand-built surfaces. A test that only proves
  `window.__edenProbe != null` proves nothing about the rects it returns.
- **Do NOT ship the guard as a code review note.** "The define is off so it is tree-shaken" is a claim.
  `grep -c __edenProbe build/web/main.dart.js` on a real release build is evidence. See
  `devflow-ui-eval-stale-engine` and `edenbiz-migration-gate-is-dead` — a gate that cannot fail is the
  house speciality.
- **Do NOT add a new package dependency.** `dart:js_interop` is in the SDK; `package:web` is already a
  direct dependency.
</anti_patterns>

<error_recovery>
- `dart:js_interop`'s `@JS()` + `extension type` syntax requires Dart >= 3.3; the package floor is 3.6,
  so it is available — but the LOCAL toolchain is Flutter 3.41.9 while CI pins 3.47.4. If an interop
  API differs, code to the floor and confirm on CI.
- `flutter test` runs on the VM, not the browser: `probe_bridge_web.dart` cannot be executed by a
  widget test. That is expected and is exactly why the logic lives in `probe_api.dart` (VM-testable)

- If `grep -c` returns 0 matches it exits non-zero; use `grep -c ... || true` and compare the number,
  or the guard script will fail for the RIGHT answer.

Then `probe_api.dart`, pure Dart over the binding — no JS types anywhere in this file:

```dart
class EdenProbeHit {
  final String id;              // stable within a call: 'hit-0', 'hit-1', ...
  final Rect rect;              // GLOBAL rect
  final String? identifier;
  final List<String> actions;   // declared semantics actions, as strings
}

abstract final class EdenProbeApi {
  static List<EdenProbeHit> find({String? key, String? text, String? type, String? identifier});
  static Map<String, Object?> tree();
  static bool settled();
  static Map<String, Object?> state();
}
```

Approach:
1. Root at `WidgetsBinding.instance.rootElement`; walk with `visitChildElements`.
2. `key:` matches `ValueKey`/`Key` whose `toString()` carries the string. `type:` matches
   `element.widget.runtimeType.toString()`. `text:` matches `Text.data` AND `RichText`'s
   `InlineSpan.toPlainText()`. `identifier:` resolves through the semantics tree.
3. `rect` = `(element.renderObject as RenderBox).localToGlobal(Offset.zero) & size` — the RENDER BOX's
   own rect, never an ancestor's.
4. `tree()` = `{route: <current route name>, nodes: [ {identifier, rect, actions} ... ]}` over
   identified semantics nodes.
5. `settled()` = `!SchedulerBinding.instance.hasScheduledFrame &&
   SchedulerBinding.instance.transientCallbackCount == 0 && EdenProbe.inFlightRequests == 0`, where
   `inFlightRequests` is a public int a consumer's HTTP layer may increment (defaults 0 — §7.1's
   "no HTTP requests in flight", made opt-in rather than guessed).
6. `state()` = route name, `Theme.of(...).brightness.name`, viewport `w/h` from
   `PlatformDispatcher.implicitView`, and `SemanticsBinding.instance.semanticsEnabled`.

Return plain Dart maps/lists — JSON-shaped, no JS types — so the same values serialise for the shim
and are readable in a widget test.

```sh
#!/usr/bin/env bash
# Proves the probe bridge is tree-shaken out of a production web bundle.
# Usage: tool/probe_guard.sh <app-dir>
set -euo pipefail
APP_DIR="${1:-example/probe_smoke}"
cd "$APP_DIR"

flutter build web --release
PROD_HITS=$(grep -c __edenProbe build/web/main.dart.js || true)

flutter build web --release --dart-define=EDEN_PROBE=true
PROBE_HITS=$(grep -c __edenProbe build/web/main.dart.js || true)

echo "production bundle: $PROD_HITS   probe bundle: $PROBE_HITS"
[ "$PROD_HITS" -eq 0 ] || { echo "FAIL: __edenProbe found in a production bundle"; exit 1; }
[ "$PROBE_HITS" -gt 0 ] || { echo "FAIL: __edenProbe absent even WITH the define — the guard is inert"; exit 1; }
```
