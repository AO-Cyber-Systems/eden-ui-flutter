<objective>
Plan row **1a-01 (fixtures)**. Build the two primitives every later TRD in this objective stands on:
a `wrap()` pump helper with theme / width / theme-mode knobs, and a `SemanticsGeometry` helper that
resolves a semantics node's true global rect.

Purpose: `expectUiSane` (23-02), the story harness (23-03) and the probe bridge's `tree()` (23-07)
all need to answer "where is this control, really?". Getting that answer wrong is the single failure
this repo has already been burned by — see the memory note `flutter-web-semantics-node-is-the-click-target`:
the DOM semantics node receives the click, not the widget, and a nested `Semantics` without
`container: true` silently reports its PARENT's rect. Every geometry assertion built on a wrong rect
is a green test that proves nothing.

Output: `test_support/ui_oracle/` with `wrap.dart`, `semantics_geometry.dart` and hand-built
fixtures, plus the tests under `test/ui_oracle/`.
</objective>

<anti_patterns>
- **Do NOT read the rect off the RenderObject.** `tester.getRect(find.byX)` answers a different
  question (the widget's box) than "what rect does the accessibility tree publish for this node?".
  The whole point of this helper is that those two can disagree, and the accessibility one is what a
  click lands on.
- **Do NOT compose transforms from the root downward.** Walk from the node itself up through
  `SemanticsNode.transform`, applying each ancestor transform in turn. A root-down walk hides the
  container:true bug because the parent's rect is what you end up with either way.
- **Do NOT generate fixture widget trees from a list of names.** Every fixture in `_fixtures/` is
  hand-written, one file, readable top to bottom. (Constraint `no_llm_test_data`.)
- **Do NOT put `test_support/` under `lib/`.** It would ship to two consuming apps on the next pin
  bump. `lib/testing/` (23-02) is the only thing from this objective that is deliberately public.
</anti_patterns>

<error_recovery>
- `SemanticsNode` traversal needs the semantics tree to exist: `final handle = tester.ensureSemantics();`
  before the walk and `handle.dispose()` after, or `tester.getSemantics` throws "Semantics are not
  enabled".
- If `visitChildren` returns nodes in an order that changes between runs, sort by
  `(rect.top, rect.left, identifier)` before asserting — never assert on traversal order itself.
- Local Flutter here is **3.41.9**; CI pins **3.47.4**. If a `SemanticsNode` API in this TRD differs
  between them, code to the declared floor (`>=3.27.0`) and confirm on CI, not locally.
</error_recovery>

Implement `semantics_geometry.dart` exposing:

```
class SemanticsGeometryNode {
  final int id;
  final String? identifier;
  final Rect globalRect;
  final Set<SemanticsAction> actions;
}

/// Every node in the current semantics tree that carries a non-empty identifier.
List<SemanticsGeometryNode> identifiedNodes(WidgetTester tester);

/// The global rect of the node carrying [identifier]; throws a named error if absent.
Rect globalRectOf(WidgetTester tester, String identifier);

/// True when two rects share any area.
bool rectsOverlap(Rect a, Rect b);
```

Approach for `globalRect` — this is the load-bearing part:
1. `final handle = tester.ensureSemantics();` at entry; `addTearDown(handle.dispose)`.
2. Start at `tester.binding.pipelineOwner.semanticsOwner!.rootSemanticsNode`.
3. Walk children with `visitChildren`. For each node, accumulate the transform by starting from
   `node.transform` and multiplying by each ancestor's transform on the way UP — i.e. build the
   ancestor chain first, then compose root→node, applying `node.rect` last.
4. `globalRect = MatrixUtils.transformRect(composed, node.rect)`.

# CRITICAL: compose FROM THE NODE ITSELF. A root-down shortcut that stops at the nearest
#           container node returns the parent rect and silently passes case 5 for the wrong reason.
# GOTCHA: SemanticsNode.transform is null when identity — treat null as Matrix4.identity()
# GOTCHA: memory `flutter-web-semantics-node-is-the-click-target` — the node is the click target on
#         web; this helper is the only thing in the repo that can see that.

Write cases 5, 6, 7 one at a time, RED first each time. Case 7 asserts the BUGGY value (nested node
reports the 200x200 parent rect) with a comment explaining that 23-02 turns this into a hard failure
