```yaml

        run: |
          VERSION=$(grep '^version:' pubspec.yaml | sed 's/version: //')

      - name: Create release tag
        run: git tag "v${{ steps.version.outputs.version }}"
```
</codebase_examples>

<anti_patterns>
- **Do NOT tag by hand from a workstation.** `release.yml` cuts the tag from `pubspec.yaml` on merge to
  main. Bumping the version IS the release action.
- **Do NOT bury the `selectableBody` default flip in an "Added" list.** It is the one non-additive
  change in the objective and it gets its own `### Changed` entry with the issue numbers.
- **Do NOT claim gates green from branch runs.** Two individually-correct branches compose into a
  broken tree with no git conflict (memory `rerun-composed-gates-after-every-merge`). The gate run in
  task 3 is on the MERGED tree.
- **Do NOT merge without asking.** Stage C of the merge runbook: ask before merging unless durably
  authorised for this specific run.
</anti_patterns>

<error_recovery>
- `release.yml` has historically failed on every merge to main (its own comment: "#25, #26, #24, #27")
  until `--no-fatal-infos` was aligned with ci.yml. If the `Test` job fails, no tag is cut and the
  release silently does not happen — check the workflow run, do not assume the tag exists.
- If `v2.2.0` already exists for some reason, `release.yml` skips silently. Verify the tag's SHA is the
  merge commit, not an older one.
</error_recovery>
