<objective>
Plan row **1a-06 (shell API reshaping)**, and the fold-in of **issue #33**.

Two things, one TRD, because they are one edit to the same constructor and one shared back-compat
proof:

1. **Composition over flags.** `EdenNavItem` has grown a flag per consumer need (`expandable`,
   `caption`, `isDivider`, `badge`) and each one was a library change plus a pin bump in two apps. Add
   `itemBuilder` / `sectionBuilder` slots so the next consumer need is a consumer change. Flags stay
   for behaviour that must be uniform across apps, and they render THROUGH the default builder.

2. **Issue #33 — a real production bug this repo owns.** `eden_desktop_layout.dart:58` defaults
   `selectableBody = true`, wrapping `body` in a `SelectionArea`. When `body` contains a Navigator —
   every go_router shell app — deep-linking into a nested route asserts in
   `_compareScreenOrder → getTransformTo` through a never-laid-out covered page (flutter#151536, fix
   #184900 unmerged). Measured in aodex#611: six routing tests red; aodex took the
   `selectableBody: false` opt-out. eden-biz is one nested route away from the same failure. Flip the
   default to opt-in, document why, add the regression test.

Purpose: this library is pinned by two apps. Both halves are constructor-surface changes, so they ship
together and are proved together by one back-compat spine.

Output: builder typedefs and slots on both layouts, the opt-in flip, and the tests that pin all of it.
</objective>

<anti_patterns>
- **Do NOT branch.** `itemBuilder != null ? consumerWidget : _NavTile(...)` creates two code paths that
  drift; the identifier wrapper and the selection semantics end up on one of them only. Define a
  DEFAULT builder that returns `_NavTile(...)` and call `(widget.itemBuilder ?? _defaultItemBuilder)`
  at the single existing call site.
- **Do NOT let the builder own the semantics identifier.** `Semantics(identifier: ...)` wraps the
  builder's RESULT. A consumer who forgets it must still be findable by `eden-nav-<id>` — aodex and
  eden-biz E2E flows key off exactly that string.
- **Do NOT "fix" the five existing layout tests.** If they need editing, the change is not additive and
  the reshaping is wrong. They are the proof, not an obstacle.
- **Do NOT leave the flutter#151536 reason in a commit message only.** The next person to see an
  unselectable body will flip the default back. The reason goes in the dartdoc, beside the parameter.
- **Do NOT bless goldens locally** to make the "no visual change" claim. The claim is CI-verified.
</anti_patterns>
