<anti_patterns>
- **Do NOT compute deposit amount automatically.** Suggest default (counted - starting float) but let user override; banks deposit different amounts depending on safe holding rules.
- **Do NOT block confirm when variance is small (≤ 5.00 default).** Small variance is expected at end-of-day; only manager-gate when over threshold.
- **Do NOT mutate input session.** Always emit a new session via copyWith.
- **Do NOT log negative count values.** Use FilteringTextInputFormatter to bound count >= 0.
- **Do NOT auto-submit on Continue.** onSubmit fires only on the explicit 'Confirm close' tap in review.
- **Do NOT use property-based testing** (`no_property_based_default`).
- **Do NOT emit Gherkin** (`no_gherkin_layer`).
- **Do NOT accept LLM-generated fixtures** (`no_llm_test_data`).
</anti_patterns>

<gotchas>
- **Variance threshold is locked at 5.00.** Configurable param? Defer — locked. Override message gates manager approval.
- **Counted total computation efficiency.** Sum the denomination counts once per setState; not in build(). Use a computed getter or a state field updated in onChanged.
- **Deposit cashAmount default-fill.** When entering deposit step, prefill controller with `max(0, countedClosingBalance - startingFloat)` (don't go negative on a short close).
- **Pay-out negative amounts.** When the user adds a cash drop, the amount is stored NEGATIVE (debit from drawer). UI shows in red. The user enters a positive number in the form; the storage layer negates if reason categorizes as a debit. Implementation: introduce a `EdenCashTransactionKind` enum (cashDrop / petty / refund / payIn) and derive sign from kind. Locked: amount is stored negative for debits.
- **eod_screen.dart bootstrap.** Skeleton matches 015-04's staff_screen.dart shape. The anchor `// TRD 015-07 appends here ↓ EdenShiftClose + EdenXZReport` sits BELOW the CashDrawerClose section.
