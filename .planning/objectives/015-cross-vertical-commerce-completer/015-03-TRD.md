<objective>
Ship `EdenGiftCardManager` — the unified gift-card primitive serving 5 modes (issue / redeem / lookup / balance / ledger) that 2 verticals need: salon (SALON-019 sell + SALON-020 redeem; BLOCKED today) and retail (UC-08 sale + UC-09 redeem + UC-28 balance lookup; all BLOCKED today — Square / Shopify / Clover / Lightspeed all list gift cards as marketed pillars).

Per `USE_CASES_SALON_2026-05-17.md` §5 Recommendation #7 + `USE_CASES_RETAIL_2026-05-17.md` §1 UC-08/09/28. Salon spec calls for 3 separate widgets (`EdenGiftCardTile` + `EdenGiftCardSaleForm` + `EdenGiftCardRedeemSheet`); we collapse into ONE manager with a mode param — same composability, less surface area. The 5-mode design also covers retail's lookup + ledger requirements.

Wave 2 — depends on 015-01 (which adds the Wave 1 section header to `lib/eden_ui.dart` and the first commerce_screen 015 anchor). This TRD adds the Wave 2 section header to `lib/eden_ui.dart`.

Outside-in test approach: rendering each mode → utility (masking) → state emission (issue/redeem drafts) → callback integration (onLookup) → responsive → a11y.

One test at a time per Habit 3.
</objective>

<anti_patterns>
- **Do NOT show the full gift-card code anywhere in the UI.** Always mask to last-4 — even in the balance body and the ledger header. PCI-adjacent posture (per obj 011-08 EdenSecretField.classified discipline).
- **Do NOT compute the ledger inside the widget.** Consumer-provided list only — library renders.
- **Do NOT auto-toggle modes.** The mode is consumer-controlled (parent state). Don't add internal mode-switching.
- **Do NOT validate that amountToApply > 0.** $0 redeem is a valid edge case (audit traversal).
- **Do NOT include a Submit button.** Real-time onDraftChanged emits; consumer renders the submit affordance.
- **Do NOT use property-based testing** (constraint `no_property_based_default`).
- **Do NOT emit .feature files** (constraint `no_gherkin_layer`).
- **Do NOT accept LLM-generated fixtures** (constraint `no_llm_test_data`).
</anti_patterns>

<gotchas>
- **EdenBarcodeScanner navigation pattern.** Push a full-screen route; on result callback, `Navigator.pop(context, code)` returns the value to the awaiting `await Navigator.push<String>()`. Avoid stacking a second route for code-confirmation; the scanner's callback IS the confirmation.
- **REDEEM mode amountToApply prefill at init.** Use `initState()` to set the controller text — using `initialValue` on TextFormField breaks the controller-update flow for the auto-cap edit cases.
- **LOOKUP mode result rendering.** When onLookup completes with non-null record, set local state `_lookedUpRecord` and re-render an inline BALANCE-mode block below. Don't navigate or push a sheet.
- **Mode change while widget mounted.** Use `didUpdateWidget` to detect mode changes: clear local state (controllers, _lookedUpRecord) when the mode prop changes.
- **commerce_screen.dart APPEND.** Add anchor `// TRD 015-03 appends here ↓ Objective 015 — Gift card manager` BELOW the 015-01 anchor. Both 015-03 and 015-08 will eventually append to this file; the orchestrator may serialize them. Each TRD checks for its OWN anchor before inserting.

</gotchas>
