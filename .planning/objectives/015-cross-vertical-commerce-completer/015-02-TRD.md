<objective>
Ship `EdenCheckoutSheet` — the **salon-flavored bottom-sheet composite** that wraps obj-012 + 015-01 + 015-08 primitives into a 4-step chair-side checkout flow. Wave 3 capstone for the salon SKU.

Per `USE_CASES_SALON_2026-05-17.md` §5 Recommendation #5: "**`EdenCheckoutSheet`** + **`EdenSelfCheckoutPayPage` (companion Templ surface)** — Mobile-friendly bottom-sheet wrapping `EdenLineItemEditor` + `EdenTippingSelector` + `EdenPaymentEntry` + `EdenSplitTender` + `EdenReceiptPreview` into the chair-side checkout pattern. Closes SALON-016, SALON-017."

Wave 3 — depends on 015-01 (Tipping) for the tip step, 015-08 (Promotion) for the optional promotion step. Composes obj-012 `EdenLineItemEditor` + `EdenSplitTender` + obj-014 `EdenReceiptPreview` (consumer wires receipt preview in review step optionally).

The widget itself is the SHEET BODY. Consumers wrap in `showModalBottomSheet(context: ..., isScrollControlled: true, builder: (_) => EdenCheckoutSheet(...))` for actual bottom-sheet rendering. Library is transport-agnostic — does not call `showModalBottomSheet` internally so consumers control sheet presentation.

Outside-in test approach: render at each step → step navigation (Continue / Back) → emission per step → step blocking (payment incomplete) → final Complete → responsive → a11y.

One test at a time per Habit 3.
</objective>

**Outside-in rendering — step-by-step:**
1. Renders EdenStepper with 4 steps; current=lineItems given initialDraft.currentStep=lineItems
2. Step 1 (lineItems): EdenLineItemEditor visible; bound to draft.lineItems
3. Step 2 (tip): EdenTippingSelector visible; bound to draft.tip
4. Step 3 (payment): EdenSplitTender visible; allowedPaymentMethods passed through
5. Step 4 (review): EdenDescriptionList visible with Subtotal / Tip / Total rows; 'Complete' button present
6. 'Continue' button present on lineItems/tip/payment; absent on review
7. 'Back' button absent on lineItems; present on tip/payment/review

**Navigation:**
8. Tap 'Continue' on lineItems advances draft.currentStep to tip; emits onDraftChanged
9. Tap 'Continue' on tip advances to payment; emits
10. Tap 'Continue' on payment advances to review when balance is met
11. Tap 'Back' on tip returns to lineItems; emits

**Emission per step:**
12. Step lineItems: editing line-item quantity propagates to draft.lineItems via onDraftChanged
13. Step tip: tapping a preset chip propagates to draft.tip
14. Step payment: adding a payment row propagates to draft.payments
15. Optional promotion: applying a promo updates draft.appliedPromotion AND review total

**Blocking + computed values:**
16. Step payment: when payments.sum < total - $0.01, 'Continue' disabled AND EdenBanner.warning 'Remaining: $X.XX' visible
17. Step review: total computed = subtotal - promotion.discountAmount + tip.tipAmount + taxAmount (within $0.01)
18. Step review: 'Complete' tap calls onComplete with the final draft (currentStep=review)

**Responsive + a11y:**
19. iPhone-narrow (390pt): sheet body renders; EdenStepper collapses to compact dots
20. Sheet content is Scrollable inside each step (test by adding many line items + checking ScrollView present)
21. Semantics: step transitions announce via liveRegion; 'Complete' button has 'Complete checkout, total $X.XX' label

<anti_patterns>
- **Do NOT call `showModalBottomSheet` from inside the widget.** The widget IS the sheet body; consumer controls sheet presentation.
- **Do NOT auto-advance steps.** User explicitly taps Continue.
- **Do NOT mutate draft within child callbacks before emit.** Every emit constructs a fresh draft via copyWith and calls onDraftChanged.
- **Do NOT block 'Complete'.** If subtotal == 0, Complete still works (gift-card-only or full-discount checkout).
- **Do NOT bind tax computation to a specific engine.** taxRate is a consumer-provided double; multiplication only.
- **Do NOT use property-based testing** (`no_property_based_default`).
- **Do NOT emit Gherkin** (`no_gherkin_layer`).
- **Do NOT accept LLM-generated test data** (`no_llm_test_data`).
</anti_patterns>

<gotchas>
- **Computed properties on EdenCheckoutDraft.** Implement as getters (`double get subtotal => lineItems.fold(0.0, ...)`); not stored fields. Always fresh.
- **Promotion discount in subtotal computation.** total = subtotal - (appliedPromotion?.discountAmount ?? 0) + tip.tipAmount + taxAmount. The tax math may apply pre-discount or post-discount depending on jurisdiction — for v1, locked decision: tax applies AFTER discount (post-discount subtotal). Document this in the value class.
- **EdenStepper compact-at-narrow.** Use LayoutBuilder to switch between full label-on-each-step and compact dot variant. Mirror the responsive density pattern from obj 003-04 / obj 014-04.
- **Sheet height clamp.** Don't hardcode height; let DraggableScrollableSheet (consumer-supplied) handle it. Inside the widget, use `ConstrainedBox(constraints: BoxConstraints.expand(), child: Column(...))` so the inner content fills available height.
- **commerce_screen.dart APPEND.** Add anchor `// TRD 015-02 appends here ↓` BELOW the 015-08 anchor. The demo Section opens an actual modal bottom sheet via consumer-side `showModalBottomSheet` call inside the demo code.
- **lib/eden_ui.dart Wave 3 section header.** This is the FIRST Wave 3 TRD — add the new section header `// ─────────── Objective 015 — Cross-vertical commerce completer Wave 3 ───────────` AFTER the Wave 2 block. 015-06/015-07 follow.
</gotchas>
