<objective>
Ship `EdenVitalsRow` — a clinical-density vital signs strip widget for medical Patient Chart screens. Per `VERTICAL_WIREFRAMES_VALIDATION_2026-05-17.md` §3.1 M1 + M2: the primary medical chart screen needs a 6-tile BP/HR/Temp/SpO2/RR/Weight strip with trend arrows and reference-range coloring. Six `EdenStatCard`s in a Row don't fit clinically — too tall, no trend, no range coloring (validation doc §3.1.M1 gap inventory).

This is the first TRD in objective 013 (Wave 1, parallel with 013-02..013-05). **This TRD bootstraps the objective**: creates `medical_screen.dart`, adds the home-screen nav tile, and seeds the Wave 1 export section in `eden_ui.dart`. TRDs 013-02 through 013-07 APPEND to medical_screen.dart and the same export section — they do NOT create those files.

Outside-in test approach:
1. Static rendering tests first (renders 6 tiles for sample patient, each tile shows label + value + unit).
2. Reference-range coloring tests (in-range = success token, caution = warning token, out-of-range critical = danger token, no-data = neutral).
3. BP composite rendering ('128/82' from systolic/diastolic).
4. Trend arrow tests (up/down/flat selection from `priorValue` vs `currentValue`).
5. Empty / partial state tests (missing SpO2 → tile renders '—').
6. iPhone-narrow ≥390pt responsive test (4 tiles fit + horizontal scroll on overflow).
7. **HIPAA isolation test** (per global TDD Playbook habit 6): list of vitals from patient A passed alongside patient B's chart context → assertion fires in debug; in release mode test that only matching patientId vitals render.
</objective>

**Design (locked):**

Value class (FHIR-shape, library-owned — NOT `fhir_dart`):
```dart
enum EdenVitalKind { bloodPressure, heartRate, temperature, spo2, respiratoryRate, weight, bmi }

@immutable
class EdenVitalSign {
  const EdenVitalSign({
    required this.patientId,        // HIPAA isolation key (opaque string; library doesn't decode)
    required this.kind,
    required this.unit,             // 'mmHg' | 'bpm' | '°F' | '%' | 'breaths/min' | 'kg' | 'kg/m²'
    this.value,                     // double — null for BP (use systolic/diastolic)
    this.systolic,                  // BP only
    this.diastolic,                 // BP only
    this.priorValue,                // for trend arrow computation
    this.referenceMin,              // for range coloring; null = no range
    this.referenceMax,
    this.criticalMin,               // critical-low threshold (warning > danger transition)
    this.criticalMax,
    this.recordedAt,                // DateTime; rendered as 'as of' caption optional
  });
  final String patientId;
  final EdenVitalKind kind;
  final String unit;
  final double? value;
  final double? systolic;
  final double? diastolic;
  final double? priorValue;
  final double? referenceMin;
  final double? referenceMax;
  final double? criticalMin;
  final double? criticalMax;
  final DateTime? recordedAt;
}
```

Widget API:
```dart
EdenVitalsRow({
  required List<EdenVitalSign> vitals,   // 0..7 tiles; renders in given order
  String? patientId,                      // optional explicit assert key; if null, uses vitals.first.patientId
  bool showTimestamps = false,            // 'as of' caption on/off
  EdgeInsetsGeometry? padding,
})
```

**Coloring logic (uses `EdenStatusPalette` from obj 009):**
- If `value` is null → neutral surface (no data).
- If `referenceMin == null && referenceMax == null` → neutral surface (no range set).
- If `criticalMin != null && value <= criticalMin` OR `criticalMax != null && value >= criticalMax` → danger (red).
- Else if `referenceMin != null && value < referenceMin` OR `referenceMax != null && value > referenceMax` → warning (amber).
- Else → success (green).
- For BP: critical when `systolic >= 180 || diastolic >= 120` OR `systolic < 90 || diastolic < 60`; warning when above stage-1 thresholds (`systolic >= 140 || diastolic >= 90`); else success. (Encoded as defaults; consumer can override via criticalMin/Max on BP tile.)

**Trend arrow:**
- `priorValue == null` → no arrow.
- `value > priorValue * 1.05` → up arrow (Icons.arrow_upward).
- `value < priorValue * 0.95` → down arrow (Icons.arrow_downward).
- Else → flat arrow (Icons.remove).
- Arrow color matches reference-range tint (NOT a separate semantic — keeps tiles scannable).
- BP trend uses `systolic` for comparison.

**Tile layout (composes Material widgets — no new sub-widgets):**
```
┌────────────────┐
│ BP             │  10pt label
│ 128/82         │  24pt value (monospace)
│ mmHg           │  10pt unit
│ ↑ 12m ago      │  10pt trend + timestamp (if showTimestamps)
└────────────────┘
```
Tile is a `Container` with `EdenStatusPalette.{danger|warning|success|neutral}.surface` background + 1pt border in `.outline` token (medical wants borders, not shadows per UX research §1.4). `BorderRadius.circular(EdenRadii.sm)` (4pt — sharp corners for institutional feel).

**Responsive (iPhone-narrow ≥390pt):**
- Default = `SingleChildScrollView(scrollDirection: Axis.horizontal)` wrapping the `Row` of tiles. Always scrollable horizontally; on wide screens (≥840pt) all tiles fit naturally and scroll is no-op.
- Minimum tile width 96pt (4 tiles + gaps fit on 390pt baseline). Maximum tile width 120pt (so 6+ tiles don't stretch absurdly on Expanded tier).

**Theme integration:**
- `EdenStatusPalette` accessed via `Theme.of(context).extension<EdenStatusPalette>()`. If null (legacy `EdenTheme.light()` without obj 009 extension) → fall back to `EdenColors.danger/.warning/.success` hardcoded. (Graceful degrade.)

**HIPAA isolation assertion:**
- Constructor body: `assert(vitals.isEmpty || vitals.every((v) => v.patientId == (patientId ?? vitals.first.patientId)), 'EdenVitalsRow: vitals must share same patientId; received mixed PHI');`
- In release mode (asserts disabled), widget MUST filter to only vitals matching the resolved patientId (defensive). Test asserts both behaviors.

**Generic / FHIR-shape rationale:**
- The widget knows nothing about Epic or Cerner. Consumer maps Epic FHIR R4 `Observation` resources → `EdenVitalSign` value class at the integration boundary in `eden-biz-flutter`.
- BP's split into systolic/diastolic-vs-single-value matches FHIR `Observation.component` shape for BP panels — feels natural to medical devs.
</context>

<gotchas>
- **EdenStatusPalette extension access:** `Theme.of(context).extension<EdenStatusPalette>()` returns nullable. Guard with `?? _fallbackPalette()` helper that returns hardcoded `EdenColors.danger/.warning/.success`. Required for back-compat with `EdenTheme.light()` callers that haven't migrated to `EdenAdaptiveTheme(profile: ...)` yet.
- **Monospace font lookup:** Use `TextStyle(fontFamily: 'JetBrainsMono')` if available; else `fontFamilyFallback: ['monospace', 'Courier']`. Eden's `EdenTypography` may already expose `monoTextStyle()` — check `lib/src/tokens/typography.dart` first.
- **BP critical thresholds — DON'T hardcode without override.** Hypertensive Crisis (`systolic ≥ 180 || diastolic ≥ 120`) is the standard JNC-8 cutoff but some clinics tune for elderly populations. Defaults provided but `criticalMin/Max` overrides honored.
- **Trend arrow ambiguity:** "up = bad" for BP/glucose but "up = good" for SpO2/weight-recovery contexts. Library does NOT encode semantic direction — arrow color follows reference-range coloring, NOT direction. Consumer reads it as "value moved up" not "value got worse."
- **patientId assertion in tests:** assertions fire in test mode (Flutter test default = debug). Write the isolation test using `expect(() => EdenVitalsRow(vitals: mixedPatientVitals), throwsA(isA<AssertionError>()))`.
- **Empty list handling:** `EdenVitalsRow(vitals: [])` MUST render an empty SizedBox (or empty Row) without throwing. The patientId assert is conditional on vitals.isEmpty.
- **`BMI` is computed from height+weight by consumer.** Library doesn't compute it. Consumer passes `EdenVitalSign(kind: bmi, value: 24.3)`. Encoded for completeness.
- **Test pairing rule:** source file `lib/src/widgets/eden_vitals_row.dart` MUST have paired `test/widgets/eden_vitals_row_test.dart`. Enforced.
- **Hand-built fixtures only.** Fixture file MUST start with `// Do NOT regenerate via LLM — hand-built clinical fixtures for EdenVitalsRow.` Use realistic-but-non-PII patient IDs (`pt-001`, `pt-002`) and clinical values (Hgb 12-16, BP 120/80, HR 60-100, Temp 97-99°F, SpO2 95-100%, RR 12-20).
- **medical_screen.dart is new file — ONLY 013-01 creates it.** 013-02..013-07 each APPEND a Section(...) at an anchor placeholder; they do not create the file. Wave 1 ordering: 013-01 must serialize BEFORE 013-02..013-05 because of this file-create dependency (despite same wave).
- **home_screen.dart registration is THIS TRD only.** Don't double-register from later TRDs. Tile icon suggestion: `Icons.medical_services_outlined` or `Icons.monitor_heart_outlined`.
- **eden_ui.dart export section header is THIS TRD only.** Later TRDs append exports under the same `// Objective 013 — B-Medical clinical primitives Wave N` headers without re-emitting them.
