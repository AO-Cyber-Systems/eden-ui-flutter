<objective>
Ship `EdenPatientChartScaffold` — the composite three-pane Patient Chart shell that downstream medical apps drop into to render an Epic/Cerner/athenahealth-class chart screen with library widgets only. Per `VERTICAL_WIREFRAMES_VALIDATION_2026-05-17.md` §3.1 M1 + §3.1 medical synthesis: "Missing pages-as-composites: PatientChartShell — the three-pane fixed layout (problem-list rail · tabbed chart · alert rail) is itself a composite pattern. EdenDetailPageScaffold provides 2-pane only."

Per locked decision B (`COMPANION_UX_PATTERNS_2026-05-15.md` §0): "Shell consistent across verticals; tab CONTENT can be radically different per vertical." This scaffold IS the shell.

Wave 3, FIRST sequential capstone — composes ALL of Wave 1 + Wave 2. 013-09 follows.

Per locked decision C: PHI handling reuses obj 011's compliance overlay. `EdenAuditLogViewer` (shipped in obj 011) composes into the right rail. Per locked decision F: AI surface stays callback-driven — `aiInsightSlot` param.

Outside-in test approach:
1. Full scaffold smoke (Expanded tier): all 3 panes render with realistic fixture.
2. Header rendering (composes EdenDetailHeader with patient demographics).
3. Tab switching (tap each tab → correct content widget visible).
4. Left rail composition (problems + meds + allergies stacked in correct order).
5. Right rail composition (alerts + audit + AI slot).
6. Tier responsiveness (Compact tier collapses to tabs-only).
7. HIPAA bleed isolation (passing wrong patientId fixture → assertion fires; wrong-patient data NEVER visible).
8. AI insight slot injection.
9. Audit log composition (EdenAuditLogViewer accessible from right rail).
10. Callback wiring.
</objective>

@immutable
class EdenPatientChartData {
  const EdenPatientChartData({
    required this.patientId,         // HIPAA isolation key — every sub-widget asserts this matches
    required this.demographics,       // EdenPatientDemographics(name, mrn, dob, sex, payer, pcp)
    required this.vitals,             // List<EdenVitalSign>
    required this.medications,        // List<EdenMedicationStatement>
    required this.problems,           // List<EdenCondition>
    required this.allergies,          // List<EdenAllergyIntolerance>
    required this.labs,               // List<EdenLabResult>
    required this.notes,              // List<EdenSoapNoteData>
    required this.timelineEvents,     // List<EdenChartTimelineEvent>
    this.blockingAlerts = const [],   // List<EdenBlockingAlert> — for right rail
    this.auditEvents = const [],      // List<EdenAuditEvent> from obj 011 — for right rail audit viewer
  });
  // ... fields
}

@immutable

    required this.mrn,
    required this.dob,

    this.preferredLanguage,

}

**Tier detection:**
- Use raw `LayoutBuilder` with breakpoints at 600pt (Compact/Medium) and 840pt (Medium/Expanded).
- Don't import EdenAdaptiveLayout to avoid Wave-2-of-obj-002 coupling — the breakpoints are well-established Material 3 tiers.

**HIPAA bleed isolation (integration-level assertion):**
- Constructor: `assert(data.patientId == patientId)`.
- Constructor: `assert(data.vitals.every((v) => v.patientId == patientId), 'PHI BLEED: vital with mismatched patientId in chart data')`.
- Same for medications, problems, allergies, labs, notes (via patientId on EdenSoapNoteData), timelineEvents, auditEvents (obj 011's EdenAuditEvent must carry patientId).
- Sub-widgets also assert independently (013-01 through 013-07). Defense in depth.
- **Critical test:** integration test passes mixed-patient data → AssertionError fires before any rendering occurs. In release builds (asserts disabled), no PHI from patient B ever appears in the rendered subtree (each sub-widget filters).

**Per locked decision C — PHI overlays:**
- The scaffold itself does NOT render classification banners or PHI redaction overlay — those are consumer concerns layered ABOVE the scaffold.
- Scaffold's responsibility: HIPAA isolation (no PHI bleed across patient boundaries) + audit log visibility.
- Consumer (medical app) wraps `EdenPatientChartScaffold` in `EdenClassificationBanner(level: 'HIPAA-PHI', ...)` from obj 011 to add the banner.
