# 024-01 — Vendored fixtures + set-hash drift gate

## Why this is first

The decoder in 024-02 is only worth trusting if it is tested against the REAL
recorded payloads, not against examples someone wrote to illustrate a design.
Those payloads live in eden-biz. A copy drifts
([[private-ddl-copies-drift-from-schema]]), so the copy must arrive with its
own detector in the same change — otherwise the whole objective rests on 14
files nobody can tell are current.

## BINDING CONTRACT (repeated per objective rule)

1. The renderer never fetches. 2. Affordances are granted by the payload.
3. Actions bind to tool ids or proposal ids, NEVER routes. 4. Refusal is
one-sided. 5. What this layer cannot do honestly becomes a refusal — never a
guess, never a crash. 6. §22: a check whose failure mode is indistinguishable
from its success mode is not a check.

## Source of truth

eden-biz `origin/main`, `go/internal/agentintent/testdata/` — 14 `*.json`
plus `manifest.json`. Set hash:

    9c4520d9e07e54fe29d0a19016bbac3b6c91d271159985d57dd201a2bd508fd2

Manifest's stated recipe, to be reimplemented exactly:

> `*.json` in this directory except `manifest.json`, file names sorted
> bytewise (LC_ALL=C), one line per file
> `"<sha256 hex of the file bytes><two spaces><filename>\n"`,
> set hash = sha256 hex of the concatenated lines

## Files

- Create: `test/fixtures/agentintent/*.json` (14 + manifest.json), byte-identical copies
- Create: `test/fixtures/agent_intent_fixtures.dart` — loader helper
- Create: `test/fixtures/fixture_set_integrity_test.dart` — the drift gate
- Modify: `pubspec.yaml` — declare `crypto` as a **dev_dependency**

## Dependency decision, stated rather than assumed

The recipe is defined in terms of sha256, so the gate needs a real sha256.
`crypto` is already resolved **transitively at 3.0.7**; declaring it
`dev_dependencies: crypto: ^3.0.7` changes one line of `pubspec.lock`
(`transitive` → `"direct dev"`) and adds no package. It must be a DEV
dependency, never a `dependencies:` entry — the pubspec's own comment states
why: eden-biz and aodex pin this library by path/git, and anything under
`dependencies:` enters THEIR production resolve.

`golden_uniqueness_test.dart` deliberately avoided `crypto` and compared
base64 bytes instead. That was right there and is wrong here: it was
comparing two local files to each other, where any injective function works.
This gate must reproduce a hash computed by ANOTHER repo's Go code, so the
function is specified, not chosen.

## TEST LIST (written before any test code)

1. **set-completeness** — the vendored directory holds exactly 14 `*.json`
   fixtures plus `manifest.json`; the count is named, so adding or dropping a
   file fails.
2. **per-file digest** — every fixture's sha256 equals its `manifest.json`
   entry's `sha256`. Catches a single corrupted or edited file and names it.
3. **recomputed set hash == vendored manifest** — recompute by the recipe
   above and compare to the vendored `set_sha256`.
4. **vendored manifest == the pinned literal** — `set_sha256` equals
   `9c4520d9…` written out in the test. TWO assertions, not one: (3) alone
   passes if someone re-vendors a *different* set together with its matching
   manifest; (4) alone passes if the manifest is stale against its own files.
   Neither detects the other's failure.
5. **manifest entries are exhaustive** — every vendored fixture appears in
   `manifest.fixtures[]` and every manifest entry has a file. A one-sided
   check passes while the other side drifts.
6. **every fixture parses** and carries `format`, `case`, `source`, `intent`.
7. **every `intent.component_id` is non-empty** — the invariant eden-biz's
   own integrity test asserts; re-asserted here so a truncated copy is caught
   at the same place.
8. **`card/proposal` invariant holds** — for every fixture whose
   `component_id` is `card/proposal`, each action's `proposal_id` equals
   `intent.data.action_id` (eden-biz `fixtures_integrity_test.go:172`).
9. **loader: a named fixture returns a parsed map.**
10. **loader: an unknown fixture name FAILS LOUDLY** — throws naming the
    name and listing the available ones. Returning `null` would let 024-02's
    tests silently assert nothing against a typo'd filename.

## Differential control (required)

Flip one byte in one vendored fixture. Expect: tests 2, 3 and 4 fail and name
the file; the rest pass. Revert; confirm `git diff` is empty and the suite is
green. Report exit codes both ways.

## Verification

```
flutter test test/fixtures/fixture_set_integrity_test.dart   # exit 0
flutter test                                                  # exit 0, full suite
dart run custom_lint                                          # exit 0
```

Never pipe a gate to `head`/`tail` and read `$?` — that reports the pipe's
status, which has produced a false green in this repo before.

## Done when

The 14 recordings are present, their hash is pinned against eden-biz's, a
single changed byte is detected and named, and 024-02 has a loader that
cannot silently hand it nothing.
