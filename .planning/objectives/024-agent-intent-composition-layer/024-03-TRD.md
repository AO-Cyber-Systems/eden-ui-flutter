# 024-03 — The dispatcher, the host context, and the way out

## BINDING CONTRACT (repeated per objective rule)

1. The renderer never fetches. 2. Affordances are granted by the payload.
3. Actions bind to tool ids or proposal ids, NEVER routes. 4. Refusal is
one-sided. 5. What this layer cannot do honestly becomes a refusal — never a
guess, never a crash. 6. §22: a check whose failure mode is indistinguishable
from its success mode is not a check.

## Why a factory map and not the list that exists

`kDataDisplayComponents` is `List<(String, Type)>`. A Dart `Type` cannot be
constructed without reflection and AOT Flutter has none, so that list can
DETECT an unknown id and can never RENDER a known one. It stays exactly as
it is — it is the verification artifact and its closed-partition test still
works — and this TRD adds a parallel map of BUILDERS:

    Map<String, Widget Function(EdenIntentRenderRequest)>

**The two must never disagree**, so a test asserts the builder map's key set
EQUALS `kDataDisplayComponents`' id set. Adding a component to one and not
the other must fail. Without that, the partition test keeps passing while
the thing that actually renders silently lacks an entry.

## Host context — the two gaps, and why a default is forbidden

Two components need what the payload does not carry:

- `EdenServiceList.currencyCode` — eden-biz#860
- `EdenProposalCard.subject` — eden-biz#863

Both are required and undefaulted on purpose. A wrong currency renders as
convincingly as a right one; a missing subject means authorizing a mutation
under no description. `EdenIntentHostContext` supplies them.

**If the context cannot supply what a component requires, the dispatcher
returns a REFUSAL naming the missing field. It never substitutes a default.**
This is the single most important assertion in the TRD: a dispatcher that
defaulted to `USD` would render a complete, confident, wrong price, and
nothing on screen would differ from the correct one.

## Action egress

One callback carrying a fired action back out, preserving WHICH KIND it is —
a tool invocation (`toolId`) or a proposal decision (`proposalId` +
`decision`). This layer invokes nothing; it hands back what the payload
granted. The caller owns transport.

## TEST LIST (written before any test code)

### Dispatch
1. Each of the 5 renderable `component_id`s dispatches to its widget, driven
   from its own vendored fixture end-to-end: raw JSON → envelope → decode →
   widget. Assert on a painted string unique to each component.
2. **All 14 fixtures dispatch to a widget or a refusal — none throws.**
   Iterate the whole set.
3. An unknown `component_id` dispatches to `EdenRefusal` whose reason names
   the id.
4. A payload the decoder refused dispatches to `EdenRefusal` carrying the
   decoder's reason — the reason is not replaced by a generic one.

### The two maps agree
5. The builder map's key set EQUALS the `kDataDisplayComponents` id set.
   Asserted both directions, with the symmetric difference in the failure
   message.

### Host context
6. `list/services` with a context supplying `currencyCode: 'USD'` renders
   `USD 50.00`.
7. **`list/services` with NO currency in context REFUSES**, and the reason
   names `currencyCode`. It must NOT render `USD`, and the test asserts the
   absence of a price string as well as the presence of the refusal — a
   dispatcher that both refused and rendered would pass a one-sided check.
8. `card/proposal` with a context supplying a subject renders that subject.
9. **`card/proposal` with NO subject REFUSES**, naming `subject`. Same
   two-sided assertion.
10. The three components needing no context (`list/appointments`,
    `list/customers`, `error/refusal`) render with an EMPTY context — a
    context requirement that applied to everything would be a tax, not a
    contract.

### Egress
11. A granted tool action fires and arrives at the callback with its
    `toolId`, from a real widget tap.
12. A granted proposal decision fires and arrives with `proposalId` AND
    `decision`, from a real widget tap.
13. **NO path in this layer turns an action into a route.** A source-level
    assertion over `lib/src/agent_intent/`: no `Navigator`, no `pushNamed`,
    no `GoRouter`, no `Route`, no `url_launcher`. Contract 3 is the one rule
    whose violation would be an authorization bypass rather than a bug, and
    a behavioural test cannot prove the absence of a path — only a scan of
    the source can. Mirror the tripwire style of
    `test/tool/emit_component_manifest_test.dart`.
14. **This layer never fetches** (contract 1): same scan asserts no `http`,
    no `HttpClient`, no `Dio`, no `fetch`, no `Future.delayed` polling.

## Differential controls (required)

- Default `currencyCode` to `'USD'` when the context lacks it → expect case 7
  to fail ALONE. This is the control that matters most; if other cases also
  fail, the test is not isolating what it claims.
- Remove one entry from the builder map → expect case 5 to fail naming it.
- Add a `Navigator.pushNamed` call to a dispatcher file → expect case 13 to
  fail. Revert each, confirm zero diff, report exit codes.
