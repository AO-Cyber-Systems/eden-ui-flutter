- Retail order: placed → packing → shipped → delivered (+ cancelled / returned / refunded)

enum EdenAppointmentStatus {
  scheduled,   // index 0 — initial state
  confirmed,   // index 1 — patient confirmed
  arrived,     // index 2 — patient checked in at front desk
  inRoom,      // index 3 — patient roomed
  completed,   // index 4 — visit done
  noShow,      // terminal (off-path) — patient didn't show
  cancelled,   // terminal (off-path) — cancelled in advance (>24h)
  lateCancel,  // terminal (off-path) — cancelled <24h before scheduled
}

EdenAppointmentStatus? nextLinearStatus(EdenAppointmentStatus current) {
  switch (current) {
    case EdenAppointmentStatus.scheduled: return EdenAppointmentStatus.confirmed;
    case EdenAppointmentStatus.confirmed: return EdenAppointmentStatus.arrived;
    case EdenAppointmentStatus.arrived: return EdenAppointmentStatus.inRoom;
    case EdenAppointmentStatus.inRoom: return EdenAppointmentStatus.completed;
    case EdenAppointmentStatus.completed: return null;  // terminal-success
    case _: return null;  // off-path terminals
  }
}

bool isTerminalStatus(EdenAppointmentStatus status) =>
    status == EdenAppointmentStatus.noShow
    || status == EdenAppointmentStatus.cancelled
    || status == EdenAppointmentStatus.lateCancel
    || status == EdenAppointmentStatus.completed;

**EdenStepper compose (locked):**
The widget builds `EdenStepItem` list from 5 linear states. For each step, the status is computed from currentStatus:
```dart
List<EdenStepItem> _buildSteps(EdenAppointmentStatus current) {
  final linearStates = [
    EdenAppointmentStatus.scheduled,
    EdenAppointmentStatus.confirmed,
    EdenAppointmentStatus.arrived,
    EdenAppointmentStatus.inRoom,
    EdenAppointmentStatus.completed,
  ];
  final currentIndex = isTerminalStatus(current) && current != EdenAppointmentStatus.completed
      ? -1  // terminal off-path: no step is current
      : linearStates.indexOf(current);
  return linearStates.asMap().entries.map((entry) {
    final i = entry.key;
    final stepStatus = currentIndex == -1
        ? EdenStepStatus.upcoming  // off-path: all upcoming, stepper greyed out via Opacity wrapper
        : i < currentIndex
            ? EdenStepStatus.complete
            : i == currentIndex
                ? EdenStepStatus.current
                : EdenStepStatus.upcoming;
    return EdenStepItem(label: _labelFor(entry.value), status: stepStatus);
  }).toList();
}

String _labelFor(EdenAppointmentStatus s) => switch (s) {
  EdenAppointmentStatus.scheduled => 'Scheduled',
  EdenAppointmentStatus.confirmed => 'Confirmed',
  EdenAppointmentStatus.arrived => 'Arrived',
  EdenAppointmentStatus.inRoom => 'In Room',
  EdenAppointmentStatus.completed => 'Completed',
  _ => '',
};
```

**Terminal-state rendering (locked):**
When currentStatus is in {noShow, cancelled, lateCancel}:
- Stepper rendered with `Opacity(opacity: 0.4, child: stepper)` to indicate inactive.
- EdenBadge prominently positioned below stepper:
  - noShow → danger color, label 'NO SHOW'
  - lateCancel → warning color, label 'LATE CANCEL'
  - cancelled → neutral color, label 'CANCELLED'

When currentStatus == completed: stepper renders normally with last step current/complete. No terminal badge needed (visible from stepper alone).

**Time-since-scheduled warning chip:**
When currentStatus == arrived AND (`(now ?? DateTime.now()).difference(scheduledFor).inMinutes > 15`):
- Render warning chip: 'Waiting ${minutes}m past scheduled time'
- Uses EdenStatusPalette.warning color.

  <anti_patterns>
    <pattern>Treating no-show / cancelled / late-cancel as a single 'cancelled' state. Operationally these are distinct: no-show triggers billing fee, late-cancel triggers different fee or warning, cancelled is administrative.</pattern>
    <pattern>Computing late-cancel automatically from cancellation timestamp + scheduledFor. The widget DISPLAYS the consumer's chosen state. Consumer decides cancelled vs lateCancel based on its own policy.</pattern>
    <pattern>Letting EdenStepper render with currentStatus=noShow as if the appointment was halfway through. Stepper MUST be visually deactivated (Opacity) when in off-path terminal state.</pattern>
    <pattern>Tying advance button to all-states-can-advance. Once at completed or any terminal state, advance must be hidden.</pattern>
    <pattern>Rendering an empty/decorative element when currentStatus=cancelled but with no terminal badge. The terminal badge is non-optional in terminal states.</pattern>
  </anti_patterns>
