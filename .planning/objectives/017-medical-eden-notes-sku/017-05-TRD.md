<objective>
Ship `EdenSecureMessagingThread` — the HIPAA-aware secure messaging variant of the generic conversation thread. Per `USE_CASES_MEDICAL_2026-05-17.md` UC-COM-01: secure messaging (provider ↔ patient) is the foundational patient-portal communication surface. SimplePractice's marquee patient-engagement feature.

**HIPAA-aware bezel on a generic thread.** This is NOT a from-scratch chat widget — it composes the existing `EdenMessageBubble` + `EdenMessageInput` primitives and layers on top:
- Non-dismissible PHI banner via `EdenClassificationBanner` (obj 011-01) — patient + provider always reminded the channel carries PHI.
- Per-message encryption-at-rest indicator (lock icon + tooltip).
- Per-message audit-log indicator (shield icon + tooltip).
- Audit-trail toggle (composes `EdenAuditLogViewer` obj 011-04 when expanded).
- Read-only state when thread is closed (compliance hold, billing dispute, post-discharge).

**No backend bind.** Library renders the UX cues. Consumer wires:
- Encryption-at-rest implementation (cryptography is a platform concern).
- Encryption-in-transit (TLS, mTLS — platform).
- Audit log persistence (HIPAA-compliant immutable log storage — platform).
- E2E key management.

Cross-vertical leverage: same pattern reusable as `EdenSecureCommThread` for attorney-privileged threads (legal vertical, with `labelText: 'PRIVILEGED'`) or classified comms (gov, with `level: EdenClassificationLevel.controlledUnclassified`).

8. Callback wiring (send, message tap, attachment tap, audit-trail request).
