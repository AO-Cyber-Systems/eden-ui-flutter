<objective>
Ship `EdenInsuranceCard` — patient insurance card front/back capture + extracted-data display. Per `USE_CASES_MEDICAL_2026-05-17.md` UC-INT-03: required even for cash-pay practices that occasionally bill. SKU A behavioral-health practices that operate cash-pay still need this for occasional out-of-network reimbursement workflows.

**Patient-specific PHI surface.** Same HIPAA isolation discipline as obj 013 — `patientId` on the policy value class, constructor-time assertion.

**No backend bind.** Library renders the card; consumer wires OCR/extraction. The widget displays the policy data the consumer has already extracted (planName, memberId, etc.) plus the raw front/back card images. Consumer handles image upload + OCR pipeline.

**Cross-vertical leverage.** Insurance card capture generalizes to ID-document capture (trades driver license + commercial endorsements, gov beneficiary ID, fuel hazmat driver cert). Same widget shape, different `planType` enum override. Catalog demonstrates this via 1 trades-vertical scenario.

Wave 1, serializes after 017-01 for medical_screen.dart APPEND order (one file-modify train within Wave 1 prevents catalog merge conflicts).

```dart
enum EdenInsurancePlanType {
  ppo, hmo, epo, pos, hdhp,
  medicare, medicaid, militaryTricare,
  dental, vision,
  other,  // cross-vertical override (e.g. 'Driver License', 'Commercial Endorsement')

@immutable

    required this.id,
    required this.patientId,
    required this.planName,
    required this.planType,
    required this.payerId,
    required this.memberId,
    this.groupNumber,
    this.planEffectiveDate,
    this.planTerminationDate,
    this.priorityRank = EdenInsurancePriority.primary,
    this.subscriberName,
    this.subscriberRelation = EdenSubscriberRelation.self,
    this.frontImage,
    this.backImage,
    this.verifiedAt,
    this.customPlanTypeLabel,  // when planType=other: label override (e.g. 'Driver License')
  });
  // ... fields all final
}
```

Widget API:
```dart
EdenInsuranceCard({
  super.key,
  required EdenInsurancePolicy policy,
  EdenInsuranceCardLayout layout = EdenInsuranceCardLayout.stacked,
  ValueChanged<EdenInsurancePolicy>? onEditRequested,
  ValueChanged<EdenInsurancePolicy>? onReplaceImageRequested,
  VoidCallback? onCardImageTap,
});
```

**Cross-vertical reuse pattern (locked):**
- When `planType == EdenInsurancePlanType.other` AND `customPlanTypeLabel != null`, the type-badge text displays the override (e.g. 'Driver License' for a trades driver-license-capture use case).
- All other planType values render the enum name verbatim ('PPO', 'Medicare', etc.).
- Consumer apps for non-medical verticals (trades / gov / fuel) compose this same widget with their own `EdenInsurancePolicy` instances + `planType: other` + custom labels.

**Theme:** Use `EdenStatusPalette` from obj 009 for priority colors (primary = success, secondary = warning, tertiary = neutral). Use `EdenThemeProfile.medicalInstitutional` body styles for the patient-facing surface.

**Image compose composition (locked):**
- `EdenAuthenticatedImage` (obj 001-07) for the actual card-front + card-back rendering — handles backend-served images with auth headers.
- `EdenAttachmentPreview` is the FALLBACK pattern only — for when images don't exist yet and we need to surface a "file attached but not rendered" state.
- Empty-images placeholder is a custom container (NOT EdenAttachmentPreview) — minimal rect with EdenBadge prompt.

```dart
  final clock = now ?? DateTime.now();
```
