<objective>
Ship `EdenAVSGenerator` — the patient-facing After Visit Summary composite that reuses obj-013 clinical primitives. Per `USE_CASES_MEDICAL_2026-05-17.md` UC-COM-03: "The single most-requested patient-portal surface across competitors (athenahealth, DrChrono, SimplePractice all ship this)."

This is the flagship widget of obj 017's SKU A push. The provider-facing chart already exists (obj 013); this widget pivots the same clinical data into a patient-readable summary — print/email/portal-share friendly. Library renders the widget; consumer wires the actual print/email/portal channels via callbacks (same callback-driven discipline as obj 013-06 SOAPNote).

**Distinct from EdenSOAPNote in view mode.** SOAPNote is the *clinician* artifact (medical jargon: Subjective / Objective / Assessment / Plan). AVS is the *patient* artifact (plain language: "Why you came in" / "What we measured" / "What we found" / "What to do next"). Composes SOAPNote in view-mode for the clinical detail block but layers patient-readable section headers, larger body type, and explicit follow-up call-outs on top.

Wave 1, parallel with 017-02 + 017-03 (017-01 bootstraps any new medical_screen.dart sections needed for obj 017; 017-02 + 017-03 append serially after).

Outside-in test approach:
1. Renders header (patient + provider + encounter date + facility).
2. Renders composed children (SOAPNote view-mode, MedicationList active-filter, ProblemList active-filter).
3. Patient-readable section headers replace SOAP labels.
4. Typography ≥14pt body / ≥18pt section headers verified.
5. Layout=compact single-column at narrow widths.
6. Layout=printFriendly 2-column at ≥600pt; collapses to single-column below.
7. Action buttons gated to non-null callbacks (no-callback = button hidden).
8. Callback wiring (onPrintRequested fires; onEmailRequested emits EdenAvsExport).
9. HIPAA isolation (mismatched patientIds across soapData/medications/problems throws AssertionError).

- SOAP "Subjective" → AVS "Why you came in" (visitReason override; soapData.subjective as supplementary detail)
- SOAP "Objective" → AVS "What we measured" (vitals + exam findings)
- SOAP "Assessment" → AVS "What we found" (diagnoses + impressions)
- SOAP "Plan" → AVS "What to do next" (treatment + follow-up + medications)

- `EdenProblemList` (obj 013-04) filtered to `EdenConditionStatus.active`.
- Custom plain-text "Follow-up instructions" block below SOAP if `followUpInstructions != null`.
- Custom "Next appointment" pill via `EdenBadge` if `nextAppointmentAt != null`.

### Happy path (integration → composition → unit)

1. **Renders header with patient + provider + encounter date** (integration-level entry point). Given a behavioral-health follow-up fixture, the widget renders `patient-alpha`'s display name, `Dr. Jane Smith, PsyD`, and the formatted encounter date.
2. **Renders composed EdenSOAPNote in view mode.** The SOAP detail block is present and read-only (no text-input affordance).
3. **Renders active medications only.** Given a fixture with 3 active + 2 discontinued meds, only the 3 active drug names are visible; the 2 discontinued drug names are NOT in the tree.
4. **Renders active problems only.** Given a fixture with 2 active + 1 resolved condition, only the 2 active condition descriptions are visible; the resolved condition is NOT in the tree.
5. **Renders patient-readable section headers.** "Why you came in", "What we measured", "What we found", "What to do next" appear; "Subjective", "Objective", "Assessment", "Plan" do NOT appear.
6. **Renders follow-up instructions when present.** Free-form text from `document.followUpInstructions` appears in a clearly-labeled "Follow-up instructions" block.
7. **Renders next-appointment pill when present.** `EdenBadge` containing the formatted `nextAppointmentAt` is in the tree.

### Edge cases (layout + typography)

8. **Layout=compact: single-column on iPhone-narrow.** At 390pt logical width, no row layouts split header from clinical detail.
9. **Layout=printFriendly: 2-column at ≥600pt.** At 800pt width, the meds list + problems list render side-by-side via a Row.
10. **Layout=printFriendly: collapses to single-column at <600pt.** At 500pt width, the same layout=printFriendly fixture renders single-column.
11. **Body typography ≥14pt.** Sampled body text widget has fontSize >= 14 (read from TextStyle).
12. **Section header typography ≥18pt.** Sampled section header widget has fontSize >= 18.

### Failure modes (callback gating + empty states)

13. **Print button hidden when onPrintRequested is null.** No "Print" button in tree.
14. **Print button visible when onPrintRequested non-null + fires callback on tap.** Tapping the Print button calls the callback exactly once.
15. **Email button hidden when onEmailRequested is null.** No "Email" button.
16. **Email button emits EdenAvsExport with format=email on tap.** Callback receives an EdenAvsExport whose `format == EdenAvsExportFormat.email` and `document == fixture.document`.
17. **Portal button mirrors email button gating + emits format=portal.**
18. **Empty medications list renders 'No active medications'.** Empty placeholder visible; no MedicationList row content.
19. **Empty problems list renders 'No active problems'.** Empty placeholder visible.
20. **Missing followUpInstructions: no follow-up block rendered.**
21. **Missing nextAppointmentAt: no next-appointment pill rendered.**

### HIPAA isolation (multi-tenancy guard per CLAUDE.md habit 6)

22. **Mismatched soapData.patientId throws AssertionError in debug.** Build document with `patientId: 'patient-alpha'` but `soapData.patientId: 'patient-bravo'`. Expect AssertionError on widget construction.
23. **Mismatched medications[].patientId throws AssertionError in debug.** One medication with `patientId: 'patient-bravo'` in an otherwise patient-alpha document.
24. **Mismatched problems[].patientId throws AssertionError in debug.** One condition with `patientId: 'patient-bravo'` in an otherwise patient-alpha document.
25. **Wrong-patient bleed isolation.** Patient A's document MUST NOT render any of patient B's medication / problem text when both fixtures coexist in test setup.
