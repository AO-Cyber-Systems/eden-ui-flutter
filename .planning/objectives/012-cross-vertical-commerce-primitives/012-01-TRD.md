<objective>

Composable line-item table: description / qty / unit-price / discount / tax / line-total + add / remove rows + draggable reorder. <anti_patterns>
- **Do NOT bind the editor to specific domain types.** Generic `<T>` is mandatory. The library does NOT know about retail products, medical CPT codes, fuel grades, or trades labor categories. Consumer wires the typed payload via `EdenLineItem<T>(payload: T, ...)`.
- **Do NOT include an "Add row" button INSIDE the editor.** Vertical-specific add UX (product grid for retail, CPT-code picker for medical, fuel-type chip strip for fuel, labor-type selector for trades) belongs in the consumer's `itemPickerSlot`. The editor only renders + edits + removes existing rows.
- **Do NOT use `Form` + `FormField` validators in this widget.** The editor is real-time editable. Validation is the consumer's responsibility (they wire it via `onItemsChanged` and surface validation in their own UI).
- **Do NOT use `setState` to update items.** The editor is fully controlled — items + onItemsChanged are required. The editor never owns item state; it only owns local UI state (focused cell, draft text in TextField buffers).
- **Do NOT eat keyboard input.** Quantity / unit-price / discount cells use real TextFields that route to standard Flutter focus traversal. No `RawKeyboardListener` swallowing Tab.
- **Do NOT round currency in the lineTotal computation.** The displayed value is rounded via `EdenCurrencyDisplay` (which uses `NumberFormat.currency`). The stored value stays double-precision so subsequent computations don't accrue rounding error.
- **Do NOT pull from a global theme without `Theme.of(context)`.** Specifically `EdenStatusPalette` extension reads must go through `Theme.of(context).extension<EdenStatusPalette>()` and tolerate `null` (obj 009 may not be wired in consumer's app yet).
</anti_patterns>

<gotchas>
- **EdenDataTable.dense editable-cell support.** Verify at TRD-execute time whether `DataCell(TextField(...))` works in EdenDataTable.dense. If not (Material's DataTable historically expects static cells), drop down to a custom `Table` widget + row builder pattern. The `lib/src/widgets/eden_data_grid.dart` is another option — check what donor screens (e.g. trades-flutter quote_builder.dart if present) used.
- **Generic class + Stateful widget.** `EdenLineItemEditor<T> extends StatefulWidget` requires the State class to ALSO be generic: `class _EdenLineItemEditorState<T> extends State<EdenLineItemEditor<T>>`. Dart enforces this — make sure the State class generic param is propagated.
- **TextField controller management.** Each editable cell needs its own `TextEditingController` keyed by row index + column. Naive approach (build a fresh controller every build) loses cursor position on every keystroke. Use a `Map<String, TextEditingController>` keyed by `'${rowIndex}-${columnId}'` lazily initialized + disposed in `dispose()`. See `eden_intake_form.dart` (obj 001-10) for a multi-controller pattern.
- **Focus loss on row remove.** When a row is removed mid-edit, the focused TextField's row index shifts. Either: (a) call `FocusScope.of(context).unfocus()` before invoking onItemsChanged with new list, OR (b) key TextFields by item identity (use a stable `EdenLineItem` ID) rather than by index. Option (b) is correct — require consumers to provide stable IDs (or auto-generate `UniqueKey` per item internally).
- **ReorderableListView in nested-scroll trap.** If consumer wraps the editor in a `ListView` / scrolling parent, `ReorderableListView` needs `shrinkWrap: true` + `physics: NeverScrollableScrollPhysics()`. Document this in the widget dartdoc.

`EdenLineItem<T>` value class:
```dart
class EdenLineItem<T> {
  const EdenLineItem({
    required this.id,                  // stable identity for TextField keying
    required this.payload,             // domain model (cart entry, quote line, etc.)
    required this.description,
    required this.quantity,
    required this.unitPrice,
    this.discountAmount,
    this.taxRate,
    this.note,
  });

  final String id;
  final T payload;
  final String description;
  final double quantity;
  final double unitPrice;
  final double? discountAmount;
  final double? taxRate;
  final String? note;

  double get subtotal => quantity * unitPrice;
  double get discounted => subtotal - (discountAmount ?? 0);
  double get lineTotal => discounted * (1 + (taxRate ?? 0));

  EdenLineItem<T> copyWith({
    String? id, T? payload, String? description, double? quantity,
    double? unitPrice, double? discountAmount, double? taxRate, String? note,
  }) => EdenLineItem<T>(
    id: id ?? this.id,
    payload: payload ?? this.payload,
    description: description ?? this.description,
    quantity: quantity ?? this.quantity,
    unitPrice: unitPrice ?? this.unitPrice,
    discountAmount: discountAmount ?? this.discountAmount,
    taxRate: taxRate ?? this.taxRate,
    note: note ?? this.note,
  );
}
```
