<objective>

Per validation §4.1 row 3 + §5 Wave 2 TRD-04: cash/card/check/account/split with change calc. Five blocked screens (M5 · F3 · R1 · T2 · T5).

Outside-in tests: single-row baseline first, then multi-row composition, then aggregation math, then over/under-capacity error states, then cash change-due rule, then a11y.

<anti_patterns>
- **Do NOT block submission internally.** The over-capacity state is informational. Consumer decides if save button is enabled based on `sum == total` — library only surfaces the state via `onDraftsChanged` + visible banner.
- **Do NOT recompute drafts from scratch on every keystroke.** Hold `_drafts: List<EdenPaymentDraft>` in state. When an EdenPaymentEntry's onDraftChanged fires for index N, replace `_drafts[N]` and emit aggregate via `onDraftsChanged`.
- **Do NOT include a 'Submit' button.** Same as 012-03 — composition emits drafts; consumer renders submit UI.
- **Do NOT prevent removing the LAST row.** Allow it (shows empty-state placeholder + the add-row button). Some flows want the operator to start from zero rows.
- **Actually — make the floor 1 row by default for UX clarity** (per must_haves). Most flows assume "at least one tender on screen at all times". Surface "remove the last row" as opt-in via a hypothetical `allowZeroDrafts: bool` if needed later — defer.
</anti_patterns>

<gotchas>
- **EdenPaymentEntry holds its own state.** When SplitTender removes row N, the EdenPaymentEntry widget at index N is destroyed (along with its `_method`, `_amountController`, etc.). The split-tender parent only holds `List<EdenPaymentDraft>`. This means: when a row is added, the new EdenPaymentEntry initializes via `initialDraft: _drafts[index]`. When a row is updated, the parent stores the latest draft from the callback. When a row is removed, both the widget and its draft are gone.
- **Keying the EdenPaymentEntry children.** If you reorder or remove rows by index, Flutter reuses widget state across instances, causing the wrong row's TextEditingController to bleed into another row. Use stable keys per draft. Easiest: generate `ValueKey(_draftIds[index])` where `_draftIds` is a parallel `List<String>` of `Uuid().v4()`-style identifiers managed by SplitTender. Alternative: use `ObjectKey(draft)` if EdenPaymentDraft has identity semantics — but value classes don't, so use ValueKey approach.
- **Sum calculation rounding.** Sum doubles directly: `_drafts.fold(0.0, (acc, d) => acc + d.amount)`. Tolerance check uses `(sum - total).abs() < 0.01` everywhere for balance/under/over decisions.
- **Change-due rule edge case.** Cash overpayment + allowOverCapacity → show change due. But what if user enters cash $30 + card $30 with total $50? Sum 60 > total 50, last method = card → no change-due (cards don't make change). Rule: change-due ONLY when the LAST modified row's method is cash AND total cash on rows >= overage. Simpler interpretation: just check if `sum > total AND latest_modified_method == cash` → change = sum - total. Document the simplification in dartdoc.
- **commerce_screen.dart APPEND ONLY.** Replace `// TRD 012-04 appends: ...` placeholder.
</gotchas>

```dart
class _EdenSplitTenderState extends State<EdenSplitTender> {
  late List<EdenPaymentDraft> _drafts;
  late List<String> _rowIds; // stable identity for ValueKey

  int? _lastModifiedIndex;

  @override
  void initState() {
    super.initState();
    _drafts = List.from(widget.initialDrafts ?? [
      EdenPaymentDraft(method: widget.allowedMethods.first, amount: widget.total),
    ]);
    _rowIds = List.generate(_drafts.length, (_) => _generateRowId());
  }

  String _generateRowId() => DateTime.now().microsecondsSinceEpoch.toString();
  // Simple monotonic — collisions implausible in test single-threaded environment.

  double get _remaining => widget.total - _sum;

  bool get _isOverCapacity => _sum > widget.total + 0.01;
  bool get _isUnderCapacity => _sum < widget.total - 0.01;
}
```

```dart
    super.initState();

    setState(() {
      _drafts[index] = draft;
      _lastModifiedIndex = index;

    widget.onDraftsChanged(List.unmodifiable(_drafts));
```
