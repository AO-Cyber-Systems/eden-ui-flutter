<objective>
Ship `EdenSignatureCapturePage` — a full-screen single-task signature capture flow that wraps the existing `EdenSignaturePad` widget. Used by field technicians collecting customer sign-offs, medical home-visit consent capture, fuel-delivery acknowledgment, gov caseworker witness signatures.

```dart
final result = await Navigator.of(context).push<EdenSignatureCaptureResult?>(
  MaterialPageRoute(builder: (_) => EdenSignatureCapturePage(
    title: 'Customer Signature',
    instructions: 'Please sign in the box below',
    signerName: 'Mr. Johnson',
    metadata: const {'work_order_id': 'WO-4821'},
  )),
);

if (result != null) {
  // result.strokes is List<EdenSignatureStroke>
  // result.signedAt is DateTime
  // result.metadata is Map<String, String>
  await myRepo.attachSignatureToWorkOrder(result);
}
```

The page renders:
1. AppBar with `title: 'Signature'` (configurable) + optional 'Clear' TextButton in actions (visible only when pad has strokes).
2. Body: `Padding(EdgeInsets.all(24))` with `Column[crossAxisAlignment: center]`:
   - Instructions Text (default 'Please sign in the box below', overridable).
   - `Expanded(EdenSignaturePad(...))` — the existing widget. Configure `strokeColor` / `backgroundColor` per donor style (white bg + black strokes).
   - Signer-name divider row: `Row[Expanded(Divider), SizedBox, Text(signerName ?? 'Signer'), SizedBox, Expanded(Divider)]`.
   - 'Signed on $date' centered Text using hand-rolled date formatter.
   - Action button row: `Row[Expanded(OutlinedButton.icon 'Clear' refresh-icon), SizedBox, Expanded(FilledButton.icon 'Save Signature' check-icon)]`.
3. Save button is enabled when pad has strokes AND not currently saving. When saving, button shows spinner + 'Saving...' label.
4. On Save tap:
   - `setState(() => _isSaving = true)`.
   - Compose `EdenSignatureCaptureResult(strokes: padStrokes, signedAt: DateTime.now(), metadata: widget.metadata)`.
   - If `widget.onSigned != null`: `await widget.onSigned!(result);`.
   - `Navigator.of(context).pop(result)`.
   - `setState(() => _isSaving = false)` (only if still mounted).

**Per locked decision (constraint 6, 12 — no trades binding, no new deps):** the donor `SignatureCapturePage`:
- Uses a CustomPainter `_SignaturePainter` placeholder (no real signature pad) → port REMOVES the placeholder; composes the existing `EdenSignaturePad`.
- Uses a simulated `_onTapCanvas` setState → port REMOVES; `EdenSignaturePad` already handles real gesture capture via its existing API.
- Uses `String signatureData` string callback → port uses the canonical `List<EdenSignatureStroke>` format (the format EdenSignaturePad already emits and EdenConsentFlow already consumes; see Wave A TRD 001-09).
- Hardcodes `_formattedDate` (M/D/YYYY) → port keeps a hand-rolled formatter (consistent with TRD 007-05/06 decisions).

**Composition position:** this page is designed to be `Navigator.push`-ed as a full-screen route. It RETURNS the result via `pop(result)`. The `onSigned` callback is an optional pre-pop hook for consumers who want to do something synchronous (logging, draft-save) before the navigator pops.

**Out of scope (deliberate):**
- Witness-signature flow (use `EdenConsentFlow` from Wave A TRD 001-09 for multi-signature flows; this is a single-signature page).
- Image-export of the signature (consumer's job — `EdenSignatureStroke` list is sufficient; if PNG export is needed, consumer can rasterize).
- Signature comparison / validation (none — accept any non-empty stroke set).
- Save-and-continue mode (page is single-shot; for multi-step flows, compose into `EdenConsentFlow`).
</objective>
