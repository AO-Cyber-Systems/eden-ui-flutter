<objective>
Ship `EdenMobileAiFab` + `EdenMobileAiChatSheet` — the bottom-sheet AI chat variant for companion-mode home screens. Pairs with objective 003's `EdenAgentChatFab` (which is the full-screen modal variant for admin); this widget is the **draggable bottom-sheet** variant per donor `mobile_ai_chat_sheet.dart` for on-the-go phone usage.

```dart
EdenMobileAiFab(
  pageContext: 'mobile_home',
  entityType: 'appointment',
  entityId: 'apt-123',
  entityLabel: 'Smith Job — 9:00 AM',
  activePersona: EdenAiPersona.fieldTech,
  onPersonaChanged: (p) => setState(() => _persona = p),
  sendMessage: (request) => myAodexRepo.streamChat(request),  // EdenChatStreamSender
  createConversation: (initial) => myAodexRepo.create(initial),  // EdenChatConversationCreator
  quickActions: const [
    EdenMobileAiQuickAction(label: 'Find Parts', icon: Icons.search),
    EdenMobileAiQuickAction(label: 'Equipment Info', icon: Icons.info_outline),
    EdenMobileAiQuickAction(label: 'Report Issue', icon: Icons.report_outlined),
  ],
  unreadCount: 1,
  accentColor: Color(0xFFD4A853),
);
```

On tap, the FAB calls `showModalBottomSheet` with `isScrollControlled: true` and renders `EdenMobileAiChatSheet` inside a `DraggableScrollableSheet(initialChildSize: 0.6, minChildSize: 0.4, maxChildSize: 0.9)`.

Internally:
1. `EdenMobileAiFab` is a `StatelessWidget` that renders a `FloatingActionButton(backgroundColor: accentColor)` + optional badge `Positioned` dot.
2. On `onPressed`, opens `showModalBottomSheet` with the chat sheet inside.
3. `EdenMobileAiChatSheet` is a `StatefulWidget` (manages local message list + scroll controller + text controller) that on first build inserts a greeting message using the active persona.
4. The sheet exposes a private `_sendMessage(String text)` that:
   - Appends a user-shaped `EdenChatMessage` to the local list.
   - Calls the consumer's `sendMessage(EdenChatRequest)` callback and awaits stream chunks.
   - On each chunk, appends/updates an assistant-shaped `EdenChatMessage` and scrolls to bottom.
5. Quick action chips fire `_sendMessage(action.label)` directly.

**Per locked decision (constraint 6 — no trades binding):** the donor `MobileAiChatSheet` hardcodes:
- Field Tech persona greeting text → port REMOVES this hardcode; consumer supplies `greeting: String?` OR (default) we synthesize a generic greeting using `EdenAiPersona.displayLabel`.
- Hardcoded `_quickActions = ['Find Parts', 'Equipment Info', 'Report Issue']` → port REMOVES; consumer supplies `quickActions: List<EdenMobileAiQuickAction>`.
- "Mock assistant response" line in `_sendMessage` → port REMOVES entirely. Consumer's `sendMessage` callback is the only chat backend.
- Gold accent `0xFFD4A853` → port keeps as DEFAULT but `accentColor` is constructor-configurable.
- Hardcoded "Working on: $entityLabel" copy → port keeps default copy but exposes `entityLabelPrefix: String = 'Working on'` for vertical override.

**Composition with objective 003:** This widget DOES NOT duplicate `EdenAgentChat`'s message-stream loop logic. The chat-message rendering inside the bottom sheet body uses **`EdenChatMessageBubble`** (objective 003 export) for each message, and the streaming-state management mirrors `EdenAgentChat`'s implementation pattern (but is reimplemented here because the bottom-sheet host has different layout constraints than the full-screen modal). See gotchas — open question on whether to literally compose `EdenAgentChat` as the body OR re-implement the stream loop inline.

**Out of scope (deliberate):**
- Conversation persistence (consumer owns via `createConversation` callback).
- Multi-conversation switcher (defer).
- Attachment upload affordance (defer).
- Voice-input (defer).
- Persona-selection inside the sheet (the sheet shows the ACTIVE persona; switching personas is up to consumer's FAB-host).
