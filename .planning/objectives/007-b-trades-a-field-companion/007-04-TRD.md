<objective>
Ship `EdenPhotoCapturePage` — a full-screen photo capture flow with annotation overlay and optional categorization. Used by field crews (trades — before/during/after photos), nurses (medical — wound progress photos), drivers (fuel — meter photos), caseworkers (gov — site visit evidence photos).

```dart
final result = await Navigator.of(context).push<EdenPhotoCaptureResult?>(
  MaterialPageRoute(builder: (_) => EdenPhotoCapturePage(
    appointmentId: 'apt-123',
    onCapture: (request) async {
      // Consumer launches camera_awesome / image_picker / etc. here.
      final file = await launchCamera();
      return EdenCapturedPhoto(
        filePath: file.path,
        bytes: await file.readAsBytes(),
        mimeType: 'image/jpeg',
        capturedAt: DateTime.now(),
      );
    },
    onPickFromGallery: () async {
      final file = await launchGallery();
      return EdenCapturedPhoto(filePath: file.path, capturedAt: DateTime.now());
    },
    categories: const ['before', 'during', 'after'],
    categoryRequired: false,
  )),
);

if (result != null) {
  await myRepo.attachPhotoToWorkOrder(workOrderId: 'WO-1', photo: result);
}
```

The page renders:
1. Scaffold with `backgroundColor: Colors.black` (donor parity for camera UX).
2. AppBar `backgroundColor: black, foregroundColor: white`, title 'Capture Photo' (configurable). When captured, AppBar.actions has 'Use Photo' TextButton (white text, w600).
3. Body Column:
   - **Expanded camera area** (top): Stack with two layers:
     - Layer 1 (background): when no photo captured AND `cameraPreviewBuilder` provided → `cameraPreviewBuilder(context)`; else when no photo + no builder → centered placeholder Icon + 'Camera viewfinder placeholder' text (testable graceful degradation). When photo captured → display the photo via `Image.memory(photo.bytes!)` (or filePath via `Image.file` if bytes null — but Image.file requires `dart:io` which may not work on web; prefer bytes path).
     - Layer 2 (overlay, post-capture only): annotation TextField in a `Positioned(bottom: 0, left: 0, right: 0)` with black-translucent background.
   - **Category chips** (post-capture only, when `categories != null`): horizontal scrollable FilterChip row, single-select. `_selectedCategory` state.
   - **Bottom controls** (always visible, fixed-height): Container with black bg:
     - Pre-capture: `Row[Gallery icon button, big shutter button (72x72 white-bordered circle), Flash icon button]`. Gallery taps `onPickFromGallery`, shutter taps `onCapture`, Flash is consumer-customizable via `onToggleFlash` callback (null → no Flash button).
     - Post-capture: `Row[Expanded(OutlinedButton 'Retake'), SizedBox, Expanded(FilledButton 'Use Photo')]`.

State machine:
- `_capturedPhoto: EdenCapturedPhoto?` (null pre-capture).
- `_annotation: String` (TextField controller).
- `_selectedCategory: String?`.
- `_isCapturing: bool` (true while `onCapture` awaits — show spinner over shutter).

**Per locked decision (constraint 6, 12):** the donor `PhotoCapturePage`:
- Uses a placeholder `_simulateCapture` that fabricates a fake path → port REMOVES; consumer's `onCapture` callback returns a real `EdenCapturedPhoto`.
- Has hardcoded 'placeholder' text for the viewfinder → port keeps the placeholder ONLY when `cameraPreviewBuilder == null` (graceful degradation when consumer hasn't wired up a camera plugin).
- Uses `String? existingPhotoPath` + `String? annotation` callback strings → port uses typed `EdenCapturedPhoto` value type for both.
- Does NOT have category chips → port ADDS them as opt-in (per audit §5 "categorization (before/during/after)").

**Composition position:** push as a `Navigator.push` route, returns result via `pop(result)`.

**Out of scope:**
- Camera SDK integration (consumer wires `onCapture`).
- Image compression/transcoding (consumer's job).
- Multi-photo capture in one session (single-photo per push).
- EXIF preservation (consumer's job — pass through filePath if needed).
- Photo annotation drawing (just text annotation; no drawn-overlay UI).
- Image editing / cropping.
- Flash control (callback boundary only).
</objective>

<gotchas>
- **`Image.file` on web.** `dart:io` is not available on web. Use `kIsWeb` guard or strongly prefer `Image.memory(bytes)` path. Document.
- **AppBar 'Use Photo' action duplication.** Donor shows AppBar TextButton 'Use Photo' AFTER capture (in addition to body button). Decision: keep both per donor; both trigger the same `_confirmAndReturn` handler.
- **Spinner during `onCapture` await.** Wrap the shutter button onTap in `setState(_isCapturing = true)` + try/finally; show `CircularProgressIndicator` over the shutter button while pending. If `onCapture` throws, show SnackBar 'Capture failed: $e' (white text on red bg).
- **`onCapture: null` and `onPickFromGallery: null` handling.** When both null, the page is unusable. Constructor `assert(onCapture != null || onPickFromGallery != null)` to prevent silently-broken pages.
- **Category required gate.** When `categoryRequired: true` AND `_selectedCategory == null`, Use Photo button is disabled (onPressed null). When `categoryRequired: false`, Use Photo always enabled post-capture.
- **TextField annotation autosave.** Donor uses `TextEditingController` + reads `_controller.text` on `_confirmAndReturn`. Preserve. No auto-save on every keystroke.
- **Pre-capture vs post-capture state.** `_capturedPhoto != null` is the discriminator. Retake clears `_capturedPhoto` + `_annotation` + `_selectedCategory`.
- **No camera SDK imports.** ZERO `camera_awesome`/`image_picker`/`camera` imports. Constraint 4 + 12.
- **Resolver constraints:** `no_llm_test_data`, `no_property_based_default`, `no_gherkin_layer`.
- **iPhone-narrow ≥390pt.** Bottom control row pre-capture: 3 buttons (Gallery 60pt + Shutter 72pt + Flash 60pt + 2 gaps) ≈ 192pt + ~MainAxisAlignment.spaceAround padding → easily fits in 390pt minus 48pt page padding. Post-capture row: 2 Expanded buttons + 16pt gap → fits.
</gotchas>
