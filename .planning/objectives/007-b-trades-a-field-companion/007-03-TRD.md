<objective>
Ship `EdenPackoutPage` — a full-page composition for truck-load checklist usage tracking (used by HVAC/electrical/plumbing field crews recording materials consumed at a job site; also cross-vertical for fuel-truck inventory consumption logging).

```dart
EdenPackoutPage(
  appointmentTitle: 'HVAC Repair — Johnson',
  items: [
    EdenPackoutItem(
      id: 'pi-1', itemName: '3/4" copper pipe', sku: 'CU-075',
      quantityLoaded: 50, quantityUsed: 12, quantityReturned: 0, unit: 'ft',
    ),
    EdenPackoutItem(
      id: 'pi-2', itemName: 'R410A refrigerant', sku: 'R410A-1lb',
      quantityLoaded: 4, quantityUsed: 2, quantityReturned: 2, unit: 'lb',
    ),
  ],
  onSaveItem: (item, edit) => myRepo.updatePackout(item.id, edit),
  onRefresh: () => myRepo.refresh(),
);
```

Layout:
1. AppBar title `'Packout / Materials'` (configurable via `appBarTitle`) with optional secondary line `appointmentTitle` below.
2. Body branches on `items`:
   - Empty → `EdenEmptyState` with 'No packout items'.
   - Non-empty → Column:
     - **Summary strip** (top, `surfaceContainerLow` bg): inventory icon + '$N item types loaded · $totalUsed units used' + when pendingEdits non-empty: '${count} unsaved' (orange).
     - **Refresh-indicator-wrapped ListView.builder** of `_PackoutItemCard`s.

Per-card:
- Collapsed: `InkWell > Padding(16) > Column[Row[Expanded(name+sku), Unsaved pill if dirty, expand icon], 8pt gap, Row[QuantityChip Loaded, QuantityChip Used, QuantityChip Returned]]`. Card border = orange if dirty edit, else default outline.
- Expanded: Divider + Row[Expanded(qtyUsed TextField), Expanded(qtyReturned TextField)] + notes TextField + Save FilledButton (disabled when not dirty or saving).

State machine:
- `_pendingEdits: Map<String, EdenPackoutEdit>` (keyed by item.id).
- `_savingItems: Set<String>` (item ids currently in `_saveItem` flight).
- `_expandedItems: Set<String>` (tracked via card-level state; OR managed centrally — see gotchas).

Save semantics:
- Tap Save on card → if `_pendingEdits[item.id] != null` and `!_savingItems.contains(item.id)`:
  - Add id to `_savingItems`.
  - `await widget.onSaveItem?.call(item, edit)`.
  - On success: remove id from `_pendingEdits`; UPDATE the card's source item via the returned `EdenPackoutItem` (replaces the original in the local items list via index lookup); SnackBar 'Usage saved'.
  - On error: SnackBar 'Failed to save: $e' (red bg).
  - Remove id from `_savingItems`.

**Per locked decision (constraint 6, 12):** the donor `PackoutPage`:
- Uses Riverpod (`ConsumerStatefulWidget` + `ref.watch(packoutItemsProvider)` + `ref.read(fieldCrewRepositoryProvider).updatePackoutUsage` + `ref.invalidate`) → port DROPS Riverpod; items come in via constructor; updates via callback.
- Imports `trades/features/field_crew/domain/packout_item_model.dart` PackoutItem → port DEFINES `EdenPackoutItem` value type.
- `ref.refresh(packoutItemsProvider).future` for pull-to-refresh → port uses simple `onRefresh: Future<void> Function()?` callback wired into RefreshIndicator.

**Composition position:** consumer pushes this page as a route (or composes into a tab inside `EdenCompanionShell`). Page does NOT pop on save (user can edit multiple items in one session).

**Out of scope:**
- Adding new items to the packout (consumer pre-loads; this page edits only).
- Barcode scanning (defer; consumer can prepend a scanner page).
- Cross-truck transfer.
- Photo evidence per item.
</objective>

<gotchas>
- **Items list mutability.** Library docs say "Library does NOT persist." But for in-session UX, when `onSaveItem` returns an updated item, the page DOES swap that item in the local items list so the chips reflect the saved state. Document: page mutates its LOCAL copy of items in-memory; the outer items prop remains the initial snapshot.
- **`StatefulWidget` items prop change.** If the parent updates the `items` prop (e.g., new appointment), didUpdateWidget should reset _localItems. Implement and test.
- **Save while edit input has focus.** Saving uses the captured edit; if user is mid-typing when Save is tapped, the LATEST `_pendingEdits[item.id]` is used (per donor — saves the typed value not the original). Verify by simulating type then immediate save.
- **Multi-item parallel saves.** Two items can be saved concurrently (different ids in `_savingItems`). Don't lock the page during a single save — only that card shows the spinner.
- **Per-card controllers (TextEditingController).** Each `_PackoutItemCardState` owns 3 controllers (used, returned, notes). Properly dispose in dispose().
- **`int.tryParse` fallback semantics.** If user clears the qty field and the controller has empty string, `int.tryParse('')` returns null; donor falls back to original item's value. Preserve.
- **iPhone-narrow ≥390pt risk.** Collapsed card row: name (Expanded) + 'Unsaved' pill (~70pt) + expand icon (24pt) → fits at 390pt. Quantity chip row: 3 chips with 8pt gaps + 32pt total padding → ~110pt per chip max. Expanded edit row: 2 Expanded TextFormFields + 12pt gap → fits. Test.
- **No Riverpod / no trades imports.** Constraint 4 + 12.
- **Resolver constraints:** `no_llm_test_data`, `no_property_based_default`, `no_gherkin_layer`.
</gotchas>
