<objective>
Ship `EdenLoadingIndicator` — the **M3 Expressive shape-morphing loader** that replaces `CircularProgressIndicator` as Eden's default for under-5s loads. Three named variants:
- `.shapeMorph()` — 4 dots morphing between shapes (M3 Expressive default)
- `.shimmer()` — sweeping shimmer band (skeleton-band style)
- `.crossFade({skeleton, content, isLoading})` — inline skeleton-to-content swap (lightweight inline alternative to TRD 010-08's `EdenSkeletonScope`)

Per `VERTICAL_UX_RESEARCH_2026-05-16.md` §2.1.1 row 2: "Material's new loading indicator is **the** default for under-5s loads. Add `EdenLoadingIndicator` using `AnimatedContainer` + shape morph."

**Coexists** with existing `EdenSpinner` (kept for indeterminate long-running ops per research §3.2 010-05) and `EdenSkeleton` (kept; this widget composes the same color tokens for shimmer).
</objective>

<anti_patterns>
- DO NOT use a `package:shimmer` dep or `package:loading_indicator` dep. Hand-roll both shapeMorph and shimmer with `AnimationController` + `AnimatedBuilder`.
- DO NOT replace `EdenSpinner` or `EdenSkeleton`. Both are preserved. EdenLoadingIndicator is additive — research §3.2 010-05 explicitly says "Keep CPI for indeterminate long-running".
- DO NOT make shapeMorph 8+ dots — performance + visual clutter. Stick to M3 Expressive's 4-dot canonical shape.
- DO NOT forget to dispose the AnimationController. Leaked controllers cause test failures across the suite ("pending timers" errors). Always `_morphController.dispose()` in `dispose()`.
- DO NOT pump in tests with `pumpAndSettle()` for indicators with `repeat()` — `pumpAndSettle` waits for animations to complete, but `repeat()` never completes. Use `pump(Duration(milliseconds: 100))` for targeted frame assertions.
</anti_patterns>

<error_recovery>
- If `repeat(reverse: true)` causes a jarring "snap back" between cycles, use `repeat()` with a 0→1→0 internal tween instead so the animation always increases monotonically.
- If test leaks "pending timers" with the repeat() animation: in test, after pumping, explicitly call `await tester.pumpWidget(Container())` to dispose the widget tree BEFORE the test ends, ensuring the State.dispose runs.
- If crossFade flickers at transition midpoint: use `AnimatedCrossFade` from Flutter Material as the implementation (handles cross-fade correctly out of the box). Pass `firstCurve: EdenSprings.curveFor(EdenSprings.smooth)` etc.
</error_recovery>

</embedded_context>

<gotchas>
- The shape-morph between circle/square/diamond is best implemented via a `CustomPainter` that interpolates the corner radius (circle = radius/2, square = 0, diamond = "rounded rotated square" — interpolate via `BorderRadius.circular` lerp + Transform.rotate(0.785) for diamond pose).
- Each dot's morph cycle should be staggered by ~150ms so they're not in sync (visual interest). Per-dot offset: `(_morphController.value + index * 0.15) % 1.0`.
- Per CLAUDE.md TDD Playbook habit 6 — `EdenLoadingIndicator` is NOT interactive; the wrong-tap test doesn't apply. The critical test is "loop disposes cleanly" — no pending timers after widget tree torn down.
</gotchas>
