CONSUMING showMenu pattern:
```dart
Future<void> _openMenu(BuildContext context, RenderBox buttonBox) async {
  final overlay = Overlay.of(context).context.findRenderObject() as RenderBox;
  final position = RelativeRect.fromRect(
    Rect.fromPoints(
      buttonBox.localToGlobal(buttonBox.size.bottomLeft(Offset.zero), ancestor: overlay),
      buttonBox.localToGlobal(buttonBox.size.bottomRight(Offset.zero), ancestor: overlay),
    ),
    Offset.zero & overlay.size,
  );
  final selected = await showMenu<int>(
    context: context,
    position: position,
    items: [for (int i = 0; i < widget.menuItems.length; i++) PopupMenuItem(value: i, enabled: widget.menuItems[i].enabled, child: ...)],
  );
  if (selected != null) widget.menuItems[selected].onSelected();
}
```

<anti_patterns>
- DO NOT use `PopupMenuButton` directly as a single widget — it doesn't visually split into primary+arrow segments. Compose your own Row with two GestureDetector children + showMenu for the dropdown.
- DO NOT make the primary segment open the menu on tap. Primary tap fires `onPrimary`; ONLY the dropdown arrow opens the menu. Confusion here is the most common SplitButton bug — write the WRONG-ACTION isolation test first.
- DO NOT duplicate EdenButton's color resolution. Either compose two `EdenButton` widgets and use a Row + custom border-collapse, OR extract `_resolveColors(theme, variant, isDark)` into a top-level helper in `eden_button.dart` and reuse it. **Avoid the temptation to copy-paste** — that's the most likely source of color drift between EdenButton and EdenSplitButton six months from now.
- DO NOT animate the dropdown open with EdenSprings — `showMenu` has its own Material animation; overlapping a custom spring on top creates a jittery visual. Keep the menu open animation default. EdenSprings is for the PRESS state of the two segments (same as EdenButtonGroup).
- DO NOT skip the WRONG-ACTION isolation test. Mark's most common form-flow bug across orgs: "Save & New" fires Save instead because the gesture-handler bound the wrong onPressed.
</anti_patterns>

<error_recovery>
- If `showMenu` returns null (user dismissed with tap-outside), do nothing — do NOT fire `onPrimary` as a fallback. Test for this case.
- If a `menuItems` entry has `enabled: false`, the PopupMenuItem renders disabled (Material handles this); confirm via tap-on-disabled-item test that nothing fires.
- If the parent has no Overlay (rare — happens in some custom Navigator setups), `showMenu` throws. Wrap the showMenu call in try/catch and `debugPrint` the error; silent failure is OK for v1 (the consumer caller should mount inside a MaterialApp / Navigator).
</error_recovery>

<gotchas>
- `PopupMenuItem` has its own `enabled` field; pass it through from `EdenSplitMenuItem.enabled`. The `onSelected` callback must be called manually after `showMenu` returns — `PopupMenuItem.onTap` does NOT fire if the item is `enabled: false`.
- Per CLAUDE.md TDD Playbook habit 4 — hand-built fixtures only. The menuItems list in tests must be explicit `EdenSplitMenuItem(label: 'Save & New', onSelected: () => calls.add('saveAndNew'))` literals, not generated.
- Dropdown arrow segment width: match Material's IconButton minimum 48pt tap target on the arrow side. The primary segment can be any width; the arrow segment is fixed 48pt minimum.
</gotchas>
