<objective>
Ship `EdenSprings` — a hand-rolled spring-physics motion token library that future Eden widgets in this objective (and downstream) compose for M3 Expressive-style motion. Replaces ad-hoc `AnimationController(duration: ...)` + `Curves.easeOut` calls with named, physics-backed presets.

**This TRD is Wave 1 foundation: TRDs 02-10 all consume EdenSprings.**

Why now: per `VERTICAL_UX_RESEARCH_2026-05-16.md` §2.1.1 row 1, Eden uses time-based curves (`EdenDurations.easeOutExpo` = 250ms cubic-bezier); M3 Expressive (May 2025) uses damped springs. Adopt: spring tokens (`EdenSprings.snap / .smooth / .bouncy / .rubber`) calling Flutter's `SpringDescription`. Hand-rolled — Flutter ships `SpringSimulation` in `package:flutter/physics.dart`; no `rive` / `lottie` / `animations` dep.

Output: 4 named presets + 2 helper functions + 1 test file + 1 export. Single source file under `lib/src/tokens/`, matching existing `EdenDurations` shape.
</objective>

<anti_patterns>
- DO NOT add `rive`, `lottie`, `animations`, or any motion-library dependency to pubspec.yaml. Flutter's built-in `package:flutter/physics.dart` SpringSimulation + SpringDescription is sufficient.
- DO NOT modify `lib/src/tokens/durations.dart`. EdenDurations is a stable contract; EdenSprings is additive alongside it. The two coexist — `EdenDurations` for time-based curves, `EdenSprings` for physics-based motion.
- DO NOT export presets as `static final` (rebuild risk). Use `static const SpringDescription` where the const constructor permits, or `static final` ONLY if SpringDescription's constructor is non-const in current Flutter SDK — verify by reading the flutter SDK's `physics/spring_simulation.dart` first.
- DO NOT name the helper `EdenSprings.spring(...)` — that reads tautological. Use `EdenSprings.simulationFor(preset, ...)` and `EdenSprings.curveFor(preset)`.
- DO NOT bundle simulation defaults like `velocity=100`. Default `velocity = 0` (resting start) — callers supply velocity when gesture-driven (drag-release, fling).
</anti_patterns>

<error_recovery>
- If `SpringDescription` constructor is `const` in current Flutter SDK → use `static const` for presets.
- If `SpringDescription` constructor is NOT `const` (Flutter < some version) → use `static final` and document the rebuild-safety contract (compiler will hand back the same identity across calls because `final` is initialized once).
- If `SpringSimulation.x(time)` does not give a usable Curve approximation, the `EdenSprings.curveFor(preset)` helper can degrade to returning a `Curves.easeOutCubic`-equivalent with a comment explaining the limitation. **Prefer:** subclass `Curve` with `transform(double t)` calling a normalized SpringSimulation. Validate by sampling at t=0, t=0.5, t=1 and confirming t=1 ≈ target value.
</error_recovery>

</embedded_context>

<gotchas>
- `SpringSimulation` is **not** a `Curve`. To bridge into `Tween<T> + CurvedAnimation` callers, wrap the simulation in a custom `Curve` subclass that calls `simulation.x(t)` (mapped from `[0,1]` to the simulation's natural time range).
- Spring presets that are too bouncy (low damping) can overshoot beyond 1.0 — that's correct physics but breaks `CurvedAnimation` which expects `[0,1]` output. The `EdenSprings.curveFor` adapter MUST clamp/normalize, OR document that the `bouncy` and `rubber` presets are intended for `AnimationController.animateWith(simulation)` rather than `CurvedAnimation`.
- A `SpringDescription` does NOT carry a duration — duration emerges from the simulation reaching rest. For widgets that need a hard timeout (e.g. accessibility "skip animation"), pair the simulation with `MediaQuery.disableAnimations` check and fall back to instant transition.
</gotchas>

   ```dart
   static Curve curveFor(SpringDescription preset) {
     return _SpringCurve(preset);
   }

   class _SpringCurve extends Curve {
     _SpringCurve(this._preset)
         : _sim = SpringSimulation(_preset, 0.0, 1.0, 0.0);
     final SpringDescription _preset;
     final SpringSimulation _sim;

     @override
     double transform(double t) {
       // Sample at t scaled to simulation's natural time. Practical natural
       // settle ~3.0s for stiffness=160-500; multiply input t by 3.0.
       final value = _sim.x(t * 3.0);
       // Clamp for under-damped presets that overshoot beyond 1.0; callers
       // that want raw physics should use simulationFor + AnimationController.
       return value.clamp(0.0, 1.0);
     }
   }
   ```
