<objective>
Ship `EdenButtonGroup` — the **M3 Expressive segmented-button-group component**. Connected pill cluster of 2-6 buttons (icon, label, or icon+label) with shape-morph-on-press animation driven by `EdenSprings.snap` (from TRD 010-01). Cross-vertical use: toolbar mode switches, view toggles, filter pills, action banks.

Per `VERTICAL_UX_RESEARCH_2026-05-16.md` §2.1.1 row 3: "Adds `EdenButtonGroup` — connected buttons with shape changes on press. Eden's `EdenSegmentedControl` is close but different semantic." This is NEW (not a wrapper around EdenSegmentedControl) — segmented control is for **single-of-N** selection inside a tab-strip context; button group is for **action clusters where each button can be primary or each represents a discrete mode**.

Library-owned: zero state ownership (consumer supplies `selectedIndex` + `onSelected`). Transport-agnostic. Composes `EdenSprings` from TRD 010-01.
</objective>

<anti_patterns>
- DO NOT make `EdenButtonGroup` a `StatefulWidget` that owns `selectedIndex`. The consumer owns selection state (Riverpod / setState / etc.) and passes `selectedIndex` in. Library is transport-agnostic AND state-agnostic.
- DO NOT use `SegmentedButton` (Material 3 built-in). M3 SegmentedButton has different semantics (single-of-N segmented control inside chips) and our `EdenButtonGroup` is the M3 Expressive button-group spec — a sibling, not the segmented-control replacement.
- DO NOT reach into `EdenButton`'s internals. Use it as a black box OR re-implement the pressed-state visual locally — the latter is preferred because shape-morph is per-segment and EdenButton doesn't animate corners.
- DO NOT bake in a max-children assertion at 6 in production code. Use an assertion in debug mode (`assert(items.length >= 2 && items.length <= 6, ...)`) — release-mode rendering should still not crash for 1 or 7+ items (degrade gracefully).
- DO NOT skip the 'wrong-tap' isolation test. Per CLAUDE.md TDD Playbook habit 6 — every interactive widget gets a test that proves tap on item N triggers onSelected(N) and NOT any other index. Cheap test, catches the most common gesture-handler bug.
</anti_patterns>

<error_recovery>
- If shape-morph animation creates a "jumping border" visual artifact at the seam between adjacent buttons — flatten the border via `BorderRadiusGeometry.lerp(...)` driven by the pressController instead of swapping `BorderRadius` instances mid-animation. Sample at every frame using `AnimatedBuilder`.
- If `EdenSprings.snap.simulationFor(from: 0, to: 1)` simulation never reaches "done" because of low damping precision — wrap the controller with a 600ms hard timeout (`Future.delayed(Duration(milliseconds: 600), () => _pressController.value = 0)`) for the release leg. Document this as a workaround in the dartdoc.
- If iPhone-narrow 390pt overflows when 6 buttons present with long labels — apply `child: Flexible(child: ...)` around each segment AND `TextOverflow.ellipsis` on the label Text. Confirm with widget test at `tester.binding.window.physicalSizeTestValue = const Size(390 * 3, 700 * 3); tester.binding.window.devicePixelRatioTestValue = 3.0;`.
</error_recovery>

<gotchas>
- M3 Expressive button-group **shape-morph** spec: the connected corners flatten further inward on press, **NOT** outward. Inspect Android Authority M3 Expressive coverage for visual reference; the pressed segment's leading/trailing radius decreases slightly to "tuck in" while the resting state has the full pill radius.
- Adjacent segments share a border — implement via `Border.fromBorderSide(...)` with the trailing border of segment N + leading border of segment N+1 collapsing to a single visual line. Easy hack: each segment has full border, then negative `right: -1` margin overlap. Cleaner: use a Row with `Container(... border: Border(right: BorderSide(width: 1)) ...)` for non-last segments.
- Per `EdenAvatar` precedent (`status: EdenAvatarStatus?`), enums for related-but-different visual modes belong in the same library file — define `enum EdenButtonGroupStyle { connected, spaced }` if a future spaced-variant emerges. For v1, ship `connected` only and document the enum as forward-compat.
</gotchas>
