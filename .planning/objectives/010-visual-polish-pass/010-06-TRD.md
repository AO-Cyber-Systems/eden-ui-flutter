<anti_patterns>
- DO NOT modify the existing `EdenDataTable()` default constructor or its behavior in any way. Backwards-compat is the gate; touching the default constructor breaks 30+ downstream consumers across obj 003 / 004 / 008.
- DO NOT use `package:sticky_headers` or any third-party sticky-header plugin. Sticky header is a Column+Expanded+SingleChildScrollView arrangement — pure Flutter.
- DO NOT mandate inline-edit. The TRD calls for "affordance" — the row height must ACCOMMODATE 32pt-tall TextField cells, but the library does NOT inject TextFields. Consumers supply whatever cell Widgets they want; .dense() just ensures the row chrome doesn't crowd them.
- DO NOT bake in a max-rows assumption. The dense variant must handle 40, 400, 4000 rows. Use `ListView.builder` for the scrollable body (not Column.children) for any row count >50 to keep scroll perf.
- DO NOT bind keyboard shortcuts globally. Wrap the table-body region in `Focus()` + `Shortcuts()` so the keyboard handlers ONLY fire when the table has focus.
- DO NOT skip the WRONG-SELECT isolation test. Bulk-select multi-row gestures are the #1 dense-table bug class — "Mark thought he selected row 5 but really selected row 6 because of an off-by-one in onChanged".
</anti_patterns>

<error_recovery>
