CONSUMING `EdenSprings` for the unfurl animation:
```dart
late final AnimationController _menuController;

@override
void initState() {
  super.initState();
  _menuController = AnimationController.unbounded(vsync: this);
}

void _toggleMenu() {
  if (_isOpen) {
    _menuController.animateWith(EdenSprings.simulationFor(
      EdenSprings.snap, from: _menuController.value, to: 0,
    ));
  } else {
    _menuController.animateWith(EdenSprings.simulationFor(
      EdenSprings.snap, from: _menuController.value, to: 1,
    ));
  }
  setState(() => _isOpen = !_isOpen);
}
```

STAGGERED unfurl pattern (each action's animation offset by index*50ms):
```dart
double _actionAnimValue(int index) {
  // 0..1, stagger means each action starts at index*0.15 fraction of the parent
  final start = index * 0.15;
  final clamped = ((_menuController.value - start) / (1.0 - start)).clamp(0.0, 1.0);
  return clamped;
}
```

<anti_patterns>
- DO NOT replace `EdenMobileAiFab`. That widget is a specialized AI-chat launcher with persona switching and bottom-sheet integration; it shipped in obj 007 and has downstream consumers. `EdenFabMenu` is a SIBLING generic.
- DO NOT use `SpeedDial` from the `flutter_speed_dial` package — that's a third-party dep. Hand-roll the unfurl with `AnimatedBuilder` + `EdenSprings`. No new pubspec deps.
- DO NOT auto-close the menu on tap-outside via a full-screen GestureDetector that swallows ALL pointer events — that breaks taps on whatever is below the FAB. Use a `ModalBarrier` or a `Stack` with a positioned-but-pointer-aware Scrim that has 0.0 opacity so it's tappable without visually dimming.
- DO NOT bake in the brand gold default. The accent color defaults to `Theme.of(context).colorScheme.primary` so profile-aware theming works (per obj 009). The donor gold is a `EdenMobileAiFab` quirk, not a library default.
- DO NOT use `Hero` widgets without unique tags — multiple FABs on one screen with the same heroTag crashes Flutter at navigation transitions. Default `heroTag = 'eden_fab_menu'`; consumers MUST override when multiple instances co-exist.
</anti_patterns>

<error_recovery>
- If actions overflow above the viewport (FAB too close to top of screen with 6 actions) — clamp the action stack to start from the FAB and grow upward; if the top action would be above the screen, fall back to growing DOWNWARD instead (`Column(verticalDirection: VerticalDirection.up)`). Detect via `MediaQuery.of(context).size.height - fabBottomOffset < actionsHeight`.
- If hero animation interferes with route push (FAB looks like it teleports during a Navigator.push), set `heroTag: null` for FABs that don't need hero transitions, OR provide a unique tag per route.
- If spring unfurl looks jittery on iOS 16 simulator (a known Flutter physics issue at very low values), swap `EdenSprings.snap` for `EdenSprings.smooth` (critically damped) as the unfurl preset. Document the choice inline.
</error_recovery>
