<objective>
Ship `EdenStoreCreditLedger` — customer-attached store-credit balance + history surface for cashier lookup ("how much store credit does this customer have?") and manager audit ("what credit was issued / spent / expired for this customer?"). Per `USE_CASES_RETAIL_2026-05-17.md` UC-27: currently zero coverage in the eden-ui-flutter library; Lightspeed markets "Store credit, refunds & exchanges" as a pillar feature.

Renders: balance header → held-amount sub-row (when holds present) → history `EdenDataTable` → empty state for new customers.

Generic — knows nothing about retail. Consumer maps domain (`store_credit_balances`, `store_credit_transactions`, `store_credit_holds`) to `EdenStoreCreditLedgerData` + `EdenStoreCreditEntry` + `EdenStoreCreditHold`. Cross-vertical reuse: trades customer-credit / deposits ledger, salon prepaid-package balance, fuel customer-account credit (all share `balance + history + holds` shape).

Wave 1 atomic primitive. Depends on 018-01 ONLY for the `retail_polish_screen.dart` file-create (anchor pattern). No widget composition or runtime dependency.

Outside-in test approach: static rendering (header balance, holds sub-row, history table, empty state) → type-color + signed-amount formatting → iPhone-narrow card-stack collapse → helper unit tests (signed amount formatter, badge color per type).
</objective>

@immutable
class EdenStoreCreditLedgerData {
  const EdenStoreCreditLedgerData({
    required this.customerId,
    this.customerName,
    required this.balanceCents,
    this.history = const [],
    this.holds = const [],
  });
  final String customerId;
  final String? customerName;
  final int balanceCents;                       // signed; negative = overdrawn (consumer-policy concern)
  final List<EdenStoreCreditEntry> history;
  final List<EdenStoreCreditHold> holds;
}

enum EdenStoreCreditEntryType { issued, spent, adjustment, expired }

@immutable
class EdenStoreCreditEntry {
  const EdenStoreCreditEntry({
    required this.id,
    required this.occurredAt,
    required this.type,
    required this.amountCents,        // SIGNED — issued/+adj positive; spent/expired/-adj negative
    this.reason,
    this.receiptRef,
  });
  final String id;
  final DateTime occurredAt;
  final EdenStoreCreditEntryType type;
  final int amountCents;
  final String? reason;
  final String? receiptRef;
}

@immutable
class EdenStoreCreditHold {
  const EdenStoreCreditHold({
    required this.id,
    required this.holdAmountCents,         // always positive
    required this.holdReason,
    required this.placedAt,
    this.expiresAt,
  });
  final String id;
  final int holdAmountCents;
  final String holdReason;
  final DateTime placedAt;
  final DateTime? expiresAt;
}

**Layout (top to bottom):**
1. Header: `Row([Column(customerName, customerId), Spacer, EdenCurrencyDisplay(data.balanceCents, large)])`. customerName may be null → show `'Customer #${customerId}'`.
2. Holds sub-row (conditional): when `data.holds.isNotEmpty`, render below header a row showing:
   - Total held: `EdenCurrencyDisplay(holdsTotal)` with a `EdenBadge('On hold', color: amber)`.
   - Available: `EdenCurrencyDisplay(data.balanceCents - holdsTotal)` (label 'Available').
   - Inline list of hold reasons (collapsible or just `Text('${holds.length} active holds')`).
3. History table:
   - Title row: `'History'` + count badge `'${history.length} entries'`.
   - At ≥`narrowBreakpoint` width: `EdenDataTable` with columns `[Date, Type, Amount, Reason, Receipt #]`.
   - At <`narrowBreakpoint`: vertical `ListView.builder` of `EdenCard` per entry showing all 5 fields as labeled rows.
4. Empty state: when `history.isEmpty`, render `EdenEmptyState(title: 'No store-credit history', message: 'This customer has no recorded credit activity yet.')` in place of the table.

**Helpers (file-private):**
- `int _holdsTotal(List<EdenStoreCreditHold> holds)` — `holds.fold(0, (acc, h) => acc + h.holdAmountCents)`.
- `String _formatSignedMoney(int cents)` — `cents >= 0 ? '+\$${(cents / 100).toStringAsFixed(2)}' : '-\$${(-cents / 100).toStringAsFixed(2)}'`. (Use `\$` to escape Dart string interpolation.)
- `Color _typeColor(EdenStoreCreditEntryType t, BuildContext context)` — green / blue / orange / grey per type, pulled from `Theme.of(context).colorScheme` where possible.
- `String _typeLabel(EdenStoreCreditEntryType t)` — 'Issued' / 'Spent' / 'Adjustment' / 'Expired'.
- `String _formatDate(DateTime d)` — `'{MMM d}'` for current-year entries, `'{MMM d, yyyy}'` else. Hand-roll with `_months` const list (same as 018-01).
- `List<EdenStoreCreditEntry> _sortedHistory(List<EdenStoreCreditEntry> h)` — `[...h]..sort((a, b) => b.occurredAt.compareTo(a.occurredAt))`.

- **Do NOT** filter expired entries. Consumer policy.

<gotchas>
- **`balanceCents` is signed.** Consumer can pass negative (overdrawn). Widget renders `-$5.00` via `_formatSignedMoney`. Test asserts negative formatting.
- **`amountCents` in entries is signed.** Type alone doesn't determine sign — e.g., `adjustment` can be `+$10` (manager added credit) or `-$5` (manager removed credit). Render color is determined by sign of `amountCents`, not by `type`. Test asserts adjustment can be either color.
- **Holds total computation:** sum of `holdAmountCents` (always positive). Available = balance - holdsTotal. Available can be negative if holds exceed balance (consumer policy concern); render as-is.
- **History sort stability:** when two entries have identical `occurredAt`, dart's `sort` is stable; preserve consumer-provided order as a tie-break.
- **Narrow-mode breakpoint:** 700pt default. iPhone-narrow (390pt) MUST trigger card stack mode. Test at both 390pt + 600pt + 1024pt.
- **Empty `history` + non-empty `holds`:** show holds-row + empty-state for history. Test this combo.
