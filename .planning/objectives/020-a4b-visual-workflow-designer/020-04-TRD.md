<gotchas>
- **Branch node has NO popover editor.** Donor `BranchNode.tsx` is presentational-only with delete button. Library follows.
- **Condition node ports MUST have distinct Yes (green) / No (red) handle colors.** Donor uses `!bg-green-500` for yes and `!bg-red-500` for no. The visual distinction is part of UX — users read flow direction by handle color. Library emits `EdenDiagramPort(id: 'yes', color: '#10B981', ...)` + `EdenDiagramPort(id: 'no', color: '#EF4444', ...)`. TRD 020-01 already emits these per the `_conditionPorts()` helper; verify.
- **Diamond hit-test:** the InkWell ripple looks weird on a rotated container. Test pragma: wrap the Stack in a `Material(color: Colors.transparent)` + plain `GestureDetector(onTap: _openEditor)` for the condition node specifically. The visual ripple isn't necessary; the popover is the feedback.
- **Counter-rotation of content inside diamond:** Donor does `rotate-45` on shape + content sits in a separate `<div className="absolute inset-0">` that's NOT rotated. Flutter: use a Stack with the rotated container in Positioned.fill + the content in another Positioned.fill (NOT rotated). The math works because the bounding box is 140x140 square, and the diamond inscribes it.
- **Condition `value` field stays as String in popover.** Donor types `value: any` but the popover UI is a plain text input. Library v1 follows — value is stored as String. Future enhancement: type-aware input based on field metadata (deferred).
- **TRD 020-01 graph builder port emission for Branch + Merge nodes** is documented in TRD 020-01 gotchas but those ports aren't emitted yet (only trigger/condition/action/end are). When TRD 020-04 ships, the graph builder MUST be extended to handle Branch ports. Verify by reading `workflow_graph_builder.dart` — if `_branchPorts()` / `_mergePorts()` helpers are absent, the canvas won't have correct port lists on dropped branch/merge nodes. This is a **TRD 020-04 + 020-05 supplementary task** — extending the graph builder's port emission to cover branch/merge node types when they're dropped from the toolbox.
- **Branch/Merge nodes are NOT in donor's flat `conditions/actions[]` array.** They're layout-only — present in canvas, not in `EdenWorkflowSaveData.conditions/actions`. TRD 020-01's `fromCanvas` BFS skips them by default (only condition/action types are collected). This is intentional — the workflow execution engine doesn't NEED branch/merge in the flat schema; the canvas layout preserves them visually for the editor. Future enhancement: persist them as a separate `flowNodes[]` field in saveData.
- **iPhone-narrow safety:** 140-160pt widths fit comfortably at 390pt. Diamond's 140x140 bounding box is also fine.
- **Inconvenient API: `EdenDiagramPort.color` is a String hex.** Per obj 006 TRD-01: `EdenDiagramPort(id, side, offset, kind, color: '#10B981', data)`. NOT a `Color` object. The diagram painter parses the hex. Confirm by reading obj 006 diagram_data.dart at task start; if `color:` accepts `Color`, adapt.
</gotchas>

class EdenConditionNode extends StatefulWidget {

  @override State<EdenConditionNode> createState() => _EdenConditionNodeState();

class _EdenConditionNodeState extends State<EdenConditionNode> {
  bool _hovered = false;
  bool get _isTouch => !kIsWeb &&
    (defaultTargetPlatform == TargetPlatform.iOS ||
     defaultTargetPlatform == TargetPlatform.android);

  String get _field => widget.context.node.data['field'] as String? ?? '';
  EdenWorkflowConditionOperator get _operator {
    final raw = widget.context.node.data['operator'] as String?;
    return EdenWorkflowConditionOperator.values.firstWhere(
      (o) => o.name == raw, orElse: () => EdenWorkflowConditionOperator.equals);
  }
  dynamic get _value => widget.context.node.data['value'];

  String _operatorSymbol(EdenWorkflowConditionOperator op) => switch (op) {
    EdenWorkflowConditionOperator.equals => '=',
    EdenWorkflowConditionOperator.not_equals => '≠',
    EdenWorkflowConditionOperator.greater_than => '>',
    EdenWorkflowConditionOperator.less_than => '<',
    EdenWorkflowConditionOperator.contains => '∋',
    EdenWorkflowConditionOperator.not_contains => '∌',
  };

  String _operatorLabel(EdenWorkflowConditionOperator op) => switch (op) {
    EdenWorkflowConditionOperator.equals => 'Equals',
    EdenWorkflowConditionOperator.not_equals => 'Not Equals',
    EdenWorkflowConditionOperator.greater_than => 'Greater Than',
    EdenWorkflowConditionOperator.less_than => 'Less Than',
    EdenWorkflowConditionOperator.contains => 'Contains',
    EdenWorkflowConditionOperator.not_contains => 'Not Contains',
  };

  String _displayLabel() {
    final f = _field;
    if (f.isEmpty) return 'Configure...';
    return '$f ${_operatorSymbol(_operator)} ${_value ?? ''}';
  }

  Future<void> _openEditor() async {
    var newField = _field;
    var newOperator = _operator;
    var newValue = (_value ?? '').toString();

    final saved = await showDialog<bool>(
      context: context,
      builder: (dialogCtx) => StatefulBuilder(builder: (stateCtx, setLocal) => AlertDialog(
        content: SizedBox(width: 320, child: Column(mainAxisSize: MainAxisSize.min, children: [
          const Text('Field', style: TextStyle(fontSize: 12, fontWeight: FontWeight.w500)),
          TextFormField(
            initialValue: newField,
            decoration: const InputDecoration(
              hintText: 'e.g. status, priority, customer_type', isDense: true, border: OutlineInputBorder()),
            onChanged: (v) => newField = v,
          ),
          const SizedBox(height: 12),
          const Text('Operator', style: TextStyle(fontSize: 12, fontWeight: FontWeight.w500)),
          DropdownButtonFormField<EdenWorkflowConditionOperator>(

            items: EdenWorkflowConditionOperator.values.map((o) => DropdownMenuItem(
