<objective>
Wave 2B. Ship `EdenTemplateBuilderCanvas` — the editable surface widget that consumers compose into their template-builder UI alongside `EdenTemplateBlockPalette` (TRD-02) and the right-rail panels (TRD-04). The canvas:

1. Routes layout to one of two pluggable engines: `EdenTemplateVerticalStackLayout` (default — Column + ReorderableListView for top-down block flow) or `EdenTemplateFreeformLayout` (composes `EdenDiagram` from obj 006 for x,y positioning).
2. Renders 3 section tabs (Header / Body / Footer) filtering blocks by `EdenTemplateSection`.
3. Renders block placeholders via `EdenTemplateBlockPlaceholder` (consumer-overridable via descriptor `placeholderBuilder`).
4. Accepts drops from the palette via `DragTarget<EdenTemplateBlockDescriptor>`.
5. Emits callbacks for block lifecycle: add, update, delete, reorder.
6. Renders a fallback message at <1200pt per the desktop-primary positioning.

Parallel with TRD-02 in Wave 2 because they own distinct files. Depends on TRD-01 (value classes + registry).
</objective>

In `EdenTemplateBuilderCanvas.build`, switch on `widget.layout.runtimeType` (or use a visitor pattern) to choose the layout strategy. Vertical-stack is `ReorderableListView`; freeform composes `EdenDiagram` with hand-built `EdenDiagramData`.

**Freeform mode composes EdenDiagram:**
- `EdenTemplateBlock.content` slot stores `x`, `y` coordinates (doubles).
- Build `EdenDiagramData` from the filtered (by-section) blocks: each block becomes an `EdenDiagramNode` with `x: block.content['x']`, `y: block.content['y']`, `width: 160`, `height: 60`, `label: descriptor.displayName`.
- `customNodeRenderer` callback wires `EdenDiagramNode` → `EdenTemplateBlockPlaceholder` rendering.
- DragTarget overlay accepts palette descriptors and converts drop position to (x, y) via the diagram controller's `globalToLocal` (or equivalent — see obj 006 TRD-02 for drag-target hit-test on diagram).
- For v1, freeform mode does NOT support drag-to-reorder (it's freeform — no ordering); the canvas exposes `onUpdateBlock(blockId, {x: ..., y: ...})` after a node drag.

**DragTarget integration:**
- Wrap the canvas in `DragTarget<EdenTemplateBlockDescriptor>(onAcceptWithDetails: (details) { onAddBlock?.call(details.data, activeSection, _computeInsertIndex(details.offset)); }, builder: (ctx, candidate, rejected) => ...)`.

- In vertical-stack mode, `_computeInsertIndex` uses the drop y-offset to compute which sibling-block index to insert before. In freeform mode, `insertIndex` is null (block's x/y comes from the drop offset).

<gotchas>
- **Layout engine is `const`-constructible.** Both `EdenTemplateVerticalStackLayout()` and `EdenTemplateFreeformLayout()` are const. Consumers swap via `layout: const EdenTemplateFreeformLayout()`. The base class is NOT `sealed` (Dart sealed requires same library) — use `abstract class` + document the closed-set expectation.
- **ReorderableListView quirk — newIndex when moving down.** Flutter's `ReorderableListView.onReorder(int oldIndex, int newIndex)` requires the callback to subtract 1 from newIndex when oldIndex < newIndex (the `removeAt` then `insert` semantics). Library API hides this quirk: `EdenTemplateBuilderCanvas` does the subtraction before firing `onReorderBlock(section, oldIndex, adjustedNewIndex)` so consumers get sane indices. Document this in dartdoc.
- **Filtering blocks by section.** Inside the canvas, derive `sectionBlocks = widget.graph.blocks.where((b) => b.section == activeSection).toList()..sort((a, b) => a.order.compareTo(b.order));` — always sort by order. Donor pattern at `builder_canvas.dart:32-37`.
- **Block reorder updates `order` field — but that's the consumer's job.** The canvas fires `onReorderBlock(section, oldIndex, newIndex)`; the consumer's reducer updates each block's `order` to maintain sort. Library does NOT mutate the graph directly (callbacks, not state).
- **DragTarget builder is the canvas — drop-target highlight is a ring around the document page.** When `candidate.isNotEmpty`, the document page Container gets a colored border (theme primary, 2pt). Donor doesn't have this (donor uses snackbar stub); library upgrades to a real drop-target visual.
- **Empty-section state — render when `sectionBlocks.isEmpty`.** Show the donor Column (icon + 2-line message). The DragTarget still wraps this empty area, so dropping a palette item adds the first block.
- **Footer section indicator — render BELOW the block list, INSIDE the document page container.** Donor at `builder_canvas.dart:251-275`. Library matches.
- **Layout engine routing in build().** Don't try to do polymorphism via visitor for v1 — runtimeType switch is fine. Document that adding new engines requires patching this switch.
  ```dart
  Widget _buildContent() {
    if (widget.layout is EdenTemplateVerticalStackLayout) {
      return _buildVerticalStack();
    } else if (widget.layout is EdenTemplateFreeformLayout) {
      return _buildFreeform();
    }
    throw StateError('Unsupported layout engine: ${widget.layout.runtimeType}');
  }
  ```
- **Freeform mode — handle null x/y gracefully.** If a block has no `x`/`y` in its content, default to (50, 50) cascading by index (e.g., `x: 50 + index * 20, y: 50 + index * 20`) so blocks don't all stack on top of each other.
- **Freeform mode — DragTarget convert drop position.** When a palette descriptor is dropped on freeform canvas, the canvas wraps the entire `EdenDiagram` in a `DragTarget` whose builder is the diagram. On accept, compute the drop offset relative to the diagram (use `RenderBox.globalToLocal` on the diagram's RenderBox via the GlobalKey). Set `block.content['x'] = localOffset.dx; block.content['y'] = localOffset.dy;` before passing to `onAddBlock`.
- **Drop target index calc in vertical-stack.** Given drop y-offset within the ReorderableListView's RenderBox, iterate over child positions to find which sibling-block the drop fell before. Simpler: drop always appends to the end of the active section (index = sectionBlocks.length), with reorder as a follow-up gesture. Library v1 uses append-only; document that mid-list insertion is a follow-up.
- **`narrowFallback` widget — typed as Widget?, not String.** A widget gives consumers full control (custom illustration, link, etc.). Default fallback is a Center(child: Padding(child: Text(...))).
- **Material 3 theming — use `Theme.of(context).colorScheme.surface` for document page bg, NOT hard-coded white.** Donor uses `Colors.white` for the document page; library uses surface token so dark themes work. Document this divergence from donor in dartdoc.
- **Block placeholder widget — separate file `eden_template_block_placeholder.dart`.** Reusable; same widget used in TRD-05 dev catalog. Constructor: `EdenTemplateBlockPlaceholder({required this.block, required this.descriptor, this.onEdit, this.onDelete, this.showDragHandle = true})`. Renders Row(icon + Column(label + subtext) + spacer + drag handle).
- **ConsumerPlaceholderBuilder override.** When `descriptor.placeholderBuilder != null`, use that instead of the default `EdenTemplateBlockPlaceholder`. Document in TRD-01's descriptor dartdoc.
- **Don't add `BuilderToolbar` widget.** Donor has a top toolbar (title + actions) — that's consumer-driven content. Library does not ship a `EdenTemplateBuilderToolbar` v1. Consumers compose their own toolbar above the canvas.
- **`activeSection` state — internal to canvas.** No external controller v1. If a consumer needs to control the active section programmatically, that's a follow-up TRD (add `controller: EdenTemplateBuilderCanvasController`).
</gotchas>
