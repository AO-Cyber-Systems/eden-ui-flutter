Wave 2 view — Month. The existing `MonthView` widget at `lib/src/widgets/scheduler/scheduler_month_view.dart` is mostly complete (renders calendar grid with event dot indicators). Three additions for parity with the donor:
1. Rename `MonthView` → `EdenSchedulerMonthView` (public-API consistency with TRDs 04/05).
2. Add overflow handling — cap event chips per cell and add a "+N more" indicator that expands on tap.
3. Generalize the click-to-expand-day behavior (`onDateSelected` already exists; ensure it fires on cell taps consistently).

Parity row V-4 + TG-6 light variant.
</objective>

<context>
**Locked design inputs:**
- Existing `MonthView` widget at `lib/src/widgets/scheduler/scheduler_month_view.dart` (read it). It renders a 6-row × 7-column grid of day cells with event dot/chip indicators.
- Donor month view (visible in `04-schedule-page.png` switched to Month tab) shows event chips with title text. When too many events fit, donor truncates and shows count.
- Donor mobile day-detail-view (`Schedule.tsx:528-718`) — tapping a day on mobile opens a popout drawer with all events for that day. The library equivalent: tap on day cell OR `+N more` opens a Material `showModalBottomSheet` or `Dialog` with the full event list, fully usable from any view.

**Approach:**
1. Rename class + file references; deprecate old name via typedef.
2. Add `maxEventsPerCell: int` parameter (default = 3 for desktop, computed via LayoutBuilder for mobile).
3. If `events.length > maxEventsPerCell`, render first N as chips and a "+(events.length - N) more" tap target.
4. Tap on "+N more" → `showModalBottomSheet` listing all events for that day with onEventTap forwarded.
5. Tap on day NUMBER (existing) → `onDateSelected(day)` fires; consumers can choose to also `controller.setView(EdenSchedulerView.day)` to drill in.

**Mobile collapse rule:** at column width < 50pt, event chips collapse to colored dots (no title). At column width < 80pt, "+N more" becomes "+N" (no "more").
</context>

<gotchas>
- **`maxEventsPerCell` calculation:** desktop has plenty of height per cell (~80pt). 3 chips × 16pt = 48pt fits with room for the day number. Mobile cells at 390pt / 7 cols = 55pt wide × ~50pt high → maybe 2 dots fit. Use LayoutBuilder per-cell:
  ```dart
  final cellHeight = constraints.maxHeight / 6; // 6 rows
  final maxChips = (cellHeight - 24 /* day number row */) ~/ 16 /* chip height */;
  ```
- **Bottom sheet on tap:** `showModalBottomSheet(context: context, builder: (_) => _DayDetailSheet(day, events))`. Sheet has a Material 3 shape (top-rounded), a header showing the date, and a scrollable list of events.
- **Outside-of-month day handling:** existing code already renders Mar/Apr days at the edges of a month grid in muted color. Preserve. Events on outside-of-month days STILL show their chips (clicking those chips fires onEventTap, then drill-down to the right month).
- **Color dots vs chips:** at narrow widths, use `Container(width: 6, height: 6, decoration: BoxDecoration(color: event.color ?? theme.primary, shape: BoxShape.circle))` for dots. Wrap them in a `Wrap(spacing: 2)` so multiple dots fit horizontally.
- **`+N` accessibility:** at very narrow widths the "+N" is the only affordance. MUST have `Semantics(button: true, label: '$N more events')`.
- **No now-indicator on month view.** Month is date-precision, not time-precision. Don't render the red line.
- **Today highlight on month cell:** existing code already renders today's cell with a subtle background; preserve.
- **Event filtering by day:** when the events list is large and recurrence-expanded, this happens per-cell. For v1, naive `events.where((e) => sameDay(e.start, day)).toList()`. TRD 16 (performance) may add caching.
- **Recurrence:** if `events` contains an event with `recurrence: weekly(...)`, the MonthView naively only sees the original event's start day. **MonthView consumer (eden_scheduler.dart) must call `EdenSchedulerTimeMath.expandRecurrence(event, monthStart, monthEnd)` before passing events to MonthView.** Document this contract in dartdoc. Actually a cleaner contract: MonthView accepts `events` and internally calls expandRecurrence if any event has recurrence. Simpler for consumers.
</gotchas>
