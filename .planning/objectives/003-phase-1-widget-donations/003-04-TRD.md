<gotchas>
- **`maxCapacity` formula:** `reorderPoint > 0 ? reorderPoint * 2 : 100`. If consumer passes `reorderPoint: 0`, the gauge defaults to capacity=100 so the bar isn't divide-by-zero. Edge case must be tested.
- **Color override priority:** `isBelowReorder` (currentStock ≤ reorderPoint when reorderPoint > 0) forces red even if percent ≥ 50%. Example: currentStock=50, reorderPoint=80 → percent=50/(80*2)=31.25% which is amber territory by percent, BUT 50 ≤ 80 so triggers `isBelowReorder` red. Test this priority explicitly.
- **`percent.clamp(0.0, 1.0)`** — donor clamps to handle currentStock > maxCapacity gracefully. Test currentStock=200, reorderPoint=50 → maxCapacity=100, raw percent=2.0, clamped to 1.0 (full bar, green).
- **`showLabel = false`** hides the entire label Row including 'Reorder at N'. Test this off-state.
- **iPhone-narrow safety:** the label Row uses `MainAxisAlignment.spaceBetween` with two Text children — narrow viewports could overflow if labels grow. Wrap inner Texts in `Flexible(child: Text(..., overflow: TextOverflow.ellipsis))` for safety.
</gotchas>

**Color threshold — green (≥50% of maxCapacity, NOT below reorder)**
- `EdenStockLevelIndicator(currentStock: 80, reorderPoint: 50)` → maxCapacity=100, percent=0.8 → green color on bar.
- `EdenStockLevelIndicator(currentStock: 100, reorderPoint: 50)` → percent clamped to 1.0 → green.

**Color threshold — amber (25–50% of maxCapacity, NOT below reorder)**
- `EdenStockLevelIndicator(currentStock: 35, reorderPoint: 10)` → maxCapacity=20… wait that's not amber territory. Use `currentStock: 60, reorderPoint: 50` → maxCapacity=100, percent=0.6, 0.6 ≥ 0.5 → green not amber. Adjust: `currentStock: 70, reorderPoint: 100` → maxCapacity=200, percent=0.35, 0.25 ≤ 0.35 < 0.5, NOT below reorder (70 > 100? no, 70 < 100 — TRIGGERS isBelowReorder=red). Use `currentStock: 70, reorderPoint: 50` → maxCapacity=100, percent=0.7, 0.7 ≥ 0.5 → GREEN.
- Correct amber test: `currentStock: 40, reorderPoint: 30` → maxCapacity=60, percent≈0.67 → GREEN. Hmm. The amber region requires percent ∈ [0.25, 0.5) AND currentStock > reorderPoint. Try `currentStock: 35, reorderPoint: 30` → maxCapacity=60, percent≈0.58 → green. `currentStock: 20, reorderPoint: 15` → maxCapacity=30, percent=0.67 → green. The geometry makes amber narrow: need `reorderPoint*0.5 < currentStock ≤ reorderPoint*1.0` (which is below-reorder → red) OR `reorderPoint < currentStock < reorderPoint*2*0.5 = reorderPoint*1.0` (collapses to empty). **Conclusion: amber is only reachable with `reorderPoint=0` (then maxCapacity=100) at currentStock 25..49.** Test `currentStock: 35, reorderPoint: 0` → maxCapacity=100, percent=0.35, isBelowReorder=false (reorderPoint==0 short-circuits) → AMBER.

**Color threshold — red (below reorder OR <25%)**
- `EdenStockLevelIndicator(currentStock: 50, reorderPoint: 100)` → maxCapacity=200, percent=0.25, isBelowReorder=TRUE (50 ≤ 100) → RED.
- `EdenStockLevelIndicator(currentStock: 5, reorderPoint: 0)` → maxCapacity=100, percent=0.05 < 0.25, isBelowReorder=false → RED.
- `EdenStockLevelIndicator(currentStock: 100, reorderPoint: 100)` → boundary: 100 ≤ 100 = TRUE → RED.

**Labels visible / hidden**
- Default (showLabel=true) → '50 in stock' text visible + 'Reorder at 100' visible.
- `showLabel: false` → neither label text visible.
- `reorderPoint: 0, showLabel: true` → '5 in stock' visible but 'Reorder at 0' NOT visible (donor only renders reorder text when `reorderPoint > 0`).

**Height override**
- `EdenStockLevelIndicator(currentStock: 50, reorderPoint: 50, height: 16)` → bar height SizedBox is 16, borderRadius=8.

**Edge / responsive**
- Renders inside `SizedBox(width: 390)` (iPhone-narrow baseline) without `RenderFlex overflowed` warnings.
