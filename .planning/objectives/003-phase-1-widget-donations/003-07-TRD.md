## Test list (write FIRST)

**Empty path**
- `EdenBlockingAlerts(alerts: const [])` → renders only `SizedBox.shrink()`; no header text, no Container border.

**Header text (singular vs plural)**
- 1 alert → header reads '1 blocked item' (no 's').
- 2 alerts → header reads '2 blocked items'.
- 5 alerts → '5 blocked items'.

**Severity color**
- All-amber list (2 alerts, both amber) → header text + border use Colors.amber-derived color.
- Mixed list (1 red + 1 amber) → header + border use Colors.red-derived color (red takes priority).
- All-red list (3 alerts, all red) → red.

**Toggle visibility (count > 1)**
- 3-alert expanded view → all 3 task labels visible.
- Tap header → 3 task labels become NOT visible (collapsed); chevron icon switches from expand_less to expand_more.
- Tap header again → labels visible again.

**Toggle gating (count == 1)**
- 1-alert view → no chevron icon (only the count is interactive UI).
- Tapping header DOES NOT collapse (no `InkWell` `onTap` to fire).

**Action buttons**
- Alert with 2 actions → 2 `OutlinedButton`s visible, each with label and onPressed callback wired.
- Tapping an action button fires its `onPressed` (use VoidCallback closure to capture the call).
- Alert with empty actions list → no action button row rendered.

**Per-alert content rendering**
- Each alert displays `task — context` as a single Text line (ellipsis on 1 line).
- Reason text appears below in severity-tinted color (red or amber).

**Edge / responsive**
- Renders inside `SizedBox(width: 390)` (iPhone-narrow baseline) with 3 alerts and 2 actions each → no overflow warnings.
