**Critical decoupling (per OBJECTIVE.md Constraints 4–6):**
- Donor reads `ref.read(activePersonaProvider)`, `ref.read(aodexConnectedProvider)`, `ref.read(chatConversationIdProvider)`, `ref.read(aodexRepositoryProvider)`. ALL replaced by callback parameters.
- Donor streams via `repo.streamChat(AodexChatRequest)` returning `Stream<AodexStreamChunk>`. Library introduces its own `EdenChatRequest` + `EdenChatStreamChunk` + `EdenChatChunkType` types and a callback signature `Stream<EdenChatStreamChunk> Function(EdenChatRequest)`.
- Donor handles persona-switch-proposal via `PersonaSwitchProposalCard` (depends on `trades/shared/domain/intent_classification.dart`). Library replaces with a generic `Widget? proposalCard` slot — consumer renders its own proposal widget if it has one. Intent classification stays consumer-side.
- Donor handles online/offline detection via `aodexConnectedProvider`. Library accepts a plain `bool isOnline = true` parameter.
- Donor creates conversations via `repo.createConversation(personaId: persona.name, title: widget.pageContext)`. Library accepts `Future<String> Function({required String personaId, required String title}) createConversation` callback.

This TRD splits implementation into 3 small files to keep cognitive load manageable:
1. `eden_chat_streaming_callbacks.dart` — defines `EdenChatRequest`, `EdenChatStreamChunk`, `EdenChatChunkType`, callback typedefs.
2. `eden_chat_message_bubble.dart` — extracted message bubble (donor's `ChatMessageBubble`).
3. `eden_agent_chat.dart` — the FAB + sheet composition.
