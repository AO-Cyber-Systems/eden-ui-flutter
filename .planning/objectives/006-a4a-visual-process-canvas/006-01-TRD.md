<gotchas>
- **Field name `runtimeComponent` is a String, not an enum.** Donor types it as `string`; library types it as `String` (NOT a Dart enum). This is the registry-driven knob. The runtime component registry validates ids at lookup time; arbitrary strings are accepted at the value-type layer. Test: `EdenProcessTaskTemplate(runtimeComponent: 'made-up-future-type')` constructs without error (verification happens at the registry lookup boundary, not at construction).
- **`approvalRole` and `approvalUserId` are nullable strings.** Donor types `approvalRole: string | null` and `approvalUserId: string | null`. Library uses `String?` (Dart's null-safe equivalent). DO NOT enum-encode roles — roles are vertical-defined.
- **Workflow-hook ids are nullable ints.** Donor: `onCompleteWorkflowId?: number | null` etc. Library: `int? onCompleteWorkflowId`. The 4 task-level hooks + 3 group-level hooks all use the same pattern.
- **`responsibilityType` is a nullable string slot.** Donor types `responsibilityType?: string | null`. Library follows: `String? responsibilityType`.
- **`materializesAsTask` defaults TRUE for checklist/closeout_checklist.** Donor comment: "When true, this template materializes as a row in the unified tasks table. Defaults true for checklist/closeout_checklist." Library follows: `bool materializesAsTask = true` (default true; consumer override per-task).
- **`blockingBehavior` is a String (NOT enum).** Donor types `blockingBehavior: string` (free-form). Library follows.
- **JSON round-trip for all value types.** Every value type MUST expose `toJson() → Map<String, dynamic>` and `fromJson(Map<String, dynamic>) → T` factory. Mirror the existing `EdenDiagramData.toJson` / `fromJson` pattern at `lib/src/widgets/eden_diagram/diagram_data.dart:67-100`. Tests exercise round-trip.
- **`EdenProcessLayoutData.version: int = 1`.** Donor uses `version: number`. Library hard-codes default 1; future schema migrations bump it. Document in dartdoc that bumping `version` is a breaking change requiring consumer migration.
- **`EdenProcessConfig` passthrough slot.** Donor's `ProcessConfig` has `[key: string]: unknown` for vertical-specific config. Library uses `Map<String, dynamic> extra` as the catch-all; verticals stash domain config there.
- **`EdenProcessValidationIssue.type` is a Dart enum, NOT a String.** Donor uses `"error" | "warning"` discriminated union; library uses `enum EdenProcessValidationSeverity { error, warning }` for type safety. JSON serialization writes the enum `.name` ("error" / "warning") to match donor wire shape.
- **Registry singleton + test isolation.** Both registries expose a `reset()` method. Tests MUST `setUp(() { EdenProcessEntityTypeRegistry.instance.reset(); EdenProcessRuntimeComponentRegistry.instance.resetToDefaults(); });` — note `resetToDefaults()` for runtime-component (re-registers the 6 defaults), `reset()` for entity-type (clears all).
- **`EdenDiagramPortKind` enum:** `{ source, target, both }`. Donor in React Flow uses `type: 'source' | 'target'` per handle (no "both"); library adds `both` because some nodes (Phase) have ports that act bidirectionally.
- **`EdenDiagramPort.offset` is the 0..1 normalized position along the side.** 0.5 = center (most common). Edge cases: 0 = top-left corner anchor, 1 = top-right corner anchor (for `side: top`). The eden_diagram canvas (TRD 02) reads this to compute pixel position via `node.x + node.width * offset` (for top/bottom) or `node.y + node.height * offset` (for left/right).
- **`EdenDiagramPort.data` slot for handle-id.** Donor's React Flow uses `sourceHandle: 'yes' | 'no' | 'top' | ...` as the connection-handle discriminator. Library maps to `port.id` (Dart String) — `port.data['handleId']` is redundant. Document in dartdoc: "Set `id` to the donor's `sourceHandle` / `targetHandle` string for round-trip with saved edges."
- **Don't introduce a Dart `sealed` class for value types.** Plain classes with `const` constructors + immutable fields. The donor uses TypeScript interfaces (open shapes); Dart equivalent is a plain class with explicit fields. Avoid `freezed` / `dataclass` — that's a new dep (Constraint 11 violation).
</gotchas>

    required this.id,
    required this.side,
    this.offset = 0.5,
    required this.kind,
    this.color,
    this.data = const {},
  });
