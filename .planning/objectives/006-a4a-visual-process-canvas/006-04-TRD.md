class EdenProcessNodeRenderer {
  EdenProcessNodeRenderer._();

    // Wave 2 ships these one-by-one; TRD 14 final composer assembles the full set

<gotchas>
- **Start/End nodes are PURELY visual.** They don't accept any callbacks. The library doesn't even fire selection on them (selection is canvas-level state, handled by `EdenDiagram` core).
- **Orphan node delete button is a HOVER-show button.** Mirror donor (`OrphanNode.tsx:90-100`): `opacity: 0 group-hover:opacity-100`. In Flutter use `MouseRegion(onEnter: ..., onExit: ...)` → state-driven `Opacity(opacity: _hovered ? 1.0 : 0.0)`. On touch devices, always show.
- **Donor color tokens (PHASE_COLORS map, NODE_COLORS map) → Eden tokens.** Map donor's blue/green/amber/red to `theme.colorScheme.primary` / `.tertiary` / `.secondary` / `.error`. When a donor color (`#3B82F6` for blue) has no Eden semantic match, keep the hex with the comment `// donor color — keep until token system has equivalent` per OBJECTIVE.md Constraint 8.
- **48×48 size for Start/End is HARDCODED.** Donor `w-12 h-12 rounded-full`. The `EdenDiagramNode.width/height` passed to the renderer via `ctx.node` is 48; the widget just fills the parent box (no SizedBox needed — `Positioned` already constrains).
- **Use `Material(color: Colors.transparent)` wrapper** around interactive nodes so InkWell / hover effects work cleanly. The `customNodeRenderer` runs inside the diagram's Stack — Material ancestor exists (EdenDiagram is mounted in a Material app), but be defensive.
- **Selection ring style:** use `BoxDecoration(border: Border.all(color: theme.colorScheme.primary, width: 2), borderRadius: BorderRadius.circular(...))` for square nodes (Orphan); use a wider colored outline for circular nodes (Start/End) — drawn as a `Container` with `decoration: BoxDecoration(shape: BoxShape.circle, border: Border.all(...))`. Ring offset: 2pt outside the node.
- **Donor `Handle` components from React Flow are NOT needed in Flutter.** The library doesn't render handle dots inside each node — the canvas engine (`EdenDiagramPainter`) draws port dots ONLY when selected/hovered (per existing diagram_painter.dart code) AND when the customNodeRenderer is in use, the port-dot logic from TRD 02 (`_drawNode` in painter) renders them. Verify this works in the widget test by setting `ctx.selected = true` and asserting port dots are visible... actually no, the painter draws ports separately. The Flutter node widget just provides the visual body; handles are owned by the canvas.
- **Orphan node may host a Decision-type orphan.** Donor allows orphanType: `'phase' | 'taskGroup' | 'task' | 'decision'`. Cover all 4 in tests.
- **Task-type orphan with runtime-component icon:** look up via `EdenProcessRuntimeComponentRegistry.instance.lookup(runtimeId)?.icon ?? Icons.check_box`. Tests register a custom component via `EdenProcessRuntimeComponentRegistry.instance.register(...)` in setUp then verify the icon is used.
</gotchas>
