<objective>
Ship `EdenServiceCatalogTile` — the salon backbone widget per `.planning/USE_CASES_SALON_2026-05-17.md` §5 row 3. Each tile shows the canonical 5-element service identity: name + duration + price + capable-staff avatar strip + customizations chip strip. Tap-to-book fires the consumer's `onTap` with the entry instance. Composes existing primitives (`EdenCard`, `EdenAvatar`, `EdenCurrencyDisplay`, `EdenChip`) — no new dependencies.

Generic — the widget knows nothing about salon-specific service types. Consumer maps domain entities (salon services, trades labor tasks, medical procedures, fuel delivery services) to `EdenServiceCatalogEntry`. The widget renders the same tile shape across verticals.

Wave 1 of objective 016 — runs in parallel with 016-04 (EdenIntakeFormBuilder) + 016-05 (EdenClientSmsThread). **This TRD bootstraps `lib/dev_app/screens/salon_screen.dart`** — it's the lowest-numbered TRD in Wave 1 so it creates the file; 016-02 through 016-06 each APPEND a Section() entry.

Outside-in test approach: static rendering (default tile, photo variant, empty staff, empty customizations) → interaction (tap fires onTap; null callback no-throw) → avatar overflow ('+N') → customizationsBuilder slot override → iPhone-narrow safety.
</objective>

<anti_patterns>
- **Do NOT** hard-position avatar overlaps in a `Stack` at all screen sizes. Stack with `Positioned(left: i * 16)` breaks at iPhone-narrow if there are 5 avatars + a chip + the name overlay. Use a `Wrap` with per-avatar `Transform.translate(offset: Offset(-8 * idx, 0))` OR a `Row(mainAxisSize: MainAxisSize.min)` with negative right-margin via `Container(margin: EdgeInsets.only(left: -8))`. The Wrap-fallback at narrow widths is critical.
- **Do NOT** include any salon-specific terminology in the value class. `EdenServiceCatalogEntry` is generic. No `stylistIds`, no `colorFormula` field, no `chairAssignment` — those belong in consumer-side domain types.
- **Do NOT** generate fixture entries via LLM. Hand-build 5 salon services + 3 trades services + 2 medical procedures.
- **Do NOT** wire any persistence or fetch — widget is pure stateless display + onTap.
- **Do NOT** assume `EdenAvatar` exposes a `size:` parameter — verify via `head -50 lib/src/widgets/eden_avatar.dart` first; might be `EdenAvatarSize.small` enum or a `radius:` double.
- **Do NOT** assume the photo is always available — null-handle gracefully with a fallback icon (`Icons.spa_outlined` is the salon-coded default; consumer can override later).
- **Do NOT** bind to a specific service-category color scheme. Category coloring is the consumer's responsibility (they pass `trailing:` widget).
</anti_patterns>

<gotchas>
- **Avatar strip iPhone-narrow flow.** At 390pt width with a 56pt photo + 16pt padding, the body column has ~310pt. Five overlapping avatars = ~5×24pt - 4×8pt = ~88pt + 32pt chip = ~120pt. Fits in one row. With 8 staff (5 avatars + '+3' chip + customizations on the same row), width pressure rises. Use `Wrap` so the customizations row flows to the next row instead of overlapping.
- **Duration formatter pure helper.** Test it independently (no widget mount needed). Cases: 30 → '30m'; 60 → '1h'; 90 → '1h 30m'; 0 → '0m' (edge); 125 → '2h 5m'.
- **Theme-profile scope read.** Use `maybeOf(context)` not `of(context)` so absence doesn't throw. Default to `commercialWarm` literally — that's the project's baseline profile.
- **Photo aspect ratio.** 56×56pt square. If the source image is non-square, `BoxFit.cover` is correct (crops the non-square dimension). Document in a code comment that consumers wanting full-frame should pre-process.
- **Test-pairing rule.** `lib/src/widgets/eden_service_catalog_tile.dart` MUST have paired `test/widgets/eden_service_catalog_tile_test.dart`. Enforced.
- **Hand-built fixtures only.** Fixture file MUST start with `// Do NOT regenerate via LLM — hand-built fixtures for EdenServiceCatalogTile.`

class EdenServiceCatalogTile extends StatelessWidget {
  const EdenServiceCatalogTile({
    super.key,
    required this.entry,
    this.onTap,
    this.customizationsBuilder,
    this.trailing,
    this.maxVisibleAvatars = 5,
  });

  final EdenServiceCatalogEntry entry;
  final ValueChanged<EdenServiceCatalogEntry>? onTap;
  final Widget Function(BuildContext, EdenServiceCatalogEntry)? customizationsBuilder;
  final Widget? trailing;
  final int maxVisibleAvatars;

  @override
  Widget build(BuildContext context) {
    // Theme-profile fallback — explicit read for future palette swaps.
    // ignore: unused_local_variable
    final profile = EdenThemeProfileScope.maybeOf(context) ?? EdenThemeProfile.commercialWarm;
    final theme = Theme.of(context);

    return EdenCard(
      child: InkWell(
        onTap: onTap == null ? null : () => onTap!(entry),
        child: Padding(
          padding: const EdgeInsets.all(EdenSpacing.space3),
          child: Row(
            crossAxisAlignment: CrossAxisAlignment.start,
            children: [
              _Photo(entry: entry),
              const SizedBox(width: EdenSpacing.space3),

            ],

        ),

  }

class _Photo extends StatelessWidget {

class _AvatarStrip extends StatelessWidget {
  const _AvatarStrip({required this.staff, required this.maxVisible});
  final List<EdenServiceStaff> staff;
  final int maxVisible;
  @override
