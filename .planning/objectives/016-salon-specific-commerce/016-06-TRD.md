<objective>
Ship `EdenStaffSchedule` + `EdenStaffCapabilityMatrix` — the weekly staff scheduling template editor + staff × service capability grid per `.planning/USE_CASES_SALON_2026-05-17.md` SALON-044 + SALON-046 (#10 in the Top-10 gap list). Distinct from `EdenScheduler` (obj 004 — day calendar of actual appointments): this is the per-staff WEEKLY TEMPLATE that feeds `EdenTimeSlotPicker`'s availability and the booking widget's staff filter.

Two widgets in one TRD because they're tightly coupled in the salon admin workflow (you edit a stylist's schedule + capabilities in one screen) and each is small enough that the combined TRD fits the 2-3 task budget. They share value classes only minimally (`EdenStaffWeeklyShift` is schedule-only; `EdenStaffCapability` is matrix-only).

Generic — both widgets know nothing about salon-specific scheduling. Consumer maps domain entities (salon stylists, trades technicians, medical providers) to `EdenStaffWeeklyShift` + capability bools. Same widgets render the same shapes across verticals.

Wave 2 of objective 016 — runs in parallel with 016-02 (EdenTimeSlotPicker). Depends on 016-01 (`EdenServiceCatalogEntry` value class for the capability matrix columns). TRD 016-01 owns the file-create on `salon_screen.dart`; this TRD APPENDS its Section() entry.

Outside-in test approach: value class round-trip → schedule grid renders 7 weekday rows + shifts as colored bars + breaks as overlay → tap day row opens editor → matrix renders staff × service grid → tap cell flips capability → callbacks fire → iPhone-narrow safety.

<anti_patterns>
- **Do NOT** compose `EdenScheduler` for the weekly visualization. The scheduler is for actual events; this is a template. Use Stack + Container.
- **Do NOT** make breaks overlap detection a v1 feature. Consumer is responsible for validating break time ranges (start < end, no overlap). Document this contract.
- **Do NOT** auto-generate sample staff/shift fixture data via LLM. Hand-build 5 staff × 7 days = 35 EdenStaffWeeklyShift entries.
- **Do NOT** include drag-to-reschedule UX. Tap-to-edit is the v1 pattern. Drag-to-resize the shift block is a v2 enhancement.
- **Do NOT** persist state internally for the schedule editor. Consumer-controlled via `shifts: List<EdenStaffWeeklyShift>` + `onShiftChanged: ValueChanged<EdenStaffWeeklyShift>`.
- **Do NOT** combine the schedule + matrix into one widget. Keep them as two siblings — different UX, different value classes, different test surfaces.
- **Do NOT** sort the matrix rows or columns internally. Consumer chooses ordering.
- **Do NOT** generate the capability initial state randomly. Consumer passes a `List<EdenStaffCapability>` and the widget renders exactly what was passed.
</anti_patterns>

<error_recovery>
- If `showTimePicker` doesn't exist in the Flutter version (unlikely): fall back to a custom `EdenInput` with hh:mm validation.
- If `DataTable` doesn't fit narrow widths gracefully: wrap in `SingleChildScrollView(scrollDirection: Axis.horizontal, child: DataTable(...))`.
- If the shift-block `width` calculation produces a negative number (e.g., endTime before startTime): clamp to 0 and document; consumer should validate before submit.
- If TimeOfDay rendering in test environments shows locale-dependent formatting: assert via `find.byType(TimeOfDay)` is not possible — instead use `find.text('9:00 AM')` or test the underlying state property.
- If `find.byType(Checkbox)` matches more checkboxes than expected (the matrix has many): scope with `find.descendant(of: find.byType(DataRow), matching: find.byType(Checkbox))`.
</error_recovery>

<gotchas>
- **TimeOfDay equality.** Flutter's `TimeOfDay` has `==` properly implemented, but rendering format (`.format(context)`) depends on locale. Tests should use the underlying `hour` + `minute` fields for assertions, not the formatted string.
- **Stack-based shift block positioning needs constraints.** Wrap the day-row Stack in a `SizedBox(height: 40, width: rowWidth)` so Positioned children render correctly.
- **Break overlay striping.** Use a `CustomPainter` with diagonal lines OR a simpler `Container(decoration: BoxDecoration(image: DecorationImage(...)))` with a tiny PNG. v1 uses just a solid different-color overlay (theme.colorScheme.surfaceContainerHigh with 60% opacity) — striping is v2 polish.
- **Test-pairing rule.** TWO source files, TWO test files. Both required.
- **Hand-built fixtures only.** Header: `// Do NOT regenerate via LLM — hand-built fixtures for EdenStaffSchedule + EdenStaffCapabilityMatrix.`
- **salon_screen.dart APPEND.** TRD 016-01 creates the file. Find the `// TRD 016-06 will append: ...` placeholder.
- **DataTable column-sizing.** Long service names overflow the column header. Use `DataColumn(label: SizedBox(width: 100, child: Text(s.name, maxLines: 2, overflow: TextOverflow.ellipsis)))`.
- **Checkbox tristate.** Pass `tristate: false` to avoid the third "indeterminate" state — only true/false.
- **Capability lookup performance.** For matrix rendering, build a `Map<String, bool>` keyed by `'${staffId}|${serviceId}'` once per build. Don't iterate the capabilities list per cell.
</gotchas>
