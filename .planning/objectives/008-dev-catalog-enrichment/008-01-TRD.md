<objective>
Create the shared sample-data library that every Wave 2-5 TRD draws from. Cross-vertical fixtures for trades / salon / fuel / medical / gov scenarios plus shared cross-cutting types (customers, staff, inventory). This is the foundation — every later TRD imports from here instead of inventing per-screen fixtures.

Purpose: Once-and-only-once, hand-built, vertical-realistic sample data. Avoids per-screen reinvention and makes cross-vertical demos (e.g., EdenActivityFeedItem mixing trades + salon + medical events in one list) cheap to compose.

Output: `lib/dev_app/_sample_data/` directory with 6 .dart files + 1 barrel export, importable as `import '../_sample_data/sample_data.dart';` from any catalog screen.
</objective>

<anti_patterns>
- Do NOT use a JSON / YAML file + runtime loader for fixtures. Use plain Dart `static const` collections. Compile-time + greppable.
- Do NOT generate fixture data via LLM (resolver `no_llm_test_data` constraint + global TDD Playbook habit 4). Hand-build every record. If you don't know a believable salon-vertical service name, look up a real-world salon menu first.
- Do NOT import from `lib/src/widgets/` IF the fixture is purely value-shaped (use only the public types like `EdenInsightContent`, `EdenSchedulerEvent`, `EdenAddress`, `EdenLatLng`, `EdenBlockingAlertData`, `EdenActivityFeedItemData`, etc., which ARE re-exported from `lib/eden_ui.dart`). The constraint is: no `lib/src/widgets/...` direct imports; use `package:eden_ui_flutter/eden_ui.dart` (the public barrel).
- Do NOT centralise fixtures in a single 500-LOC file. One file per vertical + one cross-cutting file. Keeps blast radius small for vertical-specific updates.
- Do NOT inline fixtures into demo screens going forward (that was the prior pattern; this TRD ends it).
</anti_patterns>

<gotchas>
- `EdenInsightContent.data` is `Map<String, dynamic>` — to make it `const` you MUST use `<String, dynamic>{ ... }` map literal explicitly.
- `EdenSchedulerEvent` carries `start`/`end` as `DateTime` which is NOT `const`-able. Use static getters returning fresh `DateTime(...)` instances rather than `static const` — every call site copies the value.
- `EdenAddress` and `EdenLatLng` are const-able. Use `static const`.
- The catalog runs against a fixed "demo today" date for stability. Use `DateTime(2026, 5, 16)` as the anchor — `today` in catalog land. Past/future events compute relative to this anchor.
- Do not forget the `Do NOT regenerate via LLM` header on every file — automated regen could be enabled later in a CI hook; the comment is the contract.
</gotchas>

<error_recovery>
- If `flutter analyze` reports unused imports in cross_cutting.dart (because not all scenario files use every shared type): annotate the export line in `sample_data.dart`, or move single-vertical types out of cross_cutting.dart into the specific vertical file.
- If a fixture references a type that doesn't exist in `lib/eden_ui.dart` exports: that's a sign the demo intent crosses the library boundary. Drop the fixture and note it in `<recovery>` for the demo TRD that needed it; do NOT add a new library export here.
- If realistic sample data feels suspicious or AI-generated (uniform name patterns like "Customer 1 / Customer 2", or all timestamps within the same minute): rewrite by hand with variation. Real-world data has irregular distributions.
</error_recovery>
