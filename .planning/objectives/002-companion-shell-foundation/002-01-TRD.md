<objective>
Ship the foundational hybrid mode-discrimination logic locked at `COMPANION_B2_SPEC_2026-05-15.md` §1.

This TRD ships:
1. `EdenAppMode` enum with three values: `admin`, `fieldCompanion`, `askUser`.
2. Pure-function `resolveAppMode(...)` implementing the locked B2-spec §1 algorithm transliterated to Dart.
3. `EdenAppModeController` — a `ChangeNotifier`-based controller exposing `currentMode` + `setMode()` + an optional `onChange` callback that fires whenever `setMode` mutates state. **Persistence is the consumer's job** — the library does NOT touch SharedPreferences.
4. `EdenAppModeScope` — an `InheritedNotifier<EdenAppModeController>` exposing `EdenAppModeScope.of(context)` (rebuilds dependents on change) and `EdenAppModeScope.modeOf(context)` (returns just the current `EdenAppMode`).

**Why Riverpod-friendly, not Riverpod-dependent.** Per `PROJECT.md` Constraints, `eden-ui-flutter` MUST NOT depend on `flutter_riverpod`. Follow the precedent in `lib/src/widgets/eden_async_form_scaffold.dart` — expose a `ChangeNotifier` + `InheritedNotifier` that Riverpod consumers can adapt with `ChangeNotifierProvider`. Document this in the file's dartdoc.

**Why this is foundational.** TRDs 03 (`EdenUxModeToggle`), 04 (`EdenFieldViewGate`), 05 (`EdenCompanionShell`), and 06 (`EdenGpsStatusIndicator`) all consume `EdenAppModeScope.modeOf(context)` to make their behaviour mode-aware. Wave 2 + Wave 3 cannot proceed without this.
</objective>

<gotchas>
- **`InheritedNotifier` rebuild semantics.** Dependents rebuild ONLY when `notifyListeners()` is called on the controller. A consumer reading `EdenAppModeScope.modeOf(context)` MUST call `context.dependOnInheritedWidgetOfExactType<EdenAppModeScope>()` — wrap the read in a method that uses `dependOnInheritedWidgetOfExactType` so widget tests can verify the rebuild.
- **`ChangeNotifier.dispose()` is the controller owner's responsibility.** The library does NOT auto-dispose. Document in dartdoc.
- **`setMode` should be idempotent.** Calling `setMode(currentMode)` MUST NOT call `notifyListeners()` (avoid spurious rebuilds). Test this.
- **`onChange` callback fires AFTER `notifyListeners()`** — order matters for consumers wiring SharedPreferences persistence; they want listeners (UI) to update before the I/O begins. Test the order.
- **Material 3 breakpoints are pt, not pixel.** `resolveAppMode` accepts a `Size viewport` (from `MediaQuery.of(context).size` or `LayoutBuilder.constraints.biggest`); both are already in logical pt. Document.
- **`EdenResponsive` already exists** at `lib/src/utils/responsive.dart` with `mobileMax=768` and `tabletMax=1024` — different numbers from this TRD's Material 3 600/840 breakpoints. Do NOT change `EdenResponsive`; this TRD introduces a separate `EdenAppMode.kCompactMax = 600` and `EdenAppMode.kExpandedMin = 840` constants. Document the intentional split in dartdoc.
</gotchas>

```dart
import 'package:flutter/foundation.dart';
import 'package:flutter/widgets.dart';

/// Locked at Companion UX research 2026-05-15 (decisions A + E).
///
/// Three Material 3 responsive tiers + companion-mode pinning:
/// - Compact (<600pt) → fieldCompanion by default
/// - Medium (600–840pt) → askUser (ambiguous)
/// - Expanded (≥840pt) → admin by default
///
/// Library remains transport-agnostic: this file does NOT import
/// shared_preferences, flutter_riverpod, or any JWT decoder. The
/// persistence + claim-decode + dart-define ARE THE CONSUMER'S JOB;
/// they pass already-resolved values into [resolveAppMode].
enum EdenAppMode { admin, fieldCompanion, askUser }

/// Material 3 Compact tier upper bound (exclusive). Below this width,
/// the user is on a phone-class device and field-companion is the
/// default.
const double kEdenAppModeCompactMax = 600.0;

/// Material 3 Expanded tier lower bound (inclusive). At or above this
/// width, the user is on a tablet-landscape-or-larger and admin is the
/// default.
const double kEdenAppModeExpandedMin = 840.0;

/// Pure resolver function — input → output, no I/O, no state.
///
/// Resolution order (highest precedence first):
/// 1. [dartDefineBuildMode] — App Store pinned build (e.g.,
///    `flutter build --dart-define=APP_BUILD=field-companion`).
/// 2. [claimAppMode] — JWT `app_mode` claim from FedRAMP-restricted
///    backend (Wave C; mechanism in place for v1).
/// 3. [persistedAppMode] — the user's previous toggle / first-launch
///    picker choice (e.g., a SharedPreferences string the consumer
///    read at app boot). Invalid strings fall through silently.
/// 4. Viewport-driven default — Material 3 tier rules from lock E.
EdenAppMode resolveAppMode({
  required Size viewport,
  String? persistedAppMode,
  EdenAppMode? claimAppMode,
  EdenAppMode? dartDefineBuildMode,
}) {
  // 1. dart-define hard pin
  if (dartDefineBuildMode != null) return dartDefineBuildMode;

  // 2. JWT claim hard pin
  if (claimAppMode != null) return claimAppMode;

  // 3. Persisted user choice (silently ignore garbage)
  if (persistedAppMode != null) {
    for (final mode in EdenAppMode.values) {
      if (mode.name == persistedAppMode) return mode;
    }
  }

  // 4. Viewport-driven default (Material 3 tiers per lock E)
  if (viewport.width < kEdenAppModeCompactMax) return EdenAppMode.fieldCompanion;
  if (viewport.width >= kEdenAppModeExpandedMin) return EdenAppMode.admin;

  // 5. Ambiguous Medium tier
  return EdenAppMode.askUser;
}

/// ChangeNotifier wrapping the current resolved [EdenAppMode].
///
/// The consumer constructs one of these once per app and passes it to
/// [EdenAppModeScope]. Persistence is the consumer's job — wire the
/// [onChange] callback to SharedPreferences (or any other I/O) and
/// read back the persisted value on next app boot to pass into
/// [resolveAppMode] via [persistedAppMode].
///
/// Mirrors a Riverpod `StateNotifier<EdenAppMode>` shape without
/// depending on `flutter_riverpod`. Callers using Riverpod can wrap
/// with `ChangeNotifierProvider`.
class EdenAppModeController extends ChangeNotifier {
  EdenAppModeController({
    required EdenAppMode initialMode,
    this.onChange,
  }) : _currentMode = initialMode;

  EdenAppMode _currentMode;

  /// Optional callback fired AFTER listeners are notified. Wire this
  /// to your persistence layer (e.g., SharedPreferences setString).
  /// Order: notifyListeners() runs first so the UI updates before any
  /// I/O begins.
  final ValueChanged<EdenAppMode>? onChange;

  EdenAppMode get currentMode => _currentMode;

  /// Idempotent: calling with the current mode is a no-op (no
  /// notifyListeners, no onChange).
  void setMode(EdenAppMode newMode) {
    if (newMode == _currentMode) return;
    _currentMode = newMode;
    notifyListeners();
    onChange?.call(newMode);
  }
}

/// InheritedNotifier scope. Dependents rebuild when the controller
/// fires [ChangeNotifier.notifyListeners].
class EdenAppModeScope extends InheritedNotifier<EdenAppModeController> {
  const EdenAppModeScope({
    super.key,
    required EdenAppModeController controller,
    required super.child,
  }) : super(notifier: controller);

  /// Throws if no scope is in the tree. Use for required dependencies
  /// (e.g., inside EdenCompanionShell, EdenUxModeToggle).
  static EdenAppModeController of(BuildContext context) {
    final scope = context.dependOnInheritedWidgetOfExactType<EdenAppModeScope>();
    assert(scope != null, 'EdenAppModeScope.of() called with no scope in the tree.');
    return scope!.notifier!;
  }

  /// Returns null if no scope is in the tree. Use for optional
  /// dependencies (e.g., a widget that adapts when in a scope but
  /// renders a sensible default outside).
  static EdenAppModeController? maybeOf(BuildContext context) {
    return context.dependOnInheritedWidgetOfExactType<EdenAppModeScope>()?.notifier;
  }

  /// Convenience accessor for just the current enum value. Equivalent
  /// to `EdenAppModeScope.of(context).currentMode`.
  static EdenAppMode modeOf(BuildContext context) => of(context).currentMode;
}
```
